## `shared_decisions.py`

- 在 Pro V3 的按天整服模型（`docs/development/economy-2000-v3-pro-source/`）上加钩子，只读导入，不改原文件；V3 自带的逐日货币恒等断言照常生效。
- 加入的东西：
  - 每日玩法的铜：工坊订单、街坊委托、残余案、事件。每个活跃日的数额取自人类计时模拟（一般速度、全都做），工坊底料按实付订单比例付给 NPC 生产者。
  - 本地单机财富带入：开服批里一半玩家带存档，余额对数正态，中位 2000、最多 12000。
  - 地下委托：一次性 560 铜。
  - 反例：无源发币。
  - NPC 物价与资金的整体标尺。
- **每日玩法的铜从哪来**：比较照单机发币（铸币），和“城市预算”支付两种方式。城市预算按税率从 NPC 基础篮子销售额与开放服务销售额收钱，钱是转移，不是新发行。付完当天的玩家后，预算超出期初储备的部分当天按来源比例退回，所以税率只是每天收钱的上限。
- **S1 复核**：D3 选定的篮子覆盖和 V3 默认值不同时，按 D1 同一规则在那个覆盖下再选一次，只报告，不改 D1。
- **验收线和判定规则**写在脚本里（`LINES`、`RULES`），跑之前定好，报告开头原样列出，判定由代码按规则算出。

## `fee_sweep.py`

- 在 2000 账户玩家市场模型（`tools/economy-agent-sim`）上，套用修正后的购物规则和成熟工匠不亏本规则，用两倍塔材，只改交易费（0/2/5/8/12%）。每档 3 个种子 × 365 天。
- 判定规则：取工匠市场净收入下降不超过 10%、免费玩家药品履约下降不超过 2 个百分点的最高一档。每个账户都有专业，所以“工匠市场净收入”是全体玩家在市场上的净现金，为负数；下降幅度按它的绝对值算。另列卖家到手收入。

## `import_market.py`

- 同一个市场模型、同样的修正规则，交易费 5%。开服批一半玩家带单机存档（对数正态，中位 2,000、最多 12,000，按上限截断），带入上限取 0/500/1,000/2,000/4,000/12,000。
- 判定规则：取市场篮子指数全年峰值比不带入高不超过 10%、免费玩家药品履约下降不超过 2 个百分点的最大上限。
- V3 整服模型没有玩家之间的市场，带入的铜推不动价格，所以用这个模型补测。
