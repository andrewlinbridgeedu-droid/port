# 共享服经济候选的模拟判定（2026-09-29）

用户 2026-09-29 定：共享服经济的几项候选用模拟计算来定。这里是两个脚本，都只用 Python 标准库，结果和判定写进 `docs/development/shared-economy-decisions-20260929/`。**是设计模型，不是游戏实装，也不能证明真实服务器不会通胀。**

```sh
python3 tools/economy-decisions/shared_decisions.py --out <输出目录> --workers 4

```

## `shared_decisions.py`

- 在 Pro V3 的按天整服模型（`docs/development/economy-2000-v3-pro-source/`）上加钩子，只读导入，不改原文件；V3 自带的逐日货币恒等断言照常生效。
- 加入的东西：
  - 每日玩法的铜：工坊订单、街坊委托、残余案、事件。每个活跃日的数额取自人类计时模拟（一般速度、全都做），工坊底料按实付订单比例付给 NPC 生产者。
  - 本地单机财富带入：开服批里一半玩家带存档，余额对数正态，中位 2000、最多 12000。
  - 地下委托：一次性 560 铜。
  - 反例：无源发币。
  - NPC 物价与资金的整体标尺。
- **每日玩法的铜从哪来**：比较照单机发币（铸币），和“城市预算”支付两种方式。城市预算按税率从 NPC 基础篮子销售额与开放服务销售额收钱，钱是转移，不是新发行。
- **验收线和判定规则**写在脚本里（`LINES`、`RULES`），跑之前定好，报告开头原样列出，判定由代码按规则算出。

## `fee_sweep.py`

- 在 2000 账户玩家市场模型（`tools/economy-agent-sim`）上，套用修正后的购物规则和成熟工匠不亏本规则，用两倍塔材，只改交易费（0/2/5/8/12%）。每档 3 个种子 × 365 天。
- 判定规则：取工匠市场净收入下降不超过 10%、免费玩家药品履约下降不超过 2 个百分点的最高一档。
