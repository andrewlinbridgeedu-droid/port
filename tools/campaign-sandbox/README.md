# 雾港世界事件演练

**定位：隔离内容试玩与机制演练工具，不是正式游戏接入。** 默认“事件试玩”页串起新闻、立场、真实塔战、候选皮革制作、有限交货、安装、公共行动与简化合同结果。“机制对照（开发）”保留原四种战斗比较。完整故事见[事件案](../../mistport-ios/docs/game-design/chapter-one-30/WORLD_EVENT_LIGHTS_CASE_20260927.md)。不实现分层人物决战、永久死亡或正式经营。

macOS 14+ 独立窗口，复用 `MistportCombatCore`，不读取或写入正式存档。事件试玩仅保留内存状态，可导出钱物及战斗回执；不包含 Unity 演出、多人服务器或共享经济。

从项目根运行：

```sh
tools/campaign-sandbox/build_and_run.sh
```

脚本生成并打开 `output/workshop-playtest-20260927/MistportWorkshopPlaytest.app`。编译缓存隔离在 `/tmp/mistport-campaign-app-build`；旧演练包和外置盘链接保留。设置 `MISTPORT_CAMPAIGN_OPEN_APP=0` 可只构建。

## 事件试玩 v0.3.3

先读公报、选择立场，进入F1击败盾颚魔，结算并领取1份候选韧皮。支付13铜制作3条绑带，向有余额的项目出售2条取得18铜，再安装到12号滤筒。任选普通/困难公共行动，完成后查看新闻和账单。余下1条绑带不会自动卖出；药品按实际服用扣除。

初始48铜、30层装备、序列资格、此前11套工程、其他账号公共成绩都是明确的测试夹具。塔战使用真实目录与战斗规则，候选材料不触发正式首通奖励。单次公共尝试失败也会使用资格；允许先在开发页演练。键盘1–4为技能、5普攻、M用药；切换页会暂停。导出只记录已结算场次，不支持恢复存档。

详细验收见[本轮记录](../../docs/development/workshop-playtest-20260927/README.md)。界面可玩不等于已通过真人趣味、真实市场需求或iPhone视觉验收。

## 机制对照页

1. 选护卫阵或回流阵、普通或高难，选30/100层累计装备、普通封印物、0/3瓶药和是否带勋章。
2. 开始后点击敌人切换目标，手动使用四技能、普攻、药品和勋章。
3. 可以暂停或重新开始；配置修改仅影响新一场。导出记录会暂停，并保存到应用旁的`Records/`文件夹，采用唯一文件名；继续须点击“继续演练”。
4. 每场180秒，核心死亡立即胜利，主角死亡或超时失败。没有真实奖励；1/2点只是普通/高难公共贡献的候选预览。

两个值得比较的打法：先清除全部附属敌人；或击破一个后抢打核心。回流阵可以在治疗读条时切目标打断。不要把程序胜率当作真人难度；请记录误读机制、切目标困难、等冷却无事可做等实际体验。

## 固定候选规则 v2.1

|参数|普通|高难|
|---|---:|---:|
|核心生命|2200|4200|
|护卫/支援生命|500|1100|
|核心基础攻击|35|65|
|附属基础攻击|18|36|

实际伤害仍经过共享内核的技能、装备、天赋和封印物规则。初始技能与天赋来自Q30可得预算；装备由塔掉落表累加，技能仍为1级，未伪造稀有装备或临时攻击加成。

- 护卫阵：2/1/0名护卫存活时，核心减伤60%/25%/0%。每24秒开始4秒蓄力；期间击杀护卫，或护卫全灭后造成核心最大生命8%的有效伤害，可打断。成功打断后恢复3秒；失败后每秒一次、共6次的持续伤害，单次为正常生命上限3%向上取整，六次总预算不超过快照生命18%向下取整，最后一跳扣剩余预算，爆发时快照，核心恢复6秒。护卫继续攻击。
- 护卫核心首次半血时恰好有1名护卫，4秒后新援军抵达；到达前清空护卫则取消。2名或0名时不呼援。援军是新实例，不复活旧敌人。
- 回流阵：每20秒，活着的支援者同时读条5秒，各自承受其最大生命15%的有效伤害便中断。每个完成者治疗核心最大生命6%，记录实际治疗与溢出。读条支援者暂停普攻，核心继续攻击。
- 回流核心首次半血取消所有治疗读条，核心恢复8秒；恢复结束20秒后下一轮回流。若此时已有支援死亡，4秒后增援一名，仅一次；存活支援继续普攻。
- 普攻前摇0.8秒；核心接触后间隔3.8秒再起手，附属4.2秒。暂停机制会取消未命中的普通攻击，结束后至少0.8秒再起手。被技能延迟的敌人继续使用原内核延迟逻辑。
- 玩家技能使用现有命中时长及实时冷却；公共动作间隔1.75秒，普攻1.65秒且自身间隔2.4秒。药品仅手动/测试策略主动使用，不预扣；药品按钮间隔1秒为此原型候选约束，不修改正式游戏。
- 固定50毫秒逻辑步长，同刻到期的机制和敌人命中先于玩家命中；180秒时先判超时。核心已死亡后停止后续攻击与机制。

## 复跑

```sh
swift test --package-path mistport-ios/MistportCombatCore \
  --scratch-path /tmp/mistport-campaign-build -j 1 \
  --filter 'CampaignBattleSandboxTests|CampaignSandboxPilotTests' > /tmp/mistport-campaign-tests.log 2>&1
python3 tools/campaign-sandbox/report_trials.py /tmp/mistport-campaign-tests.log \
  docs/development/world-campaign-prototype-20260927/playable-sandbox
```

机制单元测试可以直接注入伤害构造边界，绝不作为难度样本。288场策略试跑只操作实际技能、药品和封印物；每个带药/不带药配对使用事先生成的同一时间阻塞带。

`MPCCampaignScenario`不加入正式目录；只有显式传入匹配`campaignPrototype`才能创建战斗。UI与程序策略均使用`MPCCampaignBattleDriver`。这是本地研究工具，所有状态/API都不构成共享服权威结算。

## 原生界面复核

用户明确授权后，可用 `swiftc tools/campaign-sandbox/native_play.swift -o /tmp/mistport-native-play` 编译辅助工具。它只枚举唯一运行中的 `local.mistport.workshop-playtest`，支持 `dump`、`press-text <可见按钮前缀>` 和 `press <刚读取的索引>`；不接触正式存档、不调用战斗内部方法。菜单项需要在同一操作中展开并选择。窗口截图应先聚焦并执行该窗口的 `AXRaise`；Stage Manager 缩略图不算布局验收证据。

当前界面实走证据及接入判断见 [UI_QA.md](../../docs/development/workshop-playtest-20260927/UI_QA.md)。程序288场矩阵与原生界面试玩分开记录。
