# 工资与产业结算原型

这是独立的 Python 可执行原型，不是 Swift/Unity 功能，也不是服务器身份验证或并发数据库。Pro V3 原件不改动。

## 玩家到底做什么

第一版只定义可由战斗承载的委托：工坊准备开工，但作业区被怪物占据；玩家接受清场委托，进入指定战场，胜利后用服务端认可的战斗完成事件验收。NPC 随后负责运输、制造和验收。客户端说“完成了”、等待时间结束、重复上传同一结果都不是工资来源。

游戏内接线仍待实现：公告／工坊委托卡显示地点、敌人、报酬和完成条件；接受时占用已锁定预算；加载绑定订单的战场；战斗规则层产生结果；回到城市显示到账及工坊状态。不能把当前本地 Swift 战斗结果直接当作未来共享服务器的可信证据。

真正的护送需要货车移动、受击与保护目标等新机制，调查需要线索和可判断的证据分支。这两者均未实装，不在第一版承诺中。单纯搬货点交付不作为主要玩家工作。

24铜工日是NPC劳动与成本标尺，不是玩家在线八小时，也不是自动日薪。原型120铜战斗报酬只是成本分配夹具，尚未按战斗耗时、难度、失败消耗定价，不可直接抄进游戏配置。

## 可执行内容

- 整数铜账本；显式发行回执；普通转账守恒，外贸收款人也在总账中。
- 雇主预存工资，指定玩家和目标的完成事件结算；取消退回雇主；同一事件／工资重复不支付。
- 工业燃料进口全额预付、有限外部库存、两日到货、重复到货无效。
- 10辆自行车成本夹具1560：材料／工具／场地780，NPC劳动660，玩家清场委托120。总额沿用旧候选，内部拆分为新假设，不冒充旧物料清单或工程核价。
- 客户先锁1600订单款，借款400、股本1160；交货后还本息440，企业余额1160。没有保证出售工装残值，所以企业利润0、银行利息40，玩家工资120均有付款人。
- 若未完成清场，订单退款、未发工资回收、投入材料损失；贷款从项目剩余现金回收，股东或银行可亏损。
- 银行支付存款100%独立覆盖；贷款后留200现金底线和72运营费；真实项目回款还贷，全体提款可支付。
- 180／365日，5种子，正常／持续新人加供应冲击和失败／无人接工作三种情景。休眠旧钱包不删除，新增玩家用新发行记录。

运行：

```sh
python3 -m unittest discover -s tools/economy-prototype -v
python3 tools/economy-prototype/run.py --out docs/development/economy-contract-prototype-results
```

## 实验边界

`WorkEvent.authority` 仅模拟可信规则层，字符串不是鉴权；内存状态机不是数据库事务或并发保证。测试模拟行动结果，不是已让真人玩过。

燃料供给、任务承接率、企业价格、开户资金和服务消费函数均为假设。脚本没有完整基础篮子生产链、玩家股份市场、多服对账、真实战斗投入、身份反多开或主线连续可达性。无人接工作时工厂停工是明确的失败场景，正式版需有限成本的NPC承接和世界技术独立发展机制。

长期输出可能包含失败、缺货和服务涨价；不能将账平称为无通胀，也不能将原型脚本称为游戏经济已上线。

## 本轮实跑结果

30组运行（3场景×2时长×5种子），共8,175个逐日状态，资金差额全部0。6项单元测试通过。

365日正常夹具出现49日燃料需求未满足：本模型客户收入链不完整，预算可耗尽；不能将其报告成纯物理缺货。联合冲击场景服务价格指数最高3.3304，企业累计亏损1,500–5,600铜；有燃料不等于所有市场稳定。无人接工作时玩家工资为0，未自动凭空补工资。结果文件保留全部失败。

正常夹具还暴露采购决策缺陷：固定采购产能会积累库存并占用现金；下一步要依据在途、库存、真实客户订单和交货期限下采购单，而非固定每天买满。不要用无来源的客户收入补丁掩盖这些失败。该版本完成的是合同结算和失败路径原型，不是稳定经济定案。
