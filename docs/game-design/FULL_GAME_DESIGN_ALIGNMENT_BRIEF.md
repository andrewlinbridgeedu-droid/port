# 给 ChatGPT 的需求：统一游戏设计与体验闭环

请为《秘仪：雾港升序》整理一份能指导实际制作的统一游戏设计方案。请结合我提供的天赋、教会、百层塔、成长对齐稿和第1—8关剧情稿，不要重新另造一款游戏，也不要把候选数值当作已验证事实。

## 一、产品目标与已有背景

- 手机竖屏、欧式幻想雾港、身份与记忆谜案。美术偏精致插画与幻想游戏质感。已有城市、人物和战斗素材，应优先复用。界面不能像网页表单，也不能用大面积厚框遮挡背景；文字要清晰，按钮有实体质感和按压反馈。
- 当前只重点设计隐者职业，暂不考虑PVP。玩法核心是看懂敌人、编排技能、配天赋与遗落物。理解机制的免费玩家应有机会胜过花钱更多但构筑不合理的玩家。
- 玩家战前调整技能顺序，战中技能和普攻按规则调度，以实际命中结算。不能假设已有战中手动选目标、自由闪避或手动打断系统。
- 主线包含多个地区，地区内有具体关卡，地图逐步开放。不要把旧教会Q01、Q02等编号等同于主线第1、2关，也不要把旧城区前20关等同于整个序列9。缺少的完整关卡表应列为需要开发方提供的输入，不能猜测补齐为“现有事实”。
- 天赋方向：隐者诡术、幻身、秘兆三系，各6节点，每节点最多5级，每系容量30点。序列9三系共用30点预算，不是各送30点。应支持30点专精、20+10、15+15等构筑。高序列如何继承和开放新选择仍需要统一规则，不能默认所有乘区无限累积。
- 教会：守灯、观镜、缄卷三条路线，接调查任务、挑战怪物、获得有边界的成长。已有18个调查节点候选配置，以及三座各100层长阶候选配置。层数未来可追加，属性上限、同类触发上限和奖励总产出不能无限复制。300层配置不等于已经完成平衡验证。
- 城市分工：角色页管理卡牌顺序与天赋；行囊管理物品；商店有系统随机商品和玩家寄卖；咖啡馆卖消耗品并偶尔提供隐秘交易会消息；秘术工坊修复遗落物、改造技能以形成不同打法；晋阶厅负责演证、仪式和重要身份选择。

## 二、已经核对到的实现事实与冲突

以下是开发方当前代码与最近确认的方向，不代表它们全部是最终设计：

1. 当前胜利回调缺少统一的战后结算流程：有少数技能奖励页、特定关卡后对白，但通常完成后直接返回地图。敌人退场、威胁收尾、获胜提示、奖励汇总、玩家确认继续，没有统一串起来。
2. 当前普通关卡结算会增加铜币、记录首通与区域进度，部分节点发晋阶材料。可见代码的普通基础首通铜币为1—5关30、6—10关40、11—15关50、16—19关65、第20关120，精英加15；重演约首通35%，最低8。以上只是当前实现，需审查经济合理性，不能声称已平衡。
3. 当前检查的主线结算路径没有统一的经验增量、等级条和升级结果展示。新剧情稿说“经验沿用现有表”，但没有给出可核对的经验表。因此不能直接在UI编造“经验+100”。需要明确经验是否存在、来源、用途、等级表与上限，再形成真实账本。
4. 当前普通槽位：第3关扩至2格，第10关扩至4格。已核对技能节点：第1关错步穿行，第3关假面谕令，第8关身份错置，第9关伪证，第10关错影追猎，第11关荒诞终幕，第12关逆转舞台，第13关无名剧场。不同文档的技能名称如有出入，先整理别名与唯一ID，不重复创建技能。
5. 第一件遗落物“纸人代身”安排在第5关。最新来历建议是“未寄出的信”为本体、纸人为发动形态，第2关铺垫玛拉取件，第5关邮差交付。此来历稿属于待整合建议，不能说所有对白已实装。
6. 新稿建议纸人在其他防御之后拦截一次致命伤害、保留1生命、每场一次、无后续无敌；与早期脚本教学、首轮拦截和强制反击存在冲突。必须列出废弃规则和迁移办法，不能同时生效。假面主动幻影与纸人被动遗落物必须区分。
7. 用户已要求第3—6关围绕同一只猎犬形成连续故事，不能突然当狗王或反复死而复生。目前第6关已改为单猎犬收尾。最新第1—8关稿又提出第6关加入记忆蛭双目标，这是与最新方向的冲突；本轮默认保留单猎犬方案，记忆蛭留待后续适合的关卡。若建议重新加入，必须作为需确认的变更说明必要性、前置伏笔和成本，不能偷偷视为已批准。
8. 当前部分旧结算文案仍有“战力提升60”、第5关猎犬崩解等表达，需要核对是否符合有限成长和阶段击退规则。代码存在不等于设计正确。

## 三、首先补齐战斗到结算的完整体验

请明确设计以下状态链，并给出每步触发条件、允许输入、镜头与音效、停留时间建议、可跳过范围和持久化时机：

进入关卡 → 前置对白与教学 → 战前编排 → 玩家确认开战 → 战斗 → 最后威胁收尾 → 敌人死亡/击退/解除控制 → 确认胜负 → 获胜或目标达成提示 → 奖励结算 → 必要的升级/新物品/解锁展示 → 后续剧情 → 玩家点击继续或回地图 → 整备。

不能再敌人一归零就自动切出。可讨论的初稿节奏是：最后命中后先让退场动作完成，获胜标题约1秒，再显示可停留的奖励页，由玩家确认离开。时间只是初稿，不得用固定延迟代替真实战斗完成条件。

请回答：

- 死亡、击退、驱散、救援、解除追猎等不同目标如何命名，哪些产生击杀事件？第3—5关不能写成猎犬永久死亡。
- 停止新攻击后，已发射弹道、已确认多段、持续伤害和死亡遗留如何处理？哪些取消、哪些结算？同归于尽、最后一击触发纸人怎么判？不得胜利后还扣血或重复发奖。
- 奖励页要显示本次真实所得：经验（若正式采用）、铜币、材料、遗落物、技能、剧情物证、声望与解锁。区分首通、重演、本场所得、战前已领取。第5关战前交付的纸人不能战后再发一次。
- 经验条如何从旧值到新值，连续升级如何展示？等级封顶后的经验如何处理？演证、声望、角色经验、天赋点不可混用。
- 获胜、奖励、授卡、剧情应怎样编排才不会连续弹五六层窗口？不掉落新物品的普通关也要有简洁但完整的反馈。
- 自动保存与继续按钮如何分工？杀进程、重复点击、断线、重进、重复胜利回调如何保证不丢奖、不重发？
- 失败显示什么原因，是否有部分奖励或消耗退还？如何一键调整构筑重试？退出、重试、换波、整备分别如何处理生命、技能CD、遗落物次数和消耗品？
- 请画出竖屏结算页的信息布局，覆盖胜利、阶段击退、首通解锁、普通重演、失败五种状态。不要只写“增加一个胜利弹窗”。

## 四、需要统一梳理的设计缺口

请逐项标注【已有依据】【当前实现】【建议采用】【冲突/待确认】【待测试】，不要把所有系统都描述成从零缺失。

1. **完整玩家旅程**：首次启动、城市、接任务、地图探索、关卡、胜败、整备、返回城市的入口出口；什么时候看见功能、什么时候能用；首次教学与日后重演分开。
2. **主线与剧情因果**：按真实地区/关号给敌人、场景、人物出场、线索来源、工具发放、战斗目标、后续去向；已有素材复用与新怪物制作清单。不得遇到机制问题就提前发后续技能。
3. **统一成长轴**：角色等级、序列、演证、声望、天赋点、技能槽、教会调查和塔章节如何对应。剧情硬解锁与推荐强度分开；高层不能依赖无限涨属性。
4. **战斗规则合同**：开场顺序、冷却调度、普攻填空、目标选择、弹道命中、状态层数、刷新/叠加、控制、同时事件顺序、伤害优先级、触发次数上限。技能说明、敌方说明、战报使用同一套定义。
5. **构筑与敌人验证**：每系优势、弱点和混合搭配成本；敌人可观察信号与反制工具；允许多个解法，避免某一付费物品成为唯一解。提供同预算对照、战斗时长、存活、资源消耗、失败原因，候选构筑不能冒充模拟结果。
6. **物品全生命周期**：来源、首次展示、获得、装备槽、使用、修复/恢复、改造、出售/寄卖、剧情提交和收藏记录。唯一本体、投影、物证、材料不能混淆；战中次数不能靠开关菜单重置。
7. **城市各板块闭环**：每个场所为什么去、做什么选择、消耗什么、得到什么、如何回到主线/构筑。避免商店、咖啡馆、教会、工坊都只是换皮材料店。
8. **教会与塔**：调查负责叙事和工具，塔负责构筑挑战；开放、推荐、进度、失败重试、重演、章节追加、首通奖励、有限校准、封顶体验。不要把300层都塞入早期教学。
9. **经济与免费玩家体验**：各货币来源/消耗/上限，首通与可重复收益，系统商店随机刷新与保底、寄卖货源和价格规则、手续费及防刷；无PVP不代表寄卖经济可以无限产出。明确当前版本做什么、后端未具备时哪些不得假装上线。
10. **UI/反馈规范**：层级、可读性、按钮状态、按压、奖励稀有度、掉落音效、动作收尾、获得新物品、升级、解锁、红点和信息提示频率；保留已有美术方向，不重做已满意的图标。
11. **存档与异常**：战斗结果及奖励唯一标识、首次获得、重复挑战、断线续战、迁移旧存档、测试奖励隔离。尤其不要把开发预览的免费30点或全关开放写成正常玩家流程。
12. **长期更新边界**：新序列、新技能改造、新塔章节和新敌人如何追加；旧天赋效果继承、等级压缩或阶段适用范围需有明确方案和代价。不要默认无上限叠加。

## 五、交付格式与制作顺序

请交付一份统一主文档及以下可直接制作的表，不要仅写宏观愿景：

1. 已确认事实、跨文档冲突、建议决策、缺失输入四张清单。
2. 玩家流程图，重点细化战斗结束—结算—奖励—剧情—整备。
3. 系统解锁与成长总表，行必须能映射真实地区和任务ID；未知项标待提供。
4. 逐关表：前置、敌人、教学工具、胜败目标、对白节点、首通/重演奖励、解锁、后续去向、资产需求、验收项。先完整对齐1—8关；后续按真实关卡表扩展，不编造现有内容。
5. 奖励与经验数值表及经济累计：来源、数量、发放时机、重复规则、用途、累计产出、封顶处理。建议数值明确标记，缺基准时先给公式与所需输入。
6. 结算UI及动效说明，含按钮、停留、跳过、不同胜负目标、升级和新物品变体。
7. 隐者构筑—敌人机制—技能—遗落物对应表，以及最低验证矩阵。
8. 最小可玩版本、后续版本的制作优先级和依赖。优先完成真实主线及结算闭环，再扩大塔和更多职业，不要求一次重写全项目。
9. 验收用例：零新掉落也有结算；阶段击退不计击杀；最后弹道未完成不抢跑；首通/重演/中途退出不重发；战前纸人不再发；失败不强制购买；免费合法构筑可完成对应教学；奖励到账与屏幕数字一致。

最后，请先给出你认为必须由我确认的少量关键分歧，再给推荐方案。不要因为每个细节都不确定而停住，也不要擅自决定与最新确认方向冲突的剧情、付费优势或关卡改动。
