# 雾港开发团队

这是本项目可复用的角色约定；工作时由主 agent 按需启动子 agent，不代表常驻后台服务。

| 角色 | 交付责任 |
|---|---|
| 制作负责人（主 agent） | 定义批次完成条件、分配文件、集成修改、运行游戏并完成最终验证 |
| 关卡导演 | 故事目的、敌人身份、模型与法术要求、前后剧情和关卡配置一致；常规内容直接落实 |
| 战斗与3D工程师 | 战斗规则与真实接触、模型、动画、特效、退场一致；较大任务可拆成互不冲突的子任务 |
| 验收与规则审计官 | 独立复现，检查规则、正常构筑、奖励和保存，提供证据与剩余缺口 |

每次派工只说明目标、必要依据、文件归属和完成条件。按需阅读技能与文档；不要求所有修改先填模板。不更改已确认方向的常规实现自主处理。

模型成本偏好（用户确认）：明确的小任务优先使用 Luna，包括文案、资产清单、日志整理及简单修复。Astra 用于跨 Swift/Unity 排错、复杂规则判断与最终集成。已有高成本任务收尾后不追加简单工作；避免重复读取和重复启动。委派 Luna 时只传必要上下文。

关卡导演负责模型和法术的叙事含义，工程师负责制作接入，主 agent 对整关结果负责。新模型需求明确用途、尺寸、动作及挂点；现有临时模型如实标记。

用户新增要求：每关敌人必须呈现可辨认变化，综合外观状态、阵容、动作、法术和战斗问题；不能仅换名称或血量。同一猎犬第3—6关保留身份连续性，但追猎状态和表现应逐关变化。第9关抄录傀儡复用守卫只是临时资产，不能按正式美术验收。

## 首批：第7—10关接手

- 第8关：记忆蛭显示、动画、投射、退场与无运行异常。
- 第7关：主动选核心、选中标识、伤害对象一致。
- 第10关：真实选敌、技能序列、contact、胜负与保存；不得用降血或强制胜利掩盖实现问题。
- 第8/9关：选择界面严格遵守真实两格；第10关胜利后四格。
- 剧情命名、前置对白与现有模型说明一致。
- 第9关正式天赋独立记录缺口，候选数值不得冒充已批准规则。

验收记录保留于 `docs/development/`；未实测不得标记完成。
