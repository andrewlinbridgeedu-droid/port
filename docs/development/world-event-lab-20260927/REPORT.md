# 世界事件推演室：本轮验证结果

2026-09-27，模型 `lights-lab-1.0`。对应[首测定案](../../../mistport-ios/docs/game-design/chapter-one-30/WORLD_EVENT_FIRST_TEST_DECISION_20260927.md)。这是计算假设下的设计验证，不是真人胜率、用户需求调查或可交易服务器验收。

## 完成的交付

- 可交互本地应用，默认展示结论和建议，不要求用户调参。三类细看页面、预设情景、可折叠高级参数、完整JSON导出。
- 216组事件情景，每组1000次固定种子公共行动抽样，再对核心阶段做条件概率动态规划；推荐/边界预设各2000次。
- 448组项目资金情景，覆盖价格、客户需求、客户有限钱包、原料限制与开机检查开/关。
- 2916项货币观察＝324组参数组合×3种Q30规则×3个观察时长，不称2916个独立真实市场。
- 20项模型测试通过，包括48个旧精确有理数概率对照、分层不同概率的完整二进制序列枚举、同轮双死、资金与实物资格、停工/钱包耗尽/守恒、周期领取和输入边界。

复算命令与方法见[工具说明](../../../tools/world-event-lab/README.md)。[原始结果](results.json)、[精简汇总](summary.json)、[测试输出](tests.log)、[运行输出](audit.log)保存于本目录；原始JSON附Python源码SHA-256。新增模型和工具未修改正式游戏结算。

## 1. 事件结局：保留人数优势，消除“无人死就没有结果”

推荐情景：400人，A联合会280/B灰帆120；普通成功率假设85%，双方12套工程完成；核心节点和人物战各50%，最终机会到场率85%。多数公共分领先，6/4机会；胜负按新的合同表映射。

|情景|联合会取得合同|灰帆取得合同|临时接管|
|---|---:|---:|---:|
|70:30，相近实力|96.7375%|3.1561%|0.1064%|
|少数派高难80%、节点75%、人物战70%，其余同推荐|84.5845%|14.9126%|0.5029%|
|多数派只有8套工程，少数派齐备|0%|100%|0%|
|无人参加公共行动|0%|0%|100%|

基准人物双方存活约75.9%，但不等于75.9%无经营结果。新合同映射是本轮最明确的结构改善。少数派在改进准备后由约3.2%提高到14.9%，仍不是强制50:50。

旧65%普通成功率情景下，同样的少数派改进能把公共贡献反超，取得合同约80.8%；把普通目标调为85%后，少数派通常需要靠最终突破翻盘。**不能跨假设挑一个好看的胜率当结论。** 首页采用推荐85%对照。85%仍是普通体验目标，战斗内核没有实现随机85%胜利。

各1000次公共抽样的合同概率估计，单项95% Hoeffding界为约±4.29个百分点；2000次约±3.04个百分点。条件核心DP无抽样误差，但真人行为、关联成功率与候选选择偏差不在这个误差界内。小数位仅便于复算，不代表真实精度。

模型把阵营人数作为输入，尚未模拟投资人逐利换边、宣传动员和自发形成70:30的过程。新闻、不同产业需求与免费参与是否让落后阵营仍愿意参加，必须通过体验验证，不能靠暗补少数派属性。

## 2. 生意：有客户才能收入，开机保护不等于保本

推荐60铜/套；成本34铜、主动6分钟是候选口径，卖家经济收益26铜即4.33铜/分钟。旧40铜只有6铜即1铜/分钟。首测60是测试起点，不是证明玩家会买，也不是所有职业的利润已通过。

单方12套建设720铜，项目投资1200铜；取得合同时还需要120铜调试。服务单价4铜，每营业日1套维护组具60＋外部燃料60，每日上限50单。客户钱包共6000铜、原料上限50单/日。

|每日付费需求输入|新开机检查|实际30日订单|获胜后的总投资盈亏|
|---:|---|---:|---:|
|0|不启动|0|-720铜|
|25|不启动|0|-720铜|
|30|不启动：经营净额无法覆盖调试|0|-720铜|
|35|可启动|1050|-240铜|
|40|可启动|1200|+360铜|
|50|可启动|1500|+1560铜|

这里前7日的需求须解释为已付费、原料已落实的订单。不能把问卷意向当同等保障。等待客户的时间不延长合同，已施工720铜也不会因不开机自动返还。

在旧40铜参数下，无客户且不加检查会亏600；加检查则不付120调试，亏480。推荐60铜本身提高了工程成本，因此不能把新亏720与旧亏600直接比较，声称检查更差或更好；必须保持商品参数相同做对照。448组包含这种配对。

满负荷+1560是高需求输入情景，不是保证月收益；财富来自客户已有6000铜转移。模型没有假造系统购买或股东利息。公司期末现金包含剩余本金及留存经营净额，不能全标成本金；已分配经营现金不能再退一次。

## 3. 货币：限频不能单独完成共享经济平衡

基准固定注册2000，日活概率55%，月卡30%，免费6铜/活跃日，月卡额外12铜/活跃日，Q30参与100%、选择后每日1次，每次105；其它重复8铜/活跃日。工艺参与60%、日产1件、成交率70%、价70、外部材料14/件、手续费5%、其它销毁2.3/活跃日；真新人0。

这些是公开的模拟输入，不是已经批准的月卡额度和真实成交量。回收与发行相减是系统净投放，不是通胀率。下表单位为万铜/365日。

|上线人群假设|Q30规则|Q30发行|经常性净投放|
|---|---|---:|---:|
|每天同一批活跃账号|每次105|4215.75|4433.76|
|每天同一批活跃账号|7日一次|612.15|830.16|
|每天同一批活跃账号|14日一次|311.85|529.86|
|每日独立活跃|每次105|4215.75|4433.76|
|每日独立活跃|7日一次|1099.47|1317.48|
|每日独立活跃|14日一次|557.54|775.56|

周期从第1日开始，最后不完整窗口仍可领一次。独立活跃下，每个账号7日至少领取一次概率为 `1-(1-dau*qParticipation)^7`；固定活跃群用那批账号的领取概率计算。不能用相同DAU推定相同7日独立领取人数。

基准全年回收约488.63万；免费/月卡补给约385.44万，其它重复现金321.20万。即使关闭Q30，这两类合计仍高于该回收模型。说明不能只围着7/14日反复微调。

此外，每日5个真新账号按5220铜权益、1080真净流出计算，一年新增净额755.55万；转服账号不得重发唯一权益。若三材款留在可再花费NPC钱包中，它是转移，净额更高。此模型只列该权益流，不假装已处理迁服携带余额和离服留存资产。

结论：本轮可以推进有预算事件和工艺闭环，不能把自由共享铜币、银行信用一起打开。下一步用“已核对真销毁＋有限启动储备”约束未来发行票据，先保障已承诺权益；这仍需实现和行为验证。本轮不擅改现行任务奖励。

## 4. 测试与边界

- 旧等成功率DP与现有有理数模型对照；新节点/人物战不同概率与完整二进制路径枚举对照。
- 同轮双死保留；前三节点未成则无法进入人物决战；缺席不生成胜利。
- 工程同时要求钱和物；没有客户/原料/预算不产生虚构履约。
- 每一天项目余额、卖家收入、外部流出、客户余额及累计经营分配守恒；本金亏损真实保留。
- 两种上线人群、最后不完整窗口、0日活、0参战、新人权益及NPC钱款归类覆盖。
- 本地HTTP输入有类型/范围/体积检查，拒绝跨源POST；只绑定127.0.0.1，未开放公网。

未覆盖：真实市场价格形成、财富集中、免费/月卡个体负担、账号关联、网络并发与事务持久化、实际玩家需求、真实战斗节奏、NPC托管履约。首测补救规则写进规划，但尚不是正式服自动执行的控制器。
