# 共享服角色成长设计（提案）· 2026-09-30

状态：**提案，等用户定**。现在服务器上的角色只是运维工具设的一个“塔层号”，配装直接取塔层验证模型的推荐配装（`LedgerCatalog.loadout(floor:)`）。这只够技术小样用。本页说明 M2 小服开测前，服务器要怎样保存和推进一个真正的角色。

## 1. 原则

1. **服务器保存角色，客户端只报操作。**服务器用自己存的角色复算战斗（`MPCChurchBattleDriver`），所以角色的全部战斗属性都要在服务器上，并且只能由服务器确认过的事件改变。
2. **和单机同一套规则库。**成长数值（天赋点、技能升级、教会装备、遗落物）全部复用 `MistportCombatCore`，不在服务端另写一份。
3. **按天放开，和单机一样。**已经做好：服务器按 `MPCDailyPacing` 判断塔层首通，每天 4 层，跳过的天照算；开打前判断，打赢一定发奖。服务器的一天从 `Asia/Shanghai` 零点开始（候选）。
4. **不能花钱或靠交易买到战力。**底栏商店是真钱内购，只卖章节扩展，不碰战力。共享服里能交易的只有材料和消耗品，装备和遗落物绑定角色。

## 2. 服务器存什么

| 部分 | 单机来源（规则库） | 服务器怎么得到 |
|---|---|---|
| 主线进度 | 第一章 30 关首通 | 见第 3 节，有三个选项 |
| 塔层 | `MPCChurchTowerProgress` | **已有**：服务器复算赢了才加 |
| 教会装备 | `MPCChurchGearLedger`，塔层掉落 | 塔层首通时服务器按 `MPCChurchGearCatalog.towerDrop` 发放，绑定角色 |
| 通缉遗落物 | `MPCBountyRelicLedger` | 通缉战由服务器复算，结案时发放，绑定角色 |
| 商店遗落物（被动） | 按关开放，用铜买 | 用共享铜买；开放条件看服务器上的主线进度 |
| 天赋 | `HermitTalentAllocation`，点数来自主线首通 | 点数按服务器上的主线进度算；玩家分配，服务器校验不超 |
| 技能等级 | `MPCSkillGrowth`，技能尘来自主线首通 | 同上，服务器校验花掉的尘不超过拿到的 |
| 晋阶、主材 | Q17／20／23 开放购买，第 30 关仪式 | 用共享铜或市场上买的材料；开放条件看主线进度 |
| 配装 | 4 张卡、终极技、被动、主动遗落物、外观 | 玩家在已拥有的范围内选，服务器存下，开票时冻结进票据 |

**外观**：三套外观都带战斗加成（闪避、攻击、减伤），单机里随便换。共享服照样可以随便换，但换装必须先告诉服务器；复算用票据里冻结的那一套，否则客户端和服务器的闪避结果会不一致。

**开票时冻结配装**：票据里记下当时的完整配装。复算用这份，不用结算时的角色，这样中途换装、升级都不影响已经开打的那场。现在的票据只记了 `character_floor`，要改成记完整配装。

## 3. 主线进度从哪来（要用户定）

主线 Q1–Q30 的战斗每关都有专门的出手节奏，还不在规则库的推进器里，服务器暂时复算不了。

| 选项 | 做法 | 好处 | 风险 |
|---|---|---|---|
| **A. 先信客户端，按天放开兜底**（建议 M2 用） | 客户端报“打赢第 N 关”，服务器只检查今天第 N 关开放没有、前一关打过没有 | 马上能做；按天放开限制了作弊能快多少 | 改过的客户端可以跳过打仗直接过关，但快不过日历 |
| B. 主线战斗也搬进推进器 | 像教会战斗一样，把 30 关的节奏搬进规则库，由服务器复算 | 和教会战斗一样可靠 | 工作量大，30 关各有节奏；M3 再做 |
| C. 共享服不打主线 | 共享服角色从“第一章已通关”起步，只在共享服打教会系内容 | 最简单 | 新玩家没有第一章的引导和剧情 |

建议：M2 用 A，M3 做 B。选 A 时，天赋点、技能尘这些随主线发放的东西，也跟着“信客户端＋按天放开”。

## 4. 单机存档能不能带进来（要用户定）

已定：单机的铜最多计 12,000，按 15% 折成共享铜。角色进度还没定：

| 选项 | 做法 |
|---|---|
| **甲. 不带进度**（建议） | 共享服角色从头打，按天放开。单机玩家只多带一笔铜 |
| 乙. 只带主线进度 | 已通关的主线直接算数，塔层、装备、遗落物从头打。开始日按单机迁移的办法往前推 |
| 丙. 全带 | 塔层、装备、遗落物也带。服务器验证不了，等于信客户端 |

理由：共享服的公平靠“同一天开始的人进度一样”。带进度会让单机老玩家在共享服一开服就领先，而且进度是客户端报的，服务器没法验证。

## 5. 实现顺序

1. **票据冻结完整配装**：替换 `character_floor`，复算读票据里的配装。
2. **角色表**：主线进度、天赋分配、技能等级、拥有的被动、主动遗落物、装备、遗落物、外观、当前配装。服务器按规则库校验配装合法。
3. **掉落和结案发放**：塔层首通发装备，通缉结案发遗落物，都绑定角色。
4. **主线进度接口**：按第 3 节选定的办法。
5. **运维工具**：`setCharacter` 只留给测试，正式服关掉。
6. **重打掉材料要有额度（漏洞，M2 前必补）**：现在服务端每赢一次塔层都掉材料，重打已通关的楼层也掉，没有上限。单机里重打的材料走每天的工作票据，按单递减（`MPCDailyWorkLedger`）。共享服要照单机的额度来，否则可以无限刷材料去市场卖。

## 6. 已做（2026-09-30）

服务端按天放开：
- 每个角色有“开始日”（`pacing_start`）；新号从建号当天算。运维设角色时，照单机迁移旧档的办法把开始日往前推，推到下一层今天能打为止。
- 开塔层票据时，首通受每天额度限制，超出的在开打前拒绝（`dailyLimit`，409），不会预留任何东西；已通关的楼层重打不受限。
- `/v0/me` 返回 `pacingDay` 和 `towerFirstClearsAllowed`。
- 旧库自动升级（schema 2）：老角色从建号当天算。
- 服务端测试 20 项全过，新增 4 项。
