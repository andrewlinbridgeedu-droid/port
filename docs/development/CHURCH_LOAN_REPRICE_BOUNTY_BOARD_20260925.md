# 教会借物重订价与通缉板游戏化（2026-09-25）

## 用户决定

- 强力封印物须达到相应累计功勋档才可借，不因签约消费功勋。
- 新合同签约时用铜币支付一笔较大押金和一笔较小租金。租金即使提前归还也不退；正常磨损后完好归还只退押金，明确损毁或遗失则押金全额不退。
- 同一页的通缉告示不能继续是浅色网页卡片。采用既有 `ChurchBountyBoard` 木质告示板原画、旧金标题与羊皮卷宗结构，保留已有目标立绘、接案流程和铜币／功勋游戏奖励图。

## 实施

- `ChurchLoans.swift`：当前八件按估值 `ceil(2P/3)` 后向上取整到10铜币为押金、`ceil(P/10)` 为三场不退租金；具体资格与价格以 `RELICS_AND_LOANS.md` 为准。签约时两笔原子扣除，合同内快照价格；三场普通磨损仍更新耐久但不罚没押金。`markLost` 只供将来明确损毁／遗失事件调用，不把当前通缉阵亡或撤退误作遗失。归还收据按 loanID 幂等。
- 旧档合同 `terms == nil` 时仍按签约当时的25%押金、功勋预付、普通磨损扣费、未用功勋退款履约；新的价格表不会追溯旧借物。已有权属与交易禁止保持。
- `GameStore.swift` 保存路径仍通过 `updateChurchServices` 同一待恢复收据合并钱包、借物与装配变动；无单独可能漏写的铜币操作。
- 借物页用两列旧金铜币图明确区分“押金／完好退”和“租金／不退”，显示签约总额与当前累计功勋门槛；已借物显示实际退押金额。旧合同页面明确标注旧条款。
- 圣所入口原图副标题仍是旧规则的“以功勋立约”，因此用内置图像编辑模式按原深紫金边横牌另存 `ButtonArtChurchLoanEntryRental`，直接把副标题写入图片为“功勋定资格 · 铜币付租押”，同时修改按钮无障碍说明；旧图片未覆盖。新图有透明上下边，显示时仅在原按钮 1050:226 框内居中裁去透明边，不拉伸字形。生成图源保存在 Codex generated_images（原文件仍保留）。
- `ChurchBountyBoard`：现有整页告示板原画作场景背景，原浅蓝白界面和桃色警示框移除；用内置图像生成模式新绘无字旧纸纹理 `BountyNoticeParchment` 作卷宗纸面。新帖继续动态生成，目标图、罪行、招式、危险度、报酬与状态仍为可点开的原生卷宗卡。未修改每日刷新、接案、战斗与结案规则。
- 规划中的三教会独立声望仍是后续方向，未在本批迁移；没有把共用旧余额复制三份。

- Swift Testing 全套394项（另有原有跳过项）通过，含八件定价、功勋门槛、缺钱不扣账、未出战／提前还／三场磨损、损毁罚没、旧档合同退款和重复归还检查。
- `audit_plan.py` 静态价格表与退款规则审计通过；这不是通关现金流、真机视觉或未来三会迁移验收。
- 未换入口图前，本批原生 Build 94 编译且签名验证通过。换图后 Build 95 的首次增量构建遇到同时进行的扑克牌页工作尚未落盘，报 `BountyPokerRound` 缺失；该页面和工程引用随后出现，重试的设备版 Build 95 编译通过。
