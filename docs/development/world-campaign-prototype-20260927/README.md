## 本轮做到了什么

规则位于 `mistport-ios/MistportCombatCore/Sources/MistportCombatCore/WorldCampaignPrototype.swift`。现有Swift Package会编译它，当前没有GameStore调用方。

- 准备期可免费加入阵营，投资自动绑定本次阵营；进入行动期后不再投资或换阵营。投资从个人钱包转入项目，财政种子资金从财政钱包转入，不新增铜币。
- 有预算、有剩余目标才收购物料，重复交付不重复转钱，参数冲突不当作重试成功；系统绑定药不能充当可交易物料。
- 本方物料与外围胜利均齐备后，工程物料用于开辟通道并真实扣库存，敌方核心人物才暴露。**这里是候选工程物料，不是把药品交入仓库就假称已经服用；正式配方还未接入。**
- 挑战票据绑定账号、阵营、遭遇、版本与截止时间；返回的战斗对象持有不可改票据。原型使用现有战斗Session运行。尚未提供网络战斗复验，客户端不能直接把对象提交给未来共享服务器。
- 两名玩家拿到同一核心的合法票据后，第一次胜利改变世界；另一次只保留个人胜利记录，不再次死亡、消耗建设料或发世界新闻。已签发票据保留公开宽限，结算等待宽限结束。
- 双方人物都死亡时没有独占合同赢家，两边保留继任标志；本事件内人物不复活。单边人物死亡时按候选规则确定合同归属。跨战役永久人物账尚未接入，不能重新创建同一原型就声称已经保证全世界永久死亡。没有伪造实际营业收入。
- 结算按投资与财政出资比例退还未使用现金，整数尾差归财政；未用物料保留在项目，不复制给投资人。成功、失败、无赢家都不凭空发利息。
- 新闻从已提交状态生成，包含固定ID、世界版本、时间与事实。重复战果不重复发布死亡；现有代码覆盖开户/投资/采购/暴露/死亡/继任/结算事实，**没有实现全部24篇文章、定时摘要或通知UI**。

上述是单个可信宿主顺序执行的规则。结构体自身不提供多机事务、账号认证或分布式锁；共享服仍需原子保存整个世界账与对应资产账。原型不读写真实Preferences。完整示例状态见 [example-flow.json](example-flow.json)，由通过的结算测试导出，含采购/挑战/死亡/结算事实；这是夹具数据。

## 结算验证

6项新结算测试覆盖：失败原子性、重复投资/采购与冲突参数、绑定药不可交付、并发票据按顺序结算仅一次死亡、两方死亡、截止/宽限、编码恢复、未完成及过期战斗拒绝、同比例退款和现金/物资守恒。联合普通遗落物及通缉回归，加上战斗对照，共20项测试通过。

结算测试为了检验状态迁移使用直接伤害生成胜利夹具；这些夹具**不计入下面288次战斗对照**，不作为难度证明。原型时间为整数测试刻度，采购2份/外围1胜等测试门槛不是正式平衡数值。

## 288次现有战斗规则对照

组合为B03、B06、塔F90 × 塔30/100层装备 × 无普通封印物/回礼扣/封存纸镇/盐封呼吸袋 × 带0/3份止痛膏 × 不用/使用篡命勋章 × 3个时序种子。角色使用Q30技能和天赋，策略自动选择目标与技能，接触时序扰动±0.25秒；携药时低于正常最大生命一半尝试用药。

结果 **288/288获胜，没有超时**。均实际调用现有伤害、治疗、敌人机制与磨损规则，没有为这批对照直接加伤害或减敌方生命。结果是确定性程序策略对照，不是288真人样本，也不是新阵营NPC难度验收。

|发现|含义|
|不使用勋章、不带普通封印物、不带药仍过三种遭遇|成熟角色在此策略下已有免费通关路线；不能将现有遭遇换名就称高难世界核心战|
|携药策略会在低血量时消耗药，但同配置不带药仍胜|这是可选保险和自动策略消耗，不是已证明的必要市场需求；不能把其用药率直接外推给所有玩家|
|使用勋章、换装备、带回礼扣等会改变时长/剩余生命/用药|准备有可测作用，但尚未建立“缺少准备会失败”的压力；普通封印物并非无条件增强|
|一次胜利后的普通品修复示例：回礼扣2铜、纸镇4铜、呼吸袋2铜|回收规模小；这里每场后修满含取整，不能冒充真实玩家的最优维修频率|

原始每次结果见 [combat-probe.json](combat-probe.json)，全部组合表见 [COMBAT_RESULTS.md](COMBAT_RESULTS.md)，命令日志见 [prototype-tests.log](prototype-tests.log)。最初固定勋章的144次仅是同一批对照的前置子集，保留在 `baseline-144-tests.log`，不能再与288相加计算独立样本。

## 由证据得到的设计修正

1. 高难核心暂不能直接选现有B03/B06/F90。下一版需要独立的世界战役遭遇身份；旧通缉人物不能因为原型复用战斗机制，就被写成阵营NPC或改变正史生死。
2. 不按经济缺口抬高全部维修费。先验证核心战的可读机制与配装取舍，再观察玩家愿意承担的药品、维护和准备成本；经济不能预支尚未存在的消费。
3. 核心战仍留至少两条候选路线：普通装备配合正确技能/操作；适配封印物提供更大容错或较短战斗。若只有最贵稀有品能过，拒绝作为正式唯一入口。外围不要求投资或购买高级封印物。
4. 程序策略全胜不证明真人都觉得简单。需接入隔离试玩入口后测真实时长、错误操作、药耗与撤退；当前没有安装新构建或真机录像。
5. 产业经营、动态市场报价、熟练度、新配方、全部新闻UI及高级封印物成本仍未连接。原型项目余款退还不是投资盈利；既有27组经济结果中的持续货币净增问题仍存在。
