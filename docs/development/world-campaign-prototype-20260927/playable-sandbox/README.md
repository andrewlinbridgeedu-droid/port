# 新战役机制与独立试玩窗口

本轮把设计变成可操作的macOS演练，复用正式Swift战斗内核。两场新机制各有普通/高难数值，共四种遭遇。没有使用旧B03/B06/F90冒充新Boss，也没有把战斗胜利直接交给世界结算。

源码与使用说明：[campaign-sandbox](../../../../tools/campaign-sandbox/README.md)。可运行应用位于项目`output/campaign-battle-sandbox-20260927/MistportCampaignSandbox.app`。这不是iPhone版本，不包含Unity战场和法术演出，不写真实存档。

## 已实现

- 护卫数量减伤、4秒蓄力、按有效伤害/护卫死亡打断、有限6次持续伤害、半血援军与取消条件。
- 支援者5秒回流读条、各自伤害阈值打断、实际治疗/溢出分别记录、半血恢复与新援军。
- 固定50毫秒驱动器，同时用于手动窗口和程序策略。敌人攻击前摇、目标切换、技能接触/冷却、主动勋章、真实药品使用、暂停、180秒超时和JSON记录导出。
- 显式opt-in遭遇目录，无首通与现金奖励；原主线/塔/通缉仍走旧规则。原型勋章资格单独允许显式opt-in，不放宽正式关卡资格。
- 核心死亡后立即停战；同次敌人攻击中的反射伤害若杀死核心，余下伤害不能继续伤害主角。

## 验证层次

最终战斗源码已通过90项测试（其中14项新机制/驱动器边界测试，另1项生成288场新遭遇样本），日志见[tests.log](tests.log)。新样本中普通目标144/144通过，高难护卫66/72、高难回流72/72；144个药品配对有6个从失败转为胜利，73个结束生命更高。高难仍未由真人验收。

高难护卫清场36/36，抢攻30/36；36对中抢攻没有一次既更快又成功。高难回流两路各36/36，抢攻36/36更快。护卫阵两条路线的收益差尚未达标，不能称玩法已定案。

机制测试使用直接伤害构造阈值、时钟及终局边界；这些不进入难度统计。策略试跑只用实际技能/物品，结果见[TRIALS.md](TRIALS.md)与[trials.json](trials.json)。这是程序样本，不是真人成功率或市场购买率。

手动UI已观察到普通护卫阵24.2秒击杀护卫，产生蓄力打断；34.4秒主动用药扣1瓶并恢复332生命；不打断下一次蓄力会产生有限的持续伤害，暂停后倒计时停止。该次手动观察用于操作/机制检查，没有宣称完整真人难度验收。

手动检查发现并修复：原勋章资格只识别正式主线/教会编号，原型按钮曾无效。因此修复前的第一轮试跑已经作废，最终报告必须断言每场勋章实际激活后才能生成。还增加六跳持续伤害的总预算，整数取整后仍不得超过爆发时正常生命快照的18%。另修正签名macOS应用的SwiftPM资源查找，资源放入Contents/Resources；原有包和iOS继续使用原查找路径。

## 尚未完成

1. 高难不能仅凭程序胜负定案。真实操作时长、切目标负担、技能判断和失败原因需要真人试玩；0/25%/50%操作阻塞带只是预设条件。
2. 两条路线是否都有吸引力要分别判断。不能因两条都能通关就说选择成立；应比较时间、损耗、失误容忍及操作要求。
3. 配药消费不等于愿意购买，封印物提高容错不等于高价合理。未在本原型中接入金币、维修、材料市场或项目现金流，不据此提高经济模型的刚性消费参数。
4. 普通1/高难2仍只是本窗口预览。公共战线账、6/4核心机会、四名独立账号突破、正式新闻、关键NPC身份和产业承接尚未与这个新战斗窗口串联。旧世界结算规则原型继续作为独立证据，不冒充新链路完成。
5. 正式Unity表现、iPhone构建和真机验收未在此轮进行。独立窗口的图标、条形血量和按钮只是功能实验界面。
