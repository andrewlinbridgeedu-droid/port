# 《雾港》2,000人服务器经济模型 v3 —— 运行说明

日期：2026-09-26
性质：设计/压力测试模型，不是游戏实装，也不是平衡通过证明。
货币显示：100铜 = 1金；程序内部始终只用铜。

## 文件
- `mistport_server_economy_sim_v3.py`：完整标准库Python脚本。
- `daily_all_scenarios.csv`：10个情景 × 5个固定种子 × 365天 = 18,250行逐日结果。
- `summary_all_scenarios.csv`：每个情景/种子的365天摘要。
- `daily_<scenario>_seed1.csv`：各情景固定种子1的逐日明细。
- `analytic_checks.json`：直接代数校验。
- `bank_capacity.csv`, `bank_cases.csv`：银行上限及三期示例。

## 时间口径
- 经济日：服务器24小时会计结算边界，仅用于总量生产、库存、进口、市场和异步世界状态。
- 个人故事时间：不等于经济日。主线/塔/通缉不要求等现实日。
- 合同经营期：正式游戏仍应由有效任务/验收事件推进。脚本中的“活跃日领奖”只是现金发行节奏代理，不是关卡开放规则。

## 当前事实输入
- 一次性条件权益：初始180 + 主线2280 + 塔1700 + 十通缉1060 = 5220铜/角色。
- 本地J0现状：可重复40铜。本模型不把本地J0直接上传共享权威经济。
- 100铜=1金只用于显示，不改变任何核算。

## 关键修正
1. 2,000表示“当前归属服务器的居民账户上限”，不是终身账号数。
2. 满服每天替换20人；离开者的钱要么转出、要么进入休眠档案；转服流入带入已有钱，不算铸币。
3. 每天20个全新玩家形成的年度一次性权益上限：`20 × 365 × 5220 = 38,106,000铜`。
4. 共享J0不是固定12次保底；采用“低于进度敏感恢复线才可获得40铜”的财政转账。恢复基金耗尽后不再铸币，主线软锁需用不可交易免费重试援助另保。
5. 140,000“非燃料基础品篮子库存”不含家庭燃料。家庭燃料另有70,000kg库存；工业/安全燃料180,000kg再次独立，三者不重叠。
6. 进口下单即从稳价现金全额预付，次日到货。非燃料进口成本10铜/份、保护销售价8铜；家庭燃料进口4铜/kg、保护销售2铜/kg。收入回笼发生在实际售出时。
7. 240辆自行车/20台泵不是每30日凭空重置“新客户”。模型有目标存量、耐用寿命、实际在用存量、有限客户钱包和内部运营收入；订单由存量缺口+折旧产生。
8. 20铜并不天然等于10%股权：1560全股本项目占1.282051%；2880项目占0.694444%。
9. 1500股本银行在“3期72运营费、始终留200运营现金、不依赖提前回款”下：开办40另付最大贷款1228；开办40也从1500资本出最大贷款1188。示例实际只贷1150。

## 固定随机种子
`[1, 2, 3, 4, 5]`

## 运行
```bash
python mistport_server_economy_sim_v3.py
```

## 本次实际运行检查
- 10情景 × 5种子 × 365日 = 18,250个逐日状态。
- 每日资金恒等校验 `money_identity_error == 0`：全部通过。
- 所有玩家现金、稳价现金、恢复基金、物资库存不得为负：运行断言通过。
- 逐日CSV保留未满足需求；不会因为固定标价而删除缺货。

## 不能从本模型得出的结论
- 不能证明真实玩家会以本脚本的消费/活跃/转服/投资行为行动。
- 不能证明12铜/24铜已成为正式货币锚。
- 不能证明Swift/Unity、数据库、并发、服务器宕机、跨服迁移已实现。
- 不能证明多开、机器人、关联账户识别有效；这里只有规则边界和压力输入。
- 不能证明100%准备金的实际数据库提款在高并发下已通过；银行部分是会计/现金代数夹具。
- 不能证明所有项目工程成本真实；1560/2880仍是候选成本。
- 保护篮子模型使用“家庭保护渠道数量上限”。若允许富豪自由买空同一保护库存再转售，12铜稳定承诺会失效，需要另跑完全自由批发市场模型。
