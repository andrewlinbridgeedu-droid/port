# 每日玩法第二阶段：世界事件、无名残余、街坊委托 · 2026-09-29

对应[每日玩法与经济设计](../../../mistport-ios/docs/game-design/chapter-one-30/DAILY_LOOP_AND_ECONOMY_20260929.md)第 10 节的阶段 2。只做规则库、第一批文案和模拟器，**App 还没有接入这些规则**（阶段 3 在 Mac 上做）。云端 Linux、Swift 6.0.3，规则库 514 个测试全过（新增 24 个）。模拟结果在 `raw/`，都是机器人结果；走动和对话的分钟数是假设，没有真机计时。

## 做了什么

| 内容 | 位置 | 规则 |
|---|---|---|
| 四场世界事件 | `CityEvents.swift` | 第 4–10 天伤患潮、11–17 泵站修复、18–24 港口封锁、25–28 蒸汽工坊奠基。交货价低于工坊订单价，只收事件还缺的数量；事件战每天最多记 2 场胜利（每场 10 铜）；交货和胜场都够了当天算成功，城市变化持续到章末；到最后一天没做完算失败，代价只持续一周，不锁任何内容。成功与失败的效果见设计稿 4.3 的表 |
| 城市变化接入工坊 | `Crafting.swift` | `MPCWorkshopOrderBoard.open/sell` 多一个 `bonus`（每日订单预算加减），`MPCCraftingLedger.craft` 多一个 `surcharge`（底料加价或降价），都有默认值，旧调用不变。止痛膏涨价只给出数字（`effects(day:).salveSurcharge`），商店价格要在 App 里接 |
| 无名残余清剿 | `RemnantCases.swift` | 通缉结案后每天一案，在已结的案里轮换；十个地区各两条调查线索（三选一，答错划掉不扣钱）；答对后打一场。打赢领 30 铜（走当天的重复工作递减）和 2 份该地区的塔材料，不给功勋、不给遗落物。塔层段取地区上限和玩家已打通整十层中较低的一个。接下的案一周内可做完，没接的天数不攒 |
| 街坊委托 | `NeighborErrands.swift` | 名单就是港城地图的 23 名街坊。第 2 天起每天 2 条，逢 3 的倍数的天 3 条，当天作废。四种：送工坊货（Q5 前不出）、找东西、传话、赶塔怪。好感 3、6 解锁小故事。**第一批写好 8 人**（邮差、东岸提灯人、面包师、钟表匠、码头工人、花商、街头乐师、教会跑腿），每人 3 条委托、2 段小故事；其余 15 人暂用通用委托，没有小故事 |
| 街头战斗 | `StreetEncounters.swift` | 三类战斗都用塔恶魔的现成身体，战斗 ID 以 `church_maintenance_` 开头、敌人 ID 带 `~maintenance-`，所以 App 和 Unity 走现有塔战的演出和音乐路径。测试逐一核对能在正式战斗核心里开打、`supportsUnity` 为真。没有新模型、新演出，也没在 Unity 里看过 |
| 工坊开放（阶段 1 遗留） | `Mistport/GameStore.swift` | 阶段 1 把规则和提示文字改成 Q5，但 App 的城市服务开关还是 `old-clock-16`，工坊按钮实际要到 Q16 才亮。本轮改成和规则库同一个判断（完成第 5 关或之后任意一关）。**没编译过**，要在 Mac 上验证 |

## 模拟（按天推进，第一天开 Q1–Q3，每天 4 层塔）

模拟器改动：“全都做”和“先清支线”每天结束前做完当天的街坊委托，打当周事件战（每天最多记 2 场，最多试 3 次），工坊先为事件和委托备货、交货再做订单；有已结的通缉案时接当天的无名残余。世界事件没人做就失败，失败的代价对所有打法生效。走动与对话的假设：每条委托 2 分钟（传话再加 1 分钟），残余案调查 4 分钟，交一次事件货 0.5 分钟。

- **时长**：新内容让机器人每天多花 11–12 分钟（街坊 5、残余 4、事件 1、工坊为事件和委托备货多 2–3），没有一天超过 2 小时。机器人打一场街头战只要半分钟到一分钟，真人会慢很多，这里**不能**说明已经填满每天 1–2 小时，要等真机计时（阶段 4）。
- **铜**：本轮多出约 2,500 铜（事件 555、残余 690、街坊约 910、事件成功让订单多付约 330），扣掉多做货的底料约 540，章末余额比阶段 1 多约 1,400–1,550。每天约多 90 铜，玩得多的人多赚一点，但都只是铜。高、中熟练已经不需要做邮务。第二章凡是能用铜买战力的东西都要按天或按剧情开放（设计稿 4.7），不然这些铜会变成领先。
- **残余的铜没有被递减**：每天一案、30 铜，都落在当天前三单里。要让它和邮务互相挤占，得等 J1/J2 也接进模拟器。
- **漏掉的委托**都是前几天的送货：教会（塔）在模拟里要到 Q7、第 5 天才开，前几天手上没有塔材料，委托当天作废，不罚。东岸提灯人因此少做一条，第二段故事要在第 28 天以后；模拟在拿下 Q30 的第 28 天就停，这一天的每日内容没算。
- **街头战偏轻**：按设计比同段塔层轻，所有机器人都没输过。要不要加难度，等真机手感再定。
- **只补必需支线的玩家**不碰这些内容，四场事件都失败，吃到一周止痛膏涨价等代价，仍在第 28 天通关，墙前那天的时长和阶段 1 一样。
- **六堵墙探针、关卡图与阶段 1 完全一致**（`raw/walls.txt`、`raw/gate-map.json` 逐字节相同）。

## 发现的问题

- **模拟器的教会开放时间和游戏不一致**：模拟器沿用 2026-09-25 审计的假设，教会（塔和通缉）在 Q7 后才开；App 里教会一直开着（`cityServiceIsUnlocked(.church)` 恒为真），规则库的 `MPCChurchTowerCatalog.isUnlocked` 也恒为真。塔首通额度按天累积，所以打完的天数不受影响，但第 1–4 天的塔进度、早期材料和第 5 天的时长（模拟里最重的一天之一）都偏了。要不要把模拟器改成第 1 天就开教会，请用户定；改了以后前几轮报告里的单日最长会变。
- **工坊开放**：见上表最后一行，阶段 1 漏改了 App 的开关，本轮已改，未编译。

## 还没做 / 没验证

- **App 没有接入任何新规则**：事件板、交货与事件战入口、地图上街坊的委托对话、残余案卷、日刊、止痛膏涨价、订单预算加减都是阶段 3。App 从 `cee125a` 起没编译过；本轮 App 只改了工坊开放判断。
- 第一批 8 人的委托对白和 16 段小故事、20 条残余线索、四场事件的文案都是初稿，用户还没看过。其余 15 名街坊只有通用委托。
- 街头战没在 Unity 里看过，只核对了走现有塔战路径。
- 事件、残余、委托给的铜都是单机新发行的铜，共享服要按经济研究另算。
