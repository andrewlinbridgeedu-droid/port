# 第一章成长、塔与通缉推进效用：当前代码数学审计

日期：2026-09-25。仅审计与文档；没有修改游戏数值、存档或正式代码。原始数据、可复跑 Swift 小程序和 CSV 在 [progression 输出目录](../../output/chapter1-audit-20260925/progression/README.md)。

## 结论

当前没有“主角打怪得经验、升级提高基础属性”这条循环。第一章主要成长是解锁卡牌、天赋、两次技能强化、遗落物和教会装备。**塔与通缉的装备真实增加战斗伤害、血量和减伤，并非只涨角色页战力；能显著降低选定打法的卡关和药品压力。** 但天赋容量、技能尘供应和进度说明存在明确断层，不能据此认定整章成长已合理。

本次核心逐关探针中，零塔零通缉的高熟练候选组合在30关各找到胜例；固定中档策略败在Q8/Q19。持有支线装备后，中档变为30关均胜。这说明支线有可测战斗价值，**不证明零支线必卡，也不证明同一玩家新档能连续通关**：逐关探针预设已取得之前的合法权益，未串行兑现药费、磨损和调查用时。

早塔的强度前置值得审慎处理：正常1000基础HP、基础60普攻、无卡无药无勋章的新档条件，在作者时序模型内可循序打完前10层，取得+36%攻击、+270HP、11%直接伤害减伤；最险仅剩49HP。不是高属性测试人偶，也不是手机实玩或舒适性证明。

## 证据与方法

1. 独立 Swift Package 直接依赖当前 `MistportCombatCore`，没有复写伤害、敌人HP、奖励和装备公式。目录中的 `catalog.json` 是运行时导出，不从旧策划表抄参数。
2. `ChapterSimulator.swift` 从仓库 `NewMaskCandidateBalanceTests.swift` 的驱动摘取，保留50ms时间步、实际伤害结算、毒钟、敌人提交/接触、Q4教学拍点、后半章目标和Boss五次行动。增加玩家动作迟延参数；删除测试框架和打印。Q1–4不使用药品，以免暗赠第二瓶尚不可购买的药。
3. `TowerSimulator.swift` 从正式 `ChurchTowerVerification.swift` 的驱动摘取，允许传入当时合法配装。每层真正胜利之后才授予该层装备；按Q0、Q10、Q13、Q16、Q20资格推进。准备时长、支援目标/互斥和伤害来自核心；Unity接触回调用作者常数代替。通缉探针使用同一驱动的核心案战入口，接触近似0.65秒、首次行动近似3秒，故只作为准备程度比较，不当原生精确计时。
4. 360个主线情景（4路线×3策略×30关）、300个塔层顺序情景、120个通缉战斗情景；高档每格搜索多个合法卡序/盐囊或银扣/勋章6或14秒，报告其中少用药、剩余血量较高者。中档固定卡序/按题材选被动/每动作额外0.25秒，低档固定卡序、额外0.8秒、较差目标选择/较晚勋章。**这些是策略敏感性，不是人群熟练度分布或玩家胜率。** 普攻的2.4秒节奏与技能冷却相互制约，迟延不一定令每场耗时单调增长。
5. 365个起始日期枚举日刊案池；3万次不同固定战斗ID哈希抽样检查阵亡风险。奖励本身没有概率掉率，所以不伪造装备掉落 Monte Carlo。哈希抽样不证明随机独立性或后台防改时钟。
6. 复跑9/22成长诊断，重新验证30点/18节点、旧档补账与手动假面天赋路径。源文件SHA保存在 `source-sha256.txt`，日志保存在 `run-final.log`。

主线四路线的装备对照口径：主线不加教会装备；塔路线从Q5起假设清完当时开放层数，之后仅按正式门槛升级；通缉路线从Q5起假设已拿齐十案掉落。**后者特意是奖励作用的反事实上界，不是十案在Q4就全能打赢或同日能领齐。** 下文另用日刊、通缉无装备战斗与塔顺序结果限制可达性。

## 支线是否拿得到、需要多久

塔顺序模拟不提前赠装备：F1前没有装备、卡牌、药或勋章；真实赢F2后才戴其武器，F4后才穿其护甲。基础1000HP、60普攻来自正式默认；服装是新档雾港夜装（1%攻/1%减伤/2%固定哈希闪避）。不依赖旧测试样板的“最低Q7”默认配装。

三种动作迟延样本均完成前10层，最险49HP，约7.9–8.1分钟核心战斗；后续在Q10/13/16/20开放资格时继续，百层各约62.6/68.2/80.3分钟。主线的这些Q完成本身仍是条件，未把塔支线与主线失败/钱包串成一个玩家状态机。每层重开满血是正式规则，跨同层波次不回血；多波、先清治疗/强化者的目标策略属于模型帮助。参见 [tower-sequential-probes.csv](../../output/chapter1-audit-20260925/progression/tower-sequential-probes.csv)。

通缉小样（每格在两早期被动/三个勋章时点中取胜例，无药、无其他案装备）：Q4后无塔时B01/B07/B08/B09有胜例；加前10层装备后B02/B04/B06/B10也有胜例，B03/B05仍未找到。Q9后加前10层装备十案均有胜例；无塔要到本样本Q20后才十案均有胜例。不是穷举所有战术，不把未找到胜例当数学不可能。参见 [bounty-probes.csv](../../output/chapter1-audit-20260925/progression/bounty-probes.csv)。

正式日刊并不按旧案表的`unlockMission`发放：`ChapterOneTestView.swift:8446`打开公告→`GameStore.swift:2472`过滤尚未受理且未结案的同十案→每天固定抽3–6案（池不足则更少）→`2484`只准今日刊登或已经受理的案。证据/受理跨日期保留；每案`ChurchBounties.swift:407`只领一次。2026-09-25空账发行B08/B09/B06/B03；全接后次日B01/B04/B10/B02/B07；第三日B05。365起始日枚举，98次两日期、267次三日期可接齐，**这不是战斗完成时间分布，也不是每日重复收益**。新档当前日全结的铜币上限450、功勋92，非1060。

## 不能漏计的风险与维修

普通自有遗物每胜/败/退磨损2/5/3，修复按 `ceil(估值×损耗/200)`；假面与勋章不走此维修。银扣价值160，每次胜利的维修成本摊销约1.6铜，失败约4铜；用银扣连续打百层，预留约160铜维修，另有主线和通缉磨损。一次配装多件、按不同受益条件切换时须分件记账，不将“装备掉落”与“普通遗物耐久”混为一个系统。上述现金表尚未扣这些钱。

当前新租约：功勋只作资格；押金为估值约2/3再进十取整，租金为10%，覆盖三次实际战斗。正常磨损退全押金，损毁/遗失没收，旧功勋预付合同按旧快照履行。因此9/22“新高级租物每战扣6功勋、维护越打功勋越少”的描述已不能用于新约。借物本身不会永久增加基础HP/攻击；需要利用其机制，同时承担租金和冻结现金。

通缉阵亡真实扣费链：`ChurchBountyBattleView`的`onDefeat`（`ChapterOneTestView.swift:8904`）→`finishChurchBounty:2708`→`MPCBountyDefeatRisk`；35%事件丢当前铜币15%向上取整、最多60；12%事件从实际携带普通自有遗物中丢一件，特殊物/借物排除。固定战斗ID防重复结算，不等于失败不付代价。撤退没有这两项随机损失，但仍有磨损。

固定ID抽样10000条：铜损事件3519、遗物损事件1183；余额≥400时平均铜损21.114；若仅带160银扣，平均补买负担18.928，合计约40铜/败，尚未加药与磨损。带720物时其理论12%补买负担约86.4，再加21铜，单次失败的期望已高于B01整案60赏金。不要据此鼓励靠昂贵遗物反复失败刷通缉；也不能把这当现实金融风险建议。证据 [defeat-risk.json](../../output/chapter1-audit-20260925/progression/defeat-risk.json)。

## 建议排期，不在本次修改数值

1. 先修确定实现缺口：30点容量/分支取舍、旧Q15档少4点、正式手动假面对应天赋；这是已经给出的成长权益问题。
2. 明示“支线装备提供容错”：在Q5/Q8等节点提示可回塔拿装备，不用虚构经验等级门槛。前10层最险49HP，需真机陌生玩家验证；不得把数学有胜例写为无脑通。
3. 技能粉尘重新定目标后再补有限来源。目前两次Lv2之后整章没有更多升级，是明确的供应天花板；旧“塔每十层20、每案30、合计560尘”只是9/22候选，本次未实装/未验证，不拿它记账。
4. 提高两支线的不同构筑价值：通缉物只按攻击/HP数值递增时很快被塔覆盖。可先让少量装备保留特定机制用途，再测副作用、同槽取舍和伤害上限，避免直接叠加全部掉落。
5. 新银行/投资基线应以实际主线回刷、J0/J1/J2、租金/押金、维修与案战失败损失重新建模；保护主材储备可用提示和独立预算，不应让经济破产强制退档。
