# 串行成长模拟：按天推进 · 2026-09-29

接[塔层检定报告](../progression-sim-20260929-tower-check/README.md)。用户定：玩家不能靠投入更多时间取得领先，多玩只能多赚铜币；按每天 1–2 小时、约 30 天打完第一章设计。本轮只做规则和模拟器（第一步），App 接入是第二步。原始数据在 `raw/`。云端 Linux、Swift 6.0.3，规则库 476 个测试全过。**都是机器人结果，没有真机验证。**

## 规则（`DailyPacing.swift`）

| 内容 | 规则 |
|---|---|
| 主线 | 第 1 天开放 Q1–Q3（用户定，免得第一天只有一场短战斗），之后每天一关，Q30 在第 28 天开放；没来的日子照样累积 |
| 塔 | 首通额度每天 4 层，可累积；“第几关开放到第几层”仍然有效；重打不受限、不重复发首通奖励 |
| 通缉 | 不变（日刊每天 3–6 案） |
| 铜币 | 不限；商店遗落物仍按主线解锁 |
| 旧存档 | `migratedStart` 把建档日往前推，让下一关和下一层今天就开放 |

这些只是判断函数，**还没有接进 App 的开战和领奖流程**。第二步必须在开打前判断，打赢后一定发奖。本地存档只能信手机时钟，防改时间要等服务端。

## 为什么塔是每天 4 层

（下表是第一天只开 Q1 时比较的；改成第一天开 Q1–Q3 后结论不变。）

| 每天层数 | 全都做 / 先清支线：每天 ≤2 小时时第几天打完 | 说明 |
|---|---|---|
| 3 | 30–32 | Q30 当天才刚好凑够 F90，那天超过 2 小时 |
| **4** | **30** | F50、F70、F90 在第 13、18、23 天凑够，都比对应墙关早 |

## 结果（每天 4 层，第一天开 Q1–Q3）

| 打法 | 结果 | 打完是第几天 | 单日最长 | 每天 ≤2 小时时第几天打完 |
|---|---|---|---|---|
| 全都做（边推主线边做支线） | 9 局全部通关 | 28 | 20–40 分钟 | 28 |
| 先清支线 | 9 局全部通关 | 28 | 22–79 分钟 | 28 |
| 按提示只补必需支线 | 9 局全部通关 | 28 | 155–248 分钟（第 28 天） | 29–30 |
| 只打主线 / 只做塔 / 只做通缉 | 卡在 Q8 / Q12 / Q8 | — | — | — |

- 高熟练再快也要第 28 天才打完，低熟练同样第 28 天。时间换不来领先。
- 只补必需支线的玩家把爬塔拖到墙前，第 28 天要一口气爬 F71–F90 再打 Q30。如果平时每天爬几层，就和“全都做”一样不超过 2 小时。
- 六堵墙探针与上一轮相同（按天推进不影响单场战斗）。

## 还没解决的

- **每天的内容量远不到 1–2 小时。** 边推主线边爬塔的机器人，每天战斗平均 5–9 分钟（中位数 3–4 分钟）。真人更慢，再加上剧情，大概也只有每天十几二十分钟。剩下的时间怎么填，见[每日玩法与经济设计候选](../../../mistport-ios/docs/game-design/chapter-one-30/DAILY_LOOP_AND_ECONOMY_20260929.md)。
