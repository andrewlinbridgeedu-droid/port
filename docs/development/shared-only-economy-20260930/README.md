# 只有共享服时的铜币方案 · 2026-09-30

用户 2026-09-30 定：
- 没有单机，只有共享服；
- 不迁移旧存档，所有人从头开始；
- 不能离线玩；
- 游戏里的铜币数额“计算一个最合理的”。

本页是计算结果。**这是两套设计模型一起给出的结论，不是实测，也不能证明服务器不会通胀。**

## 结论：推荐方案

**游戏里写的数，就是服务器实际发和收的数。**方案如下：

| 项目 | 现在 | 共享服 | 说明 |
|---|---|---|---|
| **一次性奖励**：开局、主线首通、塔层首通、通缉结案 | 180 ＋ 2,280 ＋ 1,700 ＋ 1,060 ＝ 5,220 | **总额不变**，主线提前发一部分 | 服务器模型本来就按这个总额算 |
| └ 其中主线首通 | Q1–Q5 各 30 … Q26–Q29 各 120，Q30 300 | **Q3、Q5 各 130**（+100）；**Q26–Q29 各 80、Q30 260**（各 −40） | 见第 3 节 |
| **NPC 价格**：遗落物、止痛膏、晋阶主材、仪式、配方底料 | 遗落物 120–720，止痛膏 30，底料 8–13 | **不变** | 本来就和服务器的“24 铜工日、12 铜篮子”同一量级 |
| **送信（J0）** | 每单 40，不限次数，按单递减 | **每单 40，只在身上的钱低于恢复线时能做，每天最多 1 单** | 恢复线：Q17 前 180，之后 380／460／600，通关后 400（服务器模型原值，不改） |
| **街坊委托** | 送货＝订单价＋5，找东西 12，传话 8，赶塔怪 15 | 约 15%：送货＝订单价的 15%＋1，找东西 2，传话 1，赶塔怪 2 | |
| **余案** | 30 | **5** | |
| **世界事件**：交货单价、事件战 | 交货 4–12／件，事件战 10／场 | 约 15%：交货 1–2／件，事件战 2／场 | |
| **工坊订单**：NPC 每天的预算 | 60／天（最多攒 3 天） | **9／天**，单价不变 | 做得少、卖得少，不亏本 |
| **城市贡献度三类新内容** | 加急 15、街区难题 30、城市委托 60 | **第一章不给铜**（用户定）；之后 2／5／9 | |
| **每天的基本篮子**（新机制） | 没有 | **每个活跃日买一份，12 铜** | 服务器模型的前提，见第 4 节 |
| 亮灯公共目标 | — | 12（原定） | |
| 交易费 | — | 5%，进城市预算（原定） | |

四类钱在服务器上的出处：
- 一次性奖励：新发行；
- 每日玩法：从城市预算付，城市预算每天最多从 NPC 基本篮子和开放服务的销售额里收 20%；
- 送信：从恢复基金付；
- 篮子：付给 NPC 商户。

## 1. 为什么每日玩法只能付 15%

服务器经济模型（`tools/economy-decisions/final_check.py` 同一套规则、同一组情景，5 个种子 × 365 天）逐档提高每日玩法的比例：

| 比例 | 结果 |
|---|---|
| 15%、16%、17% | 所有正常和冲击情景都过线 |
| 18% | “供给减半 90 天后修复”不过：保护篮子缺货 |
| 20% 及以上 | 开服、稳定新增等基本情景也不过 |

所以上限是 17%，取 **15%** 留一点余量。原始结果见 `raw/share-ceiling.txt`。

## 2. 只把每日玩法降到 15% 不行

进度模拟器（`tools/progression-sim`，所有战斗走规则库）：

| 做法 | 结果 |
|---|---|
| 现有数值（旧单机） | 做完街头内容的玩家 28 天通关，章末余额 2,750–3,600 |
| 只把每日玩法（含送信）降到 15% | 所有玩法**第 7 天卡在 Q6**：送信每单只剩 6 铜，买不起 Q4 开放的遗落物和药 |
| 再按服务器规则改送信（恢复线以下 40、每天 1 单）、加每天 12 铜篮子 | 仍然**卡在 Q6**；等 30 天也过不去：送信只在 180 以下才给，买遗落物要 190（160＋30 的药） |

原因是**一次性奖励来得太晚**：
- 游戏里塔层和通缉的奖励要到 Q7 之后才开始发；
- 服务器模型里同样 5,220 的一次性奖励，从第一天起每个活跃日发两份。

前一周只有主线首通（每关 30），不够买 Q4 开放的遗落物。

## 3. 主线奖励提前发，总额不变

把 Q3、Q5 的首通各多给 n 铜，从 Q26–Q30 平均扣回 2n：

| n | 9 条“做完街头内容／按提示走”的模拟 |
|---|---|
| 50 | 6／9 在第 28 天前通关，最多 3 天买不起篮子 |
| 75 | 9／9 通关，最多 1 天买不起篮子 |
| **100（推荐）** | 9／9 通关，最多 1 天买不起篮子；章末余额 200–630 |

- 恢复线保持原来的 180 就够，不用改。
- 推荐方案下，Q7 在第 5 天、Q17 在第 15 天、Q30 在第 28 天，和原来的节奏一样。
- 做完街头内容的人基本不用送信；只推主线的人偶尔送 4–6 单。
- 章末余额从 2,750–3,600 降到 200–630：钱主要花在遗落物、药、主材和每天的篮子上，手上不再攒几千铜。

原始输出见 `raw/sim-*.txt`。

## 4. 服务器模型复核

`tools/economy-decisions/shared_only_check.py`（默认参数就是推荐方案）：主线提前 100、恢复线 180、每日玩法 15%、三类新内容第一章不给铜、之后按 15% 给。

- 9 个正常与冲击情景全部过 L1、严格价格线和 L3。
- 每日玩法 100% 付得出；低于恢复线的玩家 0–0.5%。
- 反例“照单机发币”被严格线挡住。
- 反例“每人每天无源多 30 铜”仍然挡不住。这和原定案一样，是已知局限：通胀监控以“按来源的发行是否都在预算内”为主，服务端审计已经按来源记账。

报告见 `raw/shared-check.md`。

**每天的基本篮子是新机制，需要你确认。**服务器模型的前提是每个活跃玩家每天买一份 12 铜的基本篮子（吃、住、燃料），这是把铜收回给 NPC 的主要出口。游戏里现在没有这个开销。可以挂在已有的地方，比如咖啡馆补给或住处；形式由你定，数额按模型是 12。

## 5. 不迁移、不能离线（用户定）

- 所有人从头开始，旧存档不上传，也就没有“本地财富带入”。服务端的带入接口在正式服关闭。
- 必须联网：
  - 战斗开票、结算和所有铜币变动都在服务器上；
  - 手机只负责操作和显示；
  - 断线时战斗暂停，重连后按服务器的记录继续或作废，不会重复发奖。

## 6. 局限

- 两套模型各看一半：进度模拟器看“玩家买不买得起”，服务器模型看“全服会不会通胀、缺货”。两边用的是同一组数，但不是同一个程序。
- 用时都是估计。模拟器里的玩家很理性，真人会乱花钱，也会漏做内容。
- 工坊：模拟器是“收入打 15% 折、底料照付”，会亏一点，比推荐的“预算降到 9、单价不变”更苛刻，所以推荐方案只会更宽松。
- 数额取整后很小（1–2 铜），手感要真机看；如果觉得太碎，可以把货币显示放大（例如 1 铜显示成 10 分），不影响经济。
