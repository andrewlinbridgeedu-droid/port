# 二维主角完整法术恢复 · 2026-10-02

用户在 169.27 真机反馈主角的法术效果消失。样板战斗的 `CombatTempoPresentation.PlayerAction` 提前截走普攻、假面、追击、终幕，只播放简化 `CombatTempoVFX.PlayerSpell`，还跳过了原来的命中效果注册。此前 42 次检查只证明动作与回执存在，没有验证完整法术，因此不能据此宣称特效完整。

现在删除这条快捷施法入口，复用 `BattlePrototype` 原有的飞牌与完整技能入口，由原效果负责唯一命中回执和命中华彩触发。AI 人物仍负责自己的动作，规则库、伤害、冷却、原效果的接触时点与其他战斗范围不改。手动假面不再附加重复的简化攻击。

追击与手动假面过去只复制三维蒙皮，而 AI 主角会隐藏旧模型。现在改为采样当前二维人物的帧，生成透明彩色影子；采样影子持有服装图集引用，换装不会提前卸载影子的贴图。没有改原动画或重画人物。

## 已验证

- Unity Mac 实际生产入口：三衣装 × 两档速度 × 普攻及九张技能牌，60 次施法均为一次命中、一次完成、一次命中华彩；接触时点与原效果预期差值在 0.10 规则秒内。
- 追击存在两份启用的二维影子，手动假面存在启用的二维护身影子；换装后冻结影子的图集仍有效；正式退出在接触前取消回执，清理人物和命中华彩。
- `unity-mac/passed.txt` 是原始探针结果；61 张 PNG 是实际 Mac Unity 帧，包含 60 次接触后约 0.10 规则秒的画面和一张手动假面图。两张总览由这些 PNG 缩小拼接。
- 作者抽看飞牌、假面、双影追击、终幕和手动假面：主体及命中华彩可见，护身影子可见。峰值帧里追击影子会与命中特效重叠，不能据一次峰值帧认定整个动作清晰度。

## 限制与失败记录

第一轮同时跑 Unity iOS 导出时，假面的接触回执为 0.683 秒，超过预期 0.380 秒 + 0.10 的容差，探针退出 2。保存 `first-run-failed.txt`；没有放宽断言。停止并行导出后，原封不动的检查包单独复跑完整 60 次通过。此现象与负载相关，但未测性能峰值，不能断言唯一原因。

Mac 检查包的旧调试 HUD 文本呈洋红块，PNG 原样保留，没有修图隐藏。它们只能作为法术与人物的 Mac 运行证据，不能当作 iPhone UI 截图或用户视觉认可。未录制，未验证真机帧率、峰值内存、三套服装全部真机逐招效果。手机抽看恢复了可见法术，不等于整套视觉认可。PR #41 继续草稿。

## 复跑

用 `BuildRuntimePreview.BuildMacPlayer` 输出 SSD 检查包，在没有同时导出 Unity 的条件下运行，环境变量 `MISTPORT_AI_HERO_CAPTURE` 指向新的 SSD 目录，参数 `--verify-ai-hero-spells`。探针在实际 `BattlePrototype` 场景运行，静音并自动退出；不访问手机或存档。

iOS 导出新鲜度、SSD 169.28 构建和签名校验通过；已安装同一台 iPhone 13，主角 ×1 样板胜利，安装与预览后 264 份 Preferences 严格字节一致。实际镜像图、原生回执、未完成范围和过早比较的时序问题见 [169.28 设备记录](device-169.28/README.md)。
