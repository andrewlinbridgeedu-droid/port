# 港城人物与可变通缉调查 · 设计决议

日期：2026-09-25。状态：**港城人物／可变调查部分仍为规划，不是十案真机验收**。用户后续决定 **Luna 暂缓，先用固定版本**；全员头顶姓名与可访问地点文字标记见 [早先实施记录](../../../../docs/development/HARBOR_LABEL_POKER_FIXED_UI_20260925.md)，两种牌局与赌注见 [牌局实施记录](../../../../docs/development/BOUNTY_CARD_MODES_20260925.md)。本稿以《请勿认领》第一章、现行 B01–B10、23 名街坊、用户画定的红／蓝道路为约束。角色故事以现行可玩案文为实施事实；B04「倒签客·乌檀」与 B06「熄灯药师·莱沃」是已确定的后续改写方向，但当前游戏仍使用旧案文和旧战斗路由，必须单列迁移。此前 GPT‑6 Pro 的「红巾错认」等新案只可借鉴调查结构，**不进入雾港正史**。

酒馆牌手现定为前港务抵押登记员 **灰筹·莫尔**：B08 结案后永久留在暮钟酒馆，普通铜币牌局可重复玩，偶尔以已解锁的遗落物或晋级主材作一次性彩头。案件线索牌局与常驻牌局分开结算；后者没有五局保底或口供。实施与验证边界见 [酒馆常驻牌桌记录](../../../../docs/development/TAVERN_PERMANENT_POKER_20260925.md)。

### 2026-09-25 最新通缉告示决议

用户否定旧双列卡片与“完成第几关后张贴”。现行实现改为本地每日 00:00 从**未受理且未结案的固定十案**中稳定抽取 3–6 份告示；同一天重进不重抽，已接案件跨日仍在“追缉进行中”，结案者不复活。抽取优先覆盖低、中、高三档，具体卷宗在告示上先展示所犯罪行、真实战斗招式、敌方生命／攻击、赏金与功勋、相对当前战力的估算危险，再由玩家决定是否领取。旧 `unlockMission` 数字只留旧档和历史制作索引，不是通缉的开放门槛；从酒馆与教会接案都无需先通主线关卡。告示板采用单列明亮档案卡，避免双列小照片遮掉最重要的危险信息。

通缉战可能阵亡，**玩家可重试，不设永久角色死亡**；本场真正携带的、可替代的普通遗落物才可能掉落，剧情关键遗落物、未携带物品、教会借物不会被没收。每次战败分别有 35% 概率失去当前铜币的 15%（最多 60 枚）、12% 概率失去一件符合条件的随身普通遗落物；可以同时发生，也可以都不发生。掉落按已结算的战斗 ID 记账，恢复旧档或重复回调不能重扣。调查证据与已接委托保留，故事正史中已经收押的罪犯不会为“每日刷新”复活。牌局输赢仍不扣物品。

**供给边界：**现有仅十个已制作可战斗身份；当未接且未结的剩余人数不足 3 时，只能张贴真实剩余人数，十案全部结束后不伪造新通缉犯。若要长期保证每天确有 3–6 个**新罪犯**，必须再制作独立身份、罪证链、形象、招式与奖池（或完成经审定的 Luna 模块池），不能让原十人无限复活、同一首通装备重复掉落。这是内容量边界，不是当前十案已实现无限每日供给。

## 决定：正史固定，调查过程可变

同一通缉案的罪犯、受害事实、作案手段、物证真实性、可排除的无辜者、最终战斗、解锁、赏金和装备固定。变化的是玩家最先得到哪条可信线索、由哪位有资格的人讲出可讲的部分、要先做哪种核验、哪条街先去、是否选择非必需的牌局，以及人物表达方式。变化必须改变至少一个**实际操作与调查顺序**，不能只把同一句话换词。玩家与故事仍追问「谁改写了一个人的记录，谁因此获利，哪个活人承担代价」，把日常邮递、工钱、医治、港务和继承连成第一章的“名字与认领”主题；港城外观继续明亮。悬疑感来自可靠性冲突、档案版本、责任链和仪式的实际代价，不复制《诡秘之主》的专有名词、角色或桥段。世界规则按 `WORLD_CONTINUITY.md`：港册只影响联网设施／身份权限，不改写全城记忆；偷来的记忆不能制造真实共同经历；公开记录可被覆写，但授权原存根须实地追查。Luna 不能为了制造谜团突破这三条规则。

每案应有作者预写且可离线完成的基线路线。Luna 可为**单次受理**组装一份经规则验证的变体，首次进入时整包存档；退出、重开、战败、重新进城都读这份包，绝不重抽。系统允许玩家以不同顺序遇到关键材料，不能让一次模型输出直接判定罪犯、授予证据、战斗胜利或奖励。每案至少两条不靠牌局的可解路径；牌局可以是第三条更短或更有角色味道的路线。

“每个玩家不一样”定为**高概率的实质差异**，不是无法证明的全球绝对唯一：服务端可对同案近期 `variantID`／路线签名去重，并在碰撞时换一份经校验的包；不因此放宽正史或可解性门槛。玩家自己的一个已受理案则始终同一版本，不能在进出地图时重随机。

GPT‑6 Pro 的核心建议是把港城当作一个**会记事的社会网络**，而非 23 个散落的线索按钮。日常谈话先建立职业、偏见和熟人关系；领案后，同一个人只谈他亲见或经手的那部分；玩家用原件、时间或另一独立证人验证，才能把口供升为可用证据。四组关系在十案中交叉：**投递与档案**（邮差、信使、门牌员、档案学徒），**商铺与顾客**（咖啡馆、花商、面包师、商人），**港务与夜路**（水手、码头工、抄账员、提灯人、钟表匠），**裁断与旁观**（巡街人、教会跑腿、学者、旅人）。同一句传闻在两人口中重述仍算同一来源。公民能满城移动，但其**现在的位置**绝不自动证明他在案发时去过那里。

## 23 名街坊都能谈，但各有立场

每人保留稳定 `id`、现有形象与街道路线。下表的“普通话题”是让城有生活感的对白方向；“案内职责”是可验证信息或调查行为，不代表一句寒暄就自动发证据。人物可以漫游全城，职业只决定常去区域。案内关键人物不得因随机路径失踪：卷宗提供上次可信区域，点击追踪后在该区逐渐显出人物名称；交谈时停步，正在等玩家出示证物的人可暂驻可信目的地。移动路径继续使用用户标出的街道，不因剧情生成捷径穿水或上屋顶。

人际关系要落实为追问和证据冲突：邮差与门牌登记员会争“地址写错”还是“牌被调换”，玩家需核两份原件；广场水手、乐师记得声音，钟表匠只认机械记录；咖啡馆跑堂记得离席先后，店主保护客人姓名；抄账员握底联、码头工人握交接单，任何一人单独都无法证明货物去向；巡街人会反驳旅人的以讹传讹。结案后有人道谢、有人不接受结果，也有人要为曾传错话道歉，但不能由 Luna 临时决定正史中的无辜者改口认罪。

上表只锁**职责**，不是最终台词。正式对白每人至少包含：一句可复听的日常街谈、一句接案后的角色立场、一条与已取得证据相关的问答、结案后一句后续反应；关键证人还需错误质疑、出示材料、已说过后的短对白。白色泡泡首屏控制在手机上能读完的 1–2 句，追问／出示证物／暂别用紧贴泡泡的小选项，不再弹旧黑色底部对话层；长原件在建筑内的独立卷宗页读。玩家点击远处人物，按现行港城交互直接将镜头聚焦、人物停步再对话；港城里不重新画一个跑到他跟前的主角。卷宗记录原话与来源。NPC 对玩家已查过的案有记忆，不在下一案重新作自我介绍。

**同职业不等于同一人。** 漫游的 `archive-apprentice-walk` 是档案学徒，B09 被栽赃的账房学徒仍是另一位；`clock-square` 广场水手、`sailor-walk` 离港水手与 B03 把线索押在牌局里的码头老水手是三位独立证人；B08 酒馆牌手也不凭职业自动并入 23 人。若今后想合并身份，必须先把原案口供、时序和独立来源规则整体修订，不能让 Luna 临时合并。

## 从谈话到缉捕：玩家实际要做什么

1. **接案与入城。** 教会告示板或酒馆柜台给同一案卷，提示最近可信目击区、受害事实和可问的职业，不标罪犯精确坐标；港城无主角，点击行人或屋顶标记使镜头聚焦、停步谈话或直接入屋。
2. **询问与复核。** 白色头顶泡泡允许“问当天经过”“出示已有物证”“质疑矛盾”“离开”。地点热点提供动手操作，如对齐钟时、叠印真章、拼收据、辨门闩、对照病历；行动成功由游戏规则判定。卷宗分栏记录**原始观察、转述、推断、被推翻的猜测**，保留说话人及原始出处。`witness/wound/exclude/compare/identity` 继续作旧档兼容结论 ID，其中 `wound` 是各案异常痕迹／行为／代价，不强求每案有肉体伤口。
3. **可选关系门槛。** B03 码头老水手、B08 酒馆牌手提供两种押铜币的牌局：易上手的五张换牌，或三人两副牌斗地主。赢牌获得他们承诺的情报，输牌失去本局赌注后可重试或查公开档案；不拿牌局输赢扣关键物品或关死案子。其他案件按身份用核对工单、保护人质、检查原件或得到受害者信任等交互，不普遍套牌局。
4. **定位和行动。** 至少两份独立原始来源与现场身份特征交叉成立，玩家才可主动出示通缉令进入既有战斗。错认只显示具体矛盾并留存此前材料；战败不抹调查。回教会或酒馆交案，奖励只结算一次。塔装备与通缉所得再回馈主线战力，和第一章成长曲线一起实玩检查。

现有游戏已接**固定五节点卷宗**与 B03／B08 牌局、两处交案和 B07 一次完整真机流程；上面的动态人物问答、各案多路线操作、白泡泡卷宗统一与服务端变体是后续设计，不冒充当前可玩内容。

## 十案不同操作，不是一条换皮的五格链

### B03／B08 的两种可选牌局（2026-09-25 实装）

简单牌局是五张换牌，不是单张比大小：双方各领五张，玩家可选零至三张换掉；对手只根据自己的牌型保留成牌或追同花，各换一次后同时摊牌。强弱从高到低为**同花顺、四条、葫芦、同花、顺子、三条、两对、一对、高牌**；同牌型比组成牌的点数，再比踢脚牌。A 可以是最大牌，也可以组成 A-2-3-4-5 最小顺子。完全同级同点数为平局。

发牌前从 10／20／40 铜币中自选赌注并立即寄存；赢局拿回赌注、再赢同额铜币与约定口供，输局失去赌注，平局退回赌注。前四局若没有赢得口供，第五局发牌保证即使玩家换掉任意三张也能胜；这一保底在界面明确告知，不暗改摊牌判定。若前四局耗尽铜币，已输赌注作为第五局抵押，第五局不再扣钱、胜后只给口供。退出牌桌时未摊开的手牌和已寄存赌注都保留，回来继续同一局，不再收费；重复结算同一局不能重复赢钱或扣钱。

**雾港斗地主是本作桌规，不冒充标准三人斗地主。**常见三人玩法是一副 54 张牌；两副 108 张通常用于四人。本作按玩家指定采用三人两副：三人各 34 张，余 6 张为底牌。依次叫 0–3 分，最高叫分者为地主，拿底牌先出，另两人合作；无人叫分则重新洗牌。同型同张数的单、对、三张、三带一／二、顺子、连对、飞机及带翼、四带二可以压过较小点数；顺子／连对／飞机不含 2 或王。4–8 张同点数是炸弹，长度较大的炸弹更强；四张王组成最大天王炸。两人连续不出后原出牌者重新领出。地主先出完即地主方胜；任一农民先出完即农民方胜。发牌与底牌每局完整随机，没有剧情保底；AI 仅根据自己的手牌、公开出牌和队友关系行动。玩家押 10／20／40 铜，输掉至多损失本局已押金额；赢局返还押金，另按叫分、炸弹、春天得到 1–8 倍净收益和口供，倍数封顶是雾港的经济规则，不宣称复制某平台现金结算。

两种牌局都可在右上角「？」查看玩法，牌背为港城星盘、灯塔与海浪的深蓝旧金纹章。牌局全输或铜币不足时仍可沿公开档案取得必要线索。牌局与通缉战败可能丢铜币／普通遗落物是两套独立结算。参考的公开规则：[Board Game Arena 三人斗地主简介](https://en.boardgamearena.com/gamepanel?game=fightthelandlord)、[JJ 两副牌四人斗地主牌型与炸弹规则](https://www.jj.cn/news/320/20110926162600018457.shtml)；三人两副、34＋6 分配和经济结算属于雾港自定变体。

## B07：同案两位玩家的实际差异

**玩家甲，先相信声音。** 领案看到“同一句求救在两街传出”的问题，先找到邮差，询问两条投递路线及时间；从其记录知道原说话者在诊所。向奥黛尔查病历与门闩样本，独立取得黏液和缺趾痕；登记员提示三间门牌曾互换。玩家将声源时间、门牌与木漆并排比对，发现第三空屋。若先责怪修门工，工单与五指工具痕会推翻猜测。到现场看铃蛙正在借声诱门，核喉铃与缺趾，选通缉令、战斗、回教会或酒馆交案。

**玩家乙，先相信物证。** 领案先去诊所看门闩，沿黏液／木屑追到木工街；修门工出示五指工具与夜班工单，证据说明他是错误嫌疑。门牌登记员让玩家发现“三号空屋”在旧簿与新牌的位置不同，但只凭此尚不能定罪。此时邮差的投递时序用于验证两处同刻求救，档案员核木漆与排水泥，确定第三间空屋。现场身份核验、战斗和交案与玩家甲相同。两人的调查顺序、人物提问内容、第一次误判和地图标记不同；最终事实与奖励相同。两条路线均不需扑克牌，任一关键 NPC 一时不在视野时可按职业／上次可信区域定位，不等随机巡游。

Pro 另提出“咖啡馆跑堂／店主提供不在场时间”和“空屋门从内侧打开”的第三组 B07 线索。这些细节**不是当前 B07 正史或现成资产**：若要采用，需先人工写出门闩检查动作、咖啡馆当夜记录、人物为何知道及与现有邮差／奥黛尔／修门工证据的关系，再加入事实卡并回归测试。Luna 不得自行发明这条新线。

## GPT‑6 Luna 案件变体服务：数据契约与权限

官方模型目录确认 `gpt-6-luna` 现可通过 Responses API 使用，支持 Structured Outputs；当前价格见官方页，报价不应硬编码到游戏。结构化输出只保证符合允许的 JSON 形状，**不保证线索逻辑或故事事实成立**，所以服务端还要做语义和图可解性验证。iOS 只向游戏服务端请求经签名／版本化的变体，不含 OpenAI 密钥；项目目前没有这项服务端或线上模型接入。

```
固定 CaseCanonPack（人工编写并入版本库）
  caseID, canonVersion, unlockMission, culpritID, battleID, rewardReceiptID
  immutableFactIDs, evidenceSourceGroups, safeSuspectIDs
  allowedNPCIDs, allowedLocationIDs, allowedInteractionIDs
  necessaryProofRule, fallbackVariantID
             ↓
领案时服务器输入：caseID + canonVersion + 匿名玩家种子 + 已知世界状态
             ↓
Luna 只输出 InvestigationVariant 候选（严格 JSON）
  openingLeadID, moduleRefs[], leadEdges[], speechPlanRefs[],
  optionalPokerBindingID
             ↓
服务端校验：ID 白名单／正史不变量／证据独立性／路网可达／
  双路线可解／无牌必可解／错误猜测可恢复／字数与安全过滤
             ↓
通过：服务端分配 variantID／计算路线签名／保存变体后返回客户端；
失败：返回作者基线包
```

拒绝 Luna 改写罪犯、物证真伪、NPC 已知事实、同一消息的原始来源、战斗数值、掉落、付费、主线生死、案卷开放或领奖状态。也不能让它“新造一间房”或把一个漫游人派到当前路网不可达处。作者先写 `CaseCanon`（不可变事实与奖励）、`InvestigationModule`（每一条经审定的证人／地点／动作／前提／失败回路）、`SpeechPlan`（同事实下可用的话术、立场与语气）；Luna **首版只返回这些条目的引用与排序，不自由编写关键事实句子**。`sourceGroupID` 识别转述链：两人读同一港务原单，仍只是一份独立来源。卷宗以 `factID` 加作者写的标准释义保存事实，泡泡可按审定句库择句和换追问顺序，因而每个玩家的对话可不同，含义仍可核验。二期可由 Luna 在服务端一次性改写**非证据性**寒暄／情绪句，逐句检查人物立场、禁编新事实和字数后存入该案快照；关键口供始终使用审定句库，点击人物时不再调用模型。对白不携带任意命令或原始 UI 事件；点击“调查”“给证据”仍由游戏规则核验。

候选包示意（以下 ID 只说明结构，实际 ID 在制作事实卡时定义；不是现有代码的数据）：

```json
  "caseID": "b07",
  "canonVersion": "b07-v1",
  "openingLeadID": "clinic-door-sample",
  "moduleRefs": ["clinic-door-sample", "carpenter-alibi", "postman-two-streets", "third-empty-house"],
  "leadEdges": [["clinic-door-sample", "carpenter-alibi"], ["carpenter-alibi", "postman-two-streets"], ["postman-two-streets", "third-empty-house"]],
  "speechPlanRefs": ["postman-after-door-sample", "carpenter-show-tool-order"],
  "optionalPokerBindingID": null

```

服务端只能返回审核通过的包或本地预写回退；`variantID` 由服务端赋值，不能信任模型自报。收到包后检查全部引用存在、对话角色确实能知道该事实、图从每个可达非终点都能完成、两组证据没有同源、关键 NPC 可沿已画道路找到、牌局全输仍可结案。首版先让模型选择**批准的模块组合**；若没有足够作者模块，无法凭一次 API 调用做出真正不同的调查剧情。

**生成时机。** 案件开放后可预热审核包，首次受理时只分配**一份**已审定整包；缓存缺失、超时、离线就使用作者基线，不让接案按钮等网络。街坊的案内台词已在当前 `SpeechPlan` 句库里；如果之后允许临场多轮闲聊，也只能补**不改变事实**的寒暄并按 `caseID + variantID + npcID + dialogueEventID` 缓存，绝不边聊边重写案件图。服务端保存版本、内容快照与校验摘要，客户端存不可变副本和事件记录；读档验证版本，旧档继续旧包，模型升级不改已受理案件。玩家取消、战败或重连不重抽；同案两处柜台、重复点击和网络重试共用稳定受理与领奖键，防止重复发奖。匿名种子只决定内容变化，不是拿玩家隐私做提示词。

**图验证。** 从领案初始线索开始广度搜索，节点只在其前提、开放关、地点和非消耗资源满足时可访问；分别禁用扑克、强制输牌、提前访问后证据保留、错误指认后恢复、断网只用本地包，确认都能达到“两份原始独立来源＋现场身份特征＋主动通缉令”。含随机漫游的节点必须有可追踪区域和可稳定对话的时段；跨区／回访次数超过 UX 预算则回退。仅 schema 通过不能放行。做 1000 个种子压力验证、每案人工审读不少于 20 包，检查单次调查时长、重复对白、线索矛盾与软锁；达标后再允许模型包进入生产。具体数量是首轮验收目标，可随测试调整。

**费用与服务。** 单次受理限一次生成调用和一次短重试，出错回本地；服务端按玩家／案号幂等去重、缓存高质量包并限制月支出。官方价格当前为每百万输入 $0.10、输出 $0.50 美元，真实每案费用还取决于提示、输出长度、重试、缓存与服务器成本。首版只对内部测试账号开动态包，保留关停开关；不把网络可用性或模型回答作为领奖前提。

## 制作顺序与可验收的边界
