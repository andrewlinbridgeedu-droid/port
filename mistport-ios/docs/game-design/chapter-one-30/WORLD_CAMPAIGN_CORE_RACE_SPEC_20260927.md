# 世界战役四层突破：离线候选与接入缺口

**后续方案边界：**[完整事件案](WORLD_EVENT_LIGHTS_CASE_20260927.md)新增公共成果决定暂定经营权、核心可翻转合同的规则，并把四次成功分别叙述为三处节点和一次人物决战。本页保留核心聚合的历史数学证据；“独占”旧概率不能直接作为新合同胜率。各层难度不同须重新计算，不能把同概率模型当真人证据。

用户随后明确“人数/组织占优，少数靠准备与操作翻盘”。当前扩展入口为[人人推进、强者突破](WORLD_EVENT_PUBLIC_FRONT_20260927.md)：全员公共战线影响最终机会，四层突破保留作末阶段候选。本页概率与缺席结果仍有效，不再把至多12人的末阶段当成完整世界事件。

2026-09-27。用户提供了 Pro 第二轮终稿；[原文](../../../../docs/development/world-campaign-prototype-20260927/core-race-review/PRO_REPLY.txt)已存档，[独立数学与规则复核](../../../../docs/development/world-campaign-prototype-20260927/core-race-review/REVIEW.md)已完成。

**当前结论：可作为下一版聚合规则原型，尚不能冻结成正式全服玩法。** 4/5/6次名额解决了无限人数抽胜利的问题，同时把核心世界贡献限制为双方合计最多12人。参与感、真实消费需求、选人和缺席安排尚未解决。正式战役、两场新Boss和共享经济没有因此上线。

本文件是聚合规则的最新入口；[上一轮核心战与需求规格](WORLD_CAMPAIGN_CORE_IMPLEMENTATION_SPEC_20260927.md)保留需求测量、时间线、分账和遥测要求，其中“一次核心胜利直接令NPC死亡”的旧候选由本轮四次突破候选替代。已有 Swift 原型行为尚未迁移，不能将 Python 离线模型写成 Swift 已更新。

## 可运行的离线聚合模型

实现：`tools/economy-agent-sim/campaign_core_race.py`。这是经济研究工具目录的不可变状态机，不连接 GameStore、Preferences 或真实钱包；没有新增现金、药耗、维修或商品消耗。

### 输入

- `campaign_id`：战役标识；本地输入，不代表已认证。
- `required=4`：目标突破成功数。
- `caps=(4/5/6, 4/5/6)`：各方机会；试验也允许0以检查关闭与冷服。正式资格不足不能假造候选。
- 固定账号—阵营资格表：上游在截止前验证加入阵营、外围贡献等条件，模型不自行授予资格。
- 每轮每个仍有机会的阵营提交一个结果：success、defeat、timeout、unfilled。

### 原子结算

1. 完整收齐该轮双方结果才调用；无机会的一方不提交结果。
2. 每个已开战账号不论胜败或超时，本次唯一世界机会都使用完毕。防止失败后换票无限重试。
3. 未开战且替补也未填满的名额提交 `unfilled`，消耗本阵营一轮机会，不伪造账号或胜利。截止前的预约/替补在上游处理。
4. 同轮先累计双方突破，再统一比较4层门槛；A达标导致B人物死亡，B达标导致A人物死亡，同轮双方达标为双死。
5. 一方/双方达标即停止后续世界轮次；机会耗尽无人达标为僵局。
6. 同轮同内容重放不重复作用，冲突内容、缺侧、重复账号、错阵营、越序和闭幕后新世界结果全部拒绝。个人迟到战绩由另一个账处理，不能再调用世界结算修改历史。

模型只有人物A/B死亡结果，**没有**正式人物实体/跨事件死亡库、持久化事务、挑战认证、上传宽限、网络战斗重演或抽选。共享服须一次事务落库波次回执、已用资格、突破、人物死亡和新闻事实；不能直接相信客户端给出的 success。

## 四次胜利不能演成同一个NPC死四遍

Pro把“单场核心NPC HP=0”同时用作“突破+1”和“第四次才永久死”，表现上存在冲突。

下一版候选语义：普通突破战击败的是核心防护节点/护卫负责人，战斗结果叫“突破完成”，**不播放目标NPC死亡、不发NPC遗产**。本轮已有3层且挑战获胜时，服务端才签发最终人物死亡事实；双边同轮达标允许双死。前3层应各有可见世界变化和新闻，不能只是同一人反复倒地。

两套Boss规则可复用为不同节点的战斗模板，但实体ID不同。正式人物、节点名单和最后一击演出仍需故事核定；当前不把内部A/B写入正史。

## 抽选、缺席与截止：正式接入前必须补齐

### 抽选

Pro的 `Hash(campaignID, factionID, waveIndex, playerID)` 若输入全公开可预测，会产生挑账号/筛账号优势；可复算也不等于有独立公平身份。

原型先固定阵营报名截止与候选快照，投资/月卡权重均为0。正式候选方案采用不可由玩家选择的稳定账号ID、预先承诺后揭示的随机种子、固定快照与公开排序算法；具体随机源、资格延迟、候补顺序及审计另行实现。本轮代码没有实现这个选人器。

用户已要求新闻推动参与，因此报名与候选通知必须提前公开，允许自愿确认愿意承担核心战；不能从所有离线合格账号中随机抽中后直接判缺席。

### 缺席与替补

开战前拒绝/未确认可换候补；真正开战后失败、撤退或正常断线超时消耗该账号机会，不允许靠拔网线无限重开。服务器故障不是玩家失败，故障补偿规则需可核验且防重复。替补必须有最终截止，不能不断换人直到得到成功回执。

文中“每轮等360秒战斗”与Boss180秒互相冲突。候选应明确拆成预约/候补时间、单战180秒、上传宽限与整轮关闭时间；180秒从权威开始回执计，普通接收时间不能取代合法命中时间。

6轮若连续各占6分钟，会形成约36分钟同步出勤要求，与异步参与的便利存在冲突。先比较预告的集中行动窗口和跨时段预约窗口，再冻结秒数；这两种安排的缺席分布不能套同一概率表。模型的 `settle_wave` 只表示上游已合法关窗，不负责计时。

## 名额稀缺不能冒充大规模参与与需求

四层方案把世界决定权留给至多12次挑战，不足以单独兑现“多数玩家购置强封印物、改变世界”的体验。首版要测外围和准备行为是否真正值得玩，而不是默认388名未入选者愿意当供应者。

可以继续研究的低成本方向：人人可做有个人记录的外围/演练，核心前公开节点情报和阵营准备结果，供货/外围贡献者在结果新闻中体现真实作用。演练默认隔离物品与奖励，不为了经济制造无限收费练习。外围如果只有刷条也不自动算好玩；至少记录参与、复玩、退出原因、真实消耗和未入选者继续参战意愿。

先保留4/5/6作为可比较的一支，不擅自采用“增加核心名额却仍每4胜致死”，否则重新引入大服必杀。扩大核心实际参与必须同时重算聚合规则、独特贡献和结局概率。

## 真人试验与物品愿付价值的修订

正式世界核心每账号只有一次机会，因此 `attemptsToFirstWin` 只能用于独立试玩/演练或跨战役序列，不能当作同一正式战役可无限重试。试玩与正式世界效果必须分开记录。

H1随机测试药可估药品效用；“自有普通封印物＋自由购药”第三组有财富、装备、经验和自选偏差，只能描述相关性。可在同装备/经验层内随机分配测试药，按玩家聚类、首尝/复尝分开报告；不同路线与两装备档不混成单一胜率。共享市场未上线前的虚拟钱包选择也不是已观察到的真实市场成交。

每组60次首尝，在成功率附近50%时Wilson95%区间约37.7%–62.3%；120次总样本不是自动区分40%/55%/70%的通行证。验收以区间精度与真实效果为准，不保证固定样本量足够。

Pro的 `C0/p0−C1/p1`（剔除待定物品价）是“每次最终成功”的现金节省额度，不能直接当作每瓶/每次耗材价格。若每次准备尝试平均消耗q单位、单价x、其它成本c1，则持平条件：

`(c1 + q×x)/p1 ≤ c0/p0`，所以 `x ≤ (p1×c0/p0 − c1)/q`。

一次性购买反复使用的物品、每次消耗的药和有剩余库存的药包有不同口径。例：p0=.45、c0=4、p1=.65、c1=4、q=1，每次耗材现金持平上限1.7778铜；每次成功现金节省2.7350铜，两者不能混用。有限票据、退出和学习下仍需真实记录，不能直接套无限独立重试模型。

## 下一步实施门槛

1. 离线四层聚合已有可运行代码和精确概率基线，可供Swift迁移；迁移须保留边界测试，不能覆盖现行游戏奖励。
2. 先补大多数玩家的外围体验与选人/预约流程，测不同人数、阵营比例和缺席；核心名额限制仍是候选，不因数学成立而自动冻结。
3. 两Boss显式版本的隔离原型已完成，已补机制边界测试；原72项清单和真人试玩仍需逐项完成，不把测试数量相近视为同一套验收。聚合模型与真实战斗分别验收。
4. 时间线、新人物、8类事实新闻、永久死亡账与项目真实收入逐项接入。没有真实收入不分红，没有真实物品使用不预支需求，没有服务端资产账不开放自由市场。

本轮已新增独立macOS演练应用并构建运行，临时Swift缓存位于`/tmp/mistport-campaign-*`；没有新增iPhone安装、Unity导出或真机试验，也未覆盖此前保留的构建和外置盘链接。
