# 玩家工作：先有操作，再有工资

用户授权开始经济原型，但进一步指出“护送、调查、搬运、验收”尚未说明实际游戏操作。修正原则：不能把任务故事名、倒计时或点交付当成已存在玩法。

## 第一版玩家流程（待接游戏）

1. 城市公告或工坊显示“清理泵站作业区”：雇主、指定战场、敌人、固定报酬、完成条件。报酬由真实雇主预算预留，不需要玩家先交押金。
2. 玩家接取后进入绑定委托的战场，使用已有实时战斗操作击败指定敌人。这里需要制作／选用合适战场和接线，不代表当前构建已有该任务。
3. 规则层记录委托ID、玩家ID、目标和唯一胜利事件；未来共享服必须由服务器验证，不能信任客户端“已胜利”的声明。
4. 验收成功后，托管工资到账一次，工坊进入可生产状态。失败不发该笔完成报酬；允许重试或放弃，放弃时未支付预算退回雇主，不处罚玩家真实存档。
5. NPC负责后续搬运、生产和普通质量验收，玩家无需反复点击“交付”。项目利润与玩家完成工作的报酬分开；工资已托管，不因老板后续经营亏损被追回。

报酬要按战斗难度、实际耗时、必要耗材与失败成本核定。24铜普通工日只是NPC劳动成本标尺，不是玩家在线八小时，不是签到自动工资。原型120铜仅为新成本拆分夹具，不是已批准奖励。

## 其它例子如何处理

- 燃料路线：第一版可做拦路怪清场，NPC运输；真正护送需要移动货车、货车受击／生命、敌人目标选择和路线机制，暂不冒充已制作。
- 冒领调查：后续需有运单、证词、可对照的时间／数量／封印、玩家选证据和结论分支；不能只点两段对白拿钱。
- 零件配送：无额外玩法时由NPC完成，不要求玩家跑腿刷工资。
- 普通验收：由NPC执行；仅将值得推理的异常作为调查委托。
- 冷服无人接：需要有预算、时间与能力限制的NPC承接，不能让全球技术停滞。当前无人工作测试将其标为未解决失败边界。

## 本轮实际制作

独立可执行原型见 `tools/economy-prototype/`，六项结算测试覆盖工资验收／重复、失败退款、进口支付／延迟、贷款坏账／全体提款、产业交付回款和失败损失；多人180／365日场景输出见 `docs/development/economy-contract-prototype-results/`。

本轮没有修改Swift、Unity、玩家存档或设备构建；游戏委托界面、战场绑定、服务器鉴权／并发数据库和真实主线可达性仍待实施。该原型是规则与资金流验证，不能写成新玩法已能在手机上玩。
