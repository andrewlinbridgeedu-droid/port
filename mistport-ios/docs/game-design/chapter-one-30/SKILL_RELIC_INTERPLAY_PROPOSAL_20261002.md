# 雾港第一章：技能牌与遗落物衔接提案

版本：v1 · 2026-10-02 · Codex

**状态：完整设计候选，待用户评审。本文没有修改游戏规则、数值、资产或存档；新增效果尚未模拟，也未经真机认可。**

本提案承接用户提供的《技能牌与遗落物的衔接》五方案稿，收敛为可以分批验证的设计。核心建议是：**让遗落物参与现有的“误认—转换—错位—兑现”，使玩家在战斗中选择何时按、对谁按；第一批只做僭命勋章、空栏名片、返礼银扣。**

本文用“张冠李戴”“无主假面”称呼候选稿中的物件。核对的源码仍有“身份错置”“假面谕令”旧显示名；本文不构成改名批准，也不恢复第一章已经撤掉的假面技能牌。

## 1. 希望玩家得到什么

玩家编排四张牌以后，既能让角色顺畅地自动施法，也能通过目标切换和主动遗落物改变这一轮的结果。

理想的一次决定是：钟匠已有三层误认，下一张转换牌即将出手。现在借勋章，能够提前转换并兑现伤害；但八秒后要交半血，必须看清接下来的敌方重击。另一种决定是：银扣刚替主角收容了一击，攻击者拿到了回礼盾。玩家把下一张反客为主送给这个攻击者，夺回仍剩下的盾，再接荒谬归结。

这两次决定都有可见的起因、收益和代价。玩家应能说出“我为什么在这时按它”，而不只记住一个冷却好了就按的按钮。

成功的体验包含四件事：

1. 误认、错位和可夺回的盾，在手机上容易辨认。
2. 同一套牌换一种遗落物，会产生不同的使用时机。
3. 用错时机仍可能吃亏；物件的异常代价保持存在。
4. 不带这三件物件时，已有技能链仍完整可用。

## 3. 共用规则：让每条衔接说得清楚

### 3.1 误认属于具体敌人

误认总量为 0–4。物件和牌写入同一份目标状态，不另开“遗落物误认”。溢出截到四层，不兑换伤害、护盾或额外彩头。目标死亡或离场后，状态不转给另一个敌人；新波次的同类敌人也不是原目标。

第一批不增加自动转换。名片把敌人补到四层，仍须由转换牌出手，才得到错位。

### 3.2 转换阈值与资源消耗

僭命勋章有效期间，转换阈值候选为三层，通常为四层。阈值降低只影响“够不够转换”，成功时仍按原转换契约清掉误认，不返还多余层数；不增加转换伤害、错位余额或额外延迟。

无名宣告的说明包含“一次两层转换”，本次核对的组合计算却仍直接判断四层。实施前先做说明、实际战斗路径与服务器路径的契约核对。**若核准的终极契约确为两层，最终阈值取最低：终极两层、勋章三层、通常四层；不会把降低量相加。**终极权益何时消耗必须沿用其核准契约，不能在这一批顺手扩张。

### 3.3 错位的建议口径

本提案建议沿用已核对的兑现余额，玩家看到“错位”以及最多两道短记号：双影用掉一道，荒谬收掉余下的错位。普通错步读取状态，沿用已有消耗契约。

第一批不新增错位时限，也不把余额擅自换算成秒。“余额是否应改为时限”属于独立规则变更，需要另行认可。若最新 main 已采用另一套核准契约，则先更新此表和测试基线，不能混用两种口径。

名片不延长错位，勋章不保留已经兑现的错位。这两条限制使“再铺垫一次”仍有意义。

### 3.4 错位与控制分开

获得错位不等于打断全部敌方动作。沿用对应敌人的普通、精英、Boss 抗性和当前延迟规则。已经离手的火球、已经发生的命中不会被撤销；不能靠反复转换永久压住重击。

新增效果不得绕过真正免疫或已有不可驱散标记。具体目标是否接受状态，由规则库判断，画面不能自行补一个“看起来成功”的错位。

### 3.5 时间与事件顺序

所有秒数使用战斗逻辑时间。暂停不走计时；切目标不刷新计时；战斗加速按现有方式推进逻辑时间。×2 下三秒窗口约占一点五秒现实时间，必须实际验证可操作性。

同一逻辑时刻先处理已经到期的窗口和应付代价，再处理新输入与命中。例如勋章恰在第八秒到期，此后的转换不再享受三层阈值；名片到期后的命中不再被其拒收。事件先后使用稳定序号，App 与服务器不能各算一种结果。

## 4. 第一批三件物件

以下所有新增数值都是首轮候选。既有数值最终以实施时规则库的核准常量为准，不在 App 另写一份。

### 4.1 僭命勋章：“冒名”

**原效果保留：**发动八秒，生命及攻击变化按既有契约执行；二十四秒冷却；结束交出剩余生命的一半。胜利、死亡、撤退和到期的清算保持一次且不能逃避。

**新增：**有效期间，转换牌在目标已有三层误认时即可转换。除阈值外，转换规则不变。

**玩家决定：**借命保住当前重击，还是等误认到三层、下一张转换牌就绪再借？八秒后敌人是否将打来另一击？

**失败仍有代价：**目标只两层、转换尚在冷却或期间切错目标，都不会凭空多给层数；八秒结束照样交命。战中换装、结束战斗或返回页面不得撤销这一笔代价。

**显示：**勋章亮起时，转换牌出现短标签“3层可换”；选中目标够层数且该牌就绪时，再给一次短促边光。没有取得转换牌时，勋章仍正常借命，界面只显示已有用途。

**玩家文案候选：**“借来的身份尚未归还，三道误认便足以换名。八秒后，交出余命的一半。”

### 4.2 空栏名片：“无人签收”

**原效果保留：**选定一名敌人，三秒内双方彼此的直接伤害被拒收，十八秒冷却。自己的技能照常消耗；第三方攻击、持续伤害和控制仍按原规则生效。

**新增：**窗口内至少有一次来自这名敌人、本应造成正值直接伤害的命中，确实被名片拒收，才在窗口自然结束时给同一名存活敌人增加两层误认。一个窗口只记一次。

这比原稿“到期自动加两层”多一个成立条件：玩家须看准敌人的攻击，不会面对不出手的敌人白拿铺垫。被闪避、原本零伤、被真正免疫取消的攻击不计；毒伤和第三方命中不计；多段命中也不多发层数。

**玩家决定：**拒收即将命中的攻击，为下一张转换做铺垫；但自己的兑现招若在三秒里打向这名敌人，也可能白白消耗。可以切到另一名敌人输出，但名片始终绑定原目标，不跟着选择移动。

**结束边界：**目标提前死亡或离场、主角死亡、战斗已经结束或撤退，均不补层、不转寄。目标已有错位时仍可按状态资格补误认，但不延长或刷新错位。互相拒伤窗口没有“把打空的伤害储存后返还”的效果。

**显示：**目标名牌变空；一次攻击被成功拒收时出现“拒收”，空名牌留下两道淡墨痕。自然结束且实际补层时出现“误认+2”；不成立则正常收起名片。

**玩家文案候选：**“三秒之内，你们的直伤互不认领。若拒收到他的攻击，空名牌收起时，他会多认错两次。”

### 4.3 返礼银扣：“回礼”

**原效果保留：**符合现行资格的一次直击触发有限收容；攻击者立即得到吸收量一半的普通护盾。既有收容量、八秒冷却和赠盾破除条件都保持。

**新增：**这份回礼盾带可识别来源。带着银扣使用反客为主时，若当前目标还有这份盾，优先夺回它：从敌人身上移除盾，把其**当前剩余量**转为主角护盾，并施加一道错位。

例如敌人最初得到一百盾，之后被打掉六十，夺回只得到四十。不是恢复最初一百，不复制已经消耗的盾，不转成治疗，不再次乘攻击或装备倍率。与主角现有盾的合并沿用对应护盾契约。

若回礼盾已经被打光，则不再返盾；反客为主照常处理其他可驱散增益，或走“无增益时加误认”的原分支。一次出手只执行一个分支，不同时夺回多项增益。

**玩家决定：**看到谁拿到了回礼盾，就把下一张反客为主送给谁。也可以选择继续打破盾，或优先对付更危险的另一个敌人。本文不增加嘲讽，也不承诺玩家能指定银扣替哪名敌人的攻击触发。

**限制：**夺回盾视为原赠盾债务已结清，但八秒冷却不会重置。若当前快节奏规则允许银扣被轻击触发，仍沿用该资格；不能悄悄改成只接重击。其体验是否被轻击抢先触发破坏，要列入样板复看。

**显示：**回礼盾用银扣的小结扣记号标“可夺”。夺回时由敌人身上的盾拆成一束银丝，收回主角手腕；原目标得到错位记号。没有剩余盾时不演出一份虚假的盾。

**玩家文案候选：**“拒收的一击，会还给来者一份盾。反客为主可将剩下的回礼夺回，让他认错主人。”

## 5. 战前搭配与战斗示例

### 5.1 保留四张牌的取舍

| 搭配 | 普通牌示例 | 主要选择 |
|---|---|---|
| 借命兑现 | 伪证 → 转换 → 双影 → 荒谬；主动勋章，被动按敌人选择 | 三层时提前转换，双影用一道错位、荒谬收尾；缺少反客，无法夺回回礼 |
| 拒收反制 | 伪证 → 转换 → 反客 → 荒谬；主动名片、被动银扣 | 名片挡伤后补层，银扣回礼给另一条反客路径；少了双影的双段兑现 |
| 保命搭配 | 已获得的牌；主动假面，被动盐囊或其他防守物件 | 继续使用原有防守与技能衔接，不强迫加入新增效果 |

这些是展示不同选择的例子，不是推荐玩家永远照抄的最优配方。前两套须在实际拥有物件和对应牌后才能配齐。四张普通牌之外，终极按已有独立规则取得和使用。

### 5.2 Q22：把候选稿的示例补完整

合法样板带僭命勋章、返礼银扣，以及独立通缉栏的伪造者倒签笔；四张普通牌为伪证、转换、反客、荒谬。

先在钟匠身上铺误认。守卫攻击触发银扣后，守卫出现可夺的回礼盾。玩家在下一张反客起手前切到守卫，夺回仍剩下的盾；若之后荒谬可用，则用掉守卫的错位。再切回钟匠，在它已有三层且转换将出手时发动勋章，提前换名。

钟匠的校准依然必须处理，倒签笔也依然需要装备；这套组合不自动通过校准。勋章交命可能撞上后续重击，操作失误仍可能失败。

这里描述的是成立条件，不虚构“第几秒必然出哪张”。开场后各牌冷却不同，必须用实际调度器证明存在可操作窗口；若并不存在，则修改搭配示例或新增效果，不能用手动指定技能的测试冒充真实自动卡栏。

### 5.3 第一章的渐进教学

| 阶段 | 玩家已能理解的内容 | 教学安排 |
|---|---|---|
| Q1–Q7 | 既有攻击、防守、假面与借命 | 保持原教学；尚无转换牌，不提前讲完整新链条 |
| Q8 | 两格与转换牌 | 学会看误认、换名；若已持勋章，提示三层提前转换 |
| Q9 | 伪证与转换 | 展示两格也能成立的铺垫和转换，不借未取得的牌 |
| Q10–Q11 | 四格、双影、荒谬 | 让玩家看见错位如何分配给双影与收尾 |
| Q12 起 | 反客与敌方增益 | 玩家实际持有银扣时，用一次回礼展示夺盾 |
| 名片首次具备衔接条件 | 物件已取得且能使用转换牌 | 短句提示“看准他出手再拒收”，实战中教一次成功和一次落空 |

教学不发额外假面次数、不赠新物件、不改变日限。教学夹具与正式账户分开。提示完成标记只表示看过，不表示用户已认可效果。

## 6. 画面、卡牌与声音

### 6.1 状态显示

误认统一用旧紫墨的破损名牌记号，最多四道；选中敌人可显示“误认 3/4”。来源只在发生时短暂出现物件小图或短词，不为每一种来源增加一套永久颜色。

错位用两张错开的名牌或短丝带记号，清楚显示剩余兑现机会。回礼盾用银扣记号。三类状态必须靠轮廓也能区分，不能只依赖颜色。

卡牌要分清三件事：技能是否就绪、当前目标是否满足强化条件、是否轮到下一张出手。条件亮牌不能让玩家误以为可以直接点击施放；下一张用独立的小角标提示，冷却中不闪“现在能用”的强光。

所有数量、短标签和说明均由规则事件或状态生成，不烘焙在卡图里。换服装只换主角外观，技能身份、动作、战场和状态表现保持一致。

### 6.2 三种衔接的视觉身份

| 效果 | 主体与材质 | 动作与回收 |
|---|---|---|
| 冒名转换 | 旧铜勋章借出一束不完整金线，扯动目标港册名牌 | 线先绷紧，帽子或名牌骤然换位；线立即断开收回，留下错位 |
| 无人签收 | 泛黄空名片、被拒回的墨字与两道紫墨痕 | 命中被拒时墨字从空白处擦过；窗口结束，墨痕落回同一目标名牌 |
| 回礼夺回 | 银扣、结扣与被拆开的盾光 | 丝线迅速扯回剩余盾，扣在主角手腕；敌方外壳消退，错位记号出现 |

命中瞬间要有快速展开与明确回收。新增衔接叠在既有法术演出上，第一批不重做整套法术。禁止把直边框、规则光板、完整等距圆环或平行光条当作主体；不拿三个换色的爆炸代替三个物件身份。

数字与短词合并去重，避免每次加层都堆一屏。多人敌方编队优先让选中目标、即将重击的敌人和可夺盾清楚，不能遮住身体动作与预告。

### 6.3 音响与操作

冒名用短铜鸣，拒收用轻纸擦，回礼用银扣合拢。音量与同时发声数量沿用现有混音预算。主动按钮接受操作后才响确认声；操作无效不播放成功声音。

名片与勋章是原有按钮，不新增第三条资源或连按小游戏。×2 保留随时切回 ×1 的既有操作，不能为新效果扩大规则时间窗而让服务器复算不同。

## 7. 第二批及其他物件的安排

第二批在第一批规则与真机体验认可之后再选，不与第一批一起打包上线。

| 物件或方案 | 建议安排 | 必须保持的边界 |
|---|---|---|
| 迟签印章 | 优先第二批：原迟到伤害实际落地且目标仍存活、有误认时，候选再加一层 | 一张迟到票据只加一次；伤害作废不加；不能生成新迟签票据或触发自身循环 |
| 对戏徽记 | 第一批可展示三条已有关系：勋章—转换、名片—转换、银扣—反客 | 徽记说明已有衔接，不再额外叠一份加成；图鉴不发数值奖励 |
| 无主假面 | 第三批可试：实际发动后的一次合资格承接，给真实攻击者一层误认 | 每次发动最多一次；永久裂纹照付。仅持有或配上转换牌绝不能免费挡伤 |
| 缄卷镇纸 | 先保留封掉第3槽换庇护 | 不返还被封的整招；存误认的规则以后单独试，以免封牌代价消失 |
| 盐囊、墨镜、铜锚、断线针 | 保留各自防守和反制用途 | 不要求所有物件读写误认，不按统一模板补一个伤害加成 |
| 三件墙关通缉遗落物 | 保持克制机制职责，继续独立装备 | 不因普通被动已可保留而强制加“对戏” |
| 沉睡遗落物 | 按原街区和后续章节逐件设计 | 不在第一章批量复活二十多件，不靠增加装备位装下它们 |
| 方案二“加演” | 后续独立样板 | 先证明“下一张”实际可读、可操作；额外段伤害与勋章及兑现加成要复算 |
| 方案三“以伤换戏” | 暂留第二章研究 | 不返还名片全部打空伤害，不把封牌完整补回，不把永久裂纹当收益材料 |
| 方案五“满堂彩” | 第一章不采用 | 暂不增加第三种战斗资源、攒满奖励或额外进度权益 |

异常代价是否成立，要看它是否仍会改变使用时机并留下失败风险。掉血与返还伤害的数字相减，不能单独证明风险存在，也不能把“总效益必须净亏”当作物件值得使用的标准。

## 8. 规则库、App 与服务器接入建议

此节是后续开发规格，不表示当前已经接入。

### 8.1 单一规则入口

在现有纯 Swift 战斗规则中增加集中配置，候选名 `MPCRelicInterplayRules`，记录版本与启用范围。三层阈值、两层补误认等数量只在规则库定义；App、Unity 与服务器读取或消费同一份结果。

优先把转换阈值计算、名片到期衔接、带来源的赠盾转移做成共用纯规则。App 实际战斗路径、教会步进器、主线步进器和成长模拟器均必须调用这些规则。不能只改一个 App 分支，再用另一份简化模拟宣称验证通过。

从开始时的既有配置取得合法装备、技能与权益。战中不换装，不信任客户端声称“给我加两层”或“这次应当夺盾”的结果。

### 8.2 事件建议

表现需要的事件包含：误认变化及来源、转换成立及所用阈值、名片实际拒收、回礼盾生成及剩余量、夺回盾、错位兑现、代价清算。每条关联战斗、原始施法或激活编号、具体目标、逻辑时刻与稳定序号。

名片的成立标记只有布尔值，不按命中段数累计奖励。赠盾使用原始来源编号与余额。规则更新完成后才发事件，Unity 不根据动画碰撞再触发一次奖励。

重播、重复消息、页面重复进入、进程恢复不得二次补误认、二次返盾或二次清算。临时窗口随本场战斗状态走；永久裂纹和物件状态仍走既有持久账本。

### 8.3 样板启用与版本

先以明确的隔离规则版本运行样板，开战记录所用版本与启用项。正式服务器未支持时，不能通过普通入口接受新版票据。关闭新增功能恢复旧衔接时，不撤销已经合法发出的奖励，不退回已使用的裂纹或异常代价。

本设计不改变 `MPCCombatTempo` 的样板范围。衔接样板分别在适用的当前节奏、受控快节奏夹具中观察，受控夹具不能冒充所有正式战斗已经切换节奏。

## 9. 验证与验收

### 9.1 先建立可信基线

从实施时最新 main 保存规则版本、源码提交、配装、取得状态、输入序列和模拟结果。先核对装备栏、错位消耗、终极阈值、赠盾收容和迟签到期的契约差异。现有路径不一致时单独列出，不用新增方案掩盖。

### 9.2 必须覆盖的规则检查

| 主题 | 核对内容 |
|---|---|
| 勋章 | 两层不转、三层转、到期恢复通常阈值；终极叠加取最低；消耗与原转换一致；勝利及撤退照样清算一次 |
| 名片 | 真正拒收一击才补层；无命中、零伤、闪避、毒伤、第三方均不成立；多段仅一次；换目标不换收件人；目标离场或战斗结束不转寄 |
| 银扣 | 部分盾只返剩余量；打光后不返；不复制其他来源盾；一次反客一个分支；赠盾债务清除但冷却保持；轻击资格与现有节奏一致 |
| 状态与调度 | 四层封顶、转换不自动发生、错位正确消耗；就绪亮牌与实际结果一致；真实自动调度能够执行示例 |
| 跨端与边界 | App、两类步进器及服务器复算一致；同一逻辑输入在 ×1/×2 相同；窗口到期同刻、重复事件、暂停、波次与结束边界一致 |

不额外书写会镜像实现细节的测试；每项应验证玩家能观察到的契约或跨端一致性。

### 9.3 平衡复跑

覆盖 Q8、Q12、Q18、Q22、Q26、Q30 的高、中、低操作水平；每处比较原基线、勋章衔接、名片衔接，以及各自与银扣的合法搭配。关键组同时覆盖已满足要求、缺少通缉克制、塔层装备不足的条件。

另跑合法按天取得的 Q1–Q30、塔 D01–D11 与通缉 B01–B10。夹具即使持有全部物件，也不能证明玩家按当天进度能取得该配装。

记录胜负、完成时长、最低合法装备、受到的重击、交命后的最低生命、误认来源、错位次数、失效主动次数及控制覆盖。固定输入对照用于证明规则差异；真实操作对照用于证明新增选择是否能被人完成。

**首轮停止线（候选）：**

- 基线判为不满足墙关条件的探针，不能因新增衔接直接变成通过；若翻转，须分析并重新评审。
- 同装备的合法搭配若使完成时长较基线缩短超过 20%，先暂停扩展，检查转换频率与收益来源。这是复审触发线，不是已经证明的平衡目标。
- 不能形成稳定连续控制、持续免费盾、循环加层或逃避代价。
- 若一种搭配在单体、群体、机制和保命条件中普遍压过其他搭配，说明选择不足，应改效果而非靠全局加敌人生命掩盖。

### 9.4 样板与真机

第一组观察 Q8/Q9 的两格衔接、Q12 的反客与回礼、Q22 的目标切换及校准，并用 D01 与 B01 复核快节奏兼容。真实角色是否能在相应阶段拥有该物件须分别标记；借用的隔离夹具不写成自然推进证据。

每组看 ×1 和 ×2：能否认出来源、能否看准下一张、是否遮挡重击、是否容易切错目标，以及是否明显感到错误使用的代价。没有额外操作的观察也要保留，避免只展示理想连招。

用户现场查看或主动选择录屏方式均可，不把 ReplayKit 录制成功设成体验验收的前提。截图证明状态与布局，动画需实际播放复看；静态图不能证明时机和连招流畅。

真机前后逐文件备份核对 Preferences，正式玩家数据不得被夹具覆盖。构建编号低于 170，DerivedData 与归档放外置 SSD，保留原符号链接。模拟器和播放器完成验证后按任务范围关闭，避免后台继续出声。

测试通过、构建成功和安装启动分别记为工程证据。**规则认可、真机操作认可和视觉认可分别记录；用户未看过的表现不记为合格。**

## 10. 建议开发顺序与交付

| 阶段 | 工作 | 交付与进入下一阶段的条件 |
|---|---|---|
| P0 提案与基线 | 用户评审本稿；最新 main 契约核对；列出已有说明与执行差异 | 选定范围及候选参数，基线可重现。本文只完成提案撰写 |
| P1 看清状态 | 误认、错位、回礼盾；就绪、条件、下一张三种提示 | 隔离布局与状态样板，先确认手机可读性 |
| P2 三件规则 | 勋章阈值、名片成功拒收补层、银扣剩余盾转移；共用规则与跨端契约 | 规则检查、成长与墙关对照报告；未通过不继续加物件 |
| P3 三件表现 | 三种物件身份、事件驱动、短教学和配装说明 | 真机实际操作、×1/×2 复看，用户认可后再正式启用 |
| P4 第二批 | 迟签印章先试，再逐件选择其他对戏或假面候选 | 每件单独解释收益、代价、取得阶段与验证结果 |

每个可独立评审阶段单独 PR，描述最终行为、验证证据和未验证项。只按用户认可及任务要求合并；PR 合并不自动记为真机视觉合格。交接记录写清规则版本、启用范围、手机实际构建、存档核对与尚未认可的内容。

不预估没有依据的工期；完整跨端与样板结果出来后，再排第二批。画面制作须按当时有效的法术技能规范执行，本提案没有生成任何美术稿。

## 11. 本稿建议提交认可的决定

1. 第一章采用现有状态链，第一批为勋章、名片、银扣，普通被动与独立通缉栏保持。
2. 勋章候选三层转换；名片须实际拒收目标的一击才在自然结束时补两层；银扣只夺回剩余赠盾。
3. 不加入名片延长错位、荒谬兑现后保留错位、假面免费挡伤、满堂彩资源或批量沉睡遗落物。
4. 对戏先用于说明已有衔接；额外配对加成在第二批逐件评审。
5. 源码与说明中错位、终极阈值的差异先核对，既有契约修复与新增衔接分开评审。

上述是作者推荐的完整方案，**尚未获得用户批准实施**。用户认可提案后，后续仍须按规则、操作与视觉三个层面验证。
