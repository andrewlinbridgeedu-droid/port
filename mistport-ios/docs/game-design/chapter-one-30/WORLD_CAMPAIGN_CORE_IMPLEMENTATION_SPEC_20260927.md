# 世界战役下一版：核心战、需求测量与接入规格

第二轮更新：[四层突破与接入缺口](WORLD_CAMPAIGN_CORE_RACE_SPEC_20260927.md)是当前聚合规则入口。新增候选要求四个不同账号成功才改变NPC生死；本文旧的一胜死亡与第一版Boss节奏保留作历史规格，不能与第二轮机制混用。需求/遥测与分账要求继续有效；原72项仅为待执行计划。

## 接入边界

保留现有主线、塔、通缉、奖励与普通封印物。新原型应提供独立测试入口，默认 `worldCampaignEnabled=false`，不读取或覆盖正式玩家 Preferences。Swift 处理机制、物品和结果；Unity 后续只读取预警、目标和阶段状态。工程完成、程序胜率与真人视觉/操作认可分别验收。

当前 `WorldCampaignPrototype` 已有投资、采购、外围开路、挑战票据、单事件唯一死亡和余款结算；它**没有**完整 NEWS/PREP/OUTER/CORE 时间机、跨战役永久死亡账、正式 NPC/后第一章桥接、真人遥测、这两场核心战或共享权威服务。新实现不能把这些缺口隐去。

## 两场核心战：补齐可编码规则

共同约束：180 秒截止；核心死亡即胜，玩家死亡即败；同一时间戳用固定规则处理，不依赖渲染帧。攻击/药品/死亡事件先写逻辑序号；截止时接受 `impactAt < deadline` 的命中，等于截止的未结命中不再发生。核心击杀后清除其周期任务与未生效持续伤害，停止结算，护卫存活不阻止胜利。不得通过夹具强制胜利来填新战斗数据。

生命、攻击、普通攻击间隔先依据真实合法塔30/100配装测量再选初值；**本文件不填一组未经运行的生命/攻击并声称难度成立**。机制计时是明确的候选，正式 HP/攻击仍是实施时须记录的版本配置。

### A：护卫阵列与有限雾压

内部 ID `campaign_core_guard_v1`，核心 1、护卫 2、支援 1。均是新事件实体 ID，允许复用表现资源，不复用主线角色身份。

- 核心减伤：2 个护卫存活时 60%，1 个存活时 25%，全灭为 0。此分档是对 Pro“任意护卫存活均固定减伤”的修订：让“只杀一个后压核心”有明确收益。减伤在统一伤害入口应用一次，覆盖技能、普攻和遗落物；延迟伤害不得在排队与落地重复减伤。
- t=20、40、60…开始 4 秒预警。支援仍活着才有强化雾压，预警明确显示来源单位和完成时间。
- 预警结束前击杀支援，取消本次及之后的强化雾压；支援不复活。不是拥有指定封印物才能打断。
- 强化完成：以预警完成时正常最大生命为基数，8 秒分 8 次结算，原始总伤害最多 24%，整数分配不得超额。按现有持续伤害防护规则处理，不绕过已生效的遗落物能力；生命基数与总额记录在事件内。
- 每次预警结束后核心停普通攻击 6 秒，已挂的持续伤害仍按时间结算。恢复窗不是完全无敌或免伤窗。支援已死时仍有清晰的核心恢复节奏，不能借取消强化把所有进攻窗口也取消。
- 同一来源不叠加第二条雾压；不永久挂环境伤害。预警期和恢复期核心不另外提交普通重击，护卫自身攻击继续。

路线一：清两护卫、清支援、压核心；路线二：清一个护卫，择机处理支援，承受剩余护卫压力压核心。第二条是候选而非“已证实更快”；报告每条的失误后果、时长和药耗。如果最后只剩一种合理顺序，机制验收不通过。

### B：支援恢复与目标切换

内部 ID `campaign_core_relay_v1`，核心 1、普通支援 2。

- t=18、36、54…开启 5 秒恢复通道。每个存活支援独立通道、可通过击杀终止。
- 本轮候选明确为**每个完整通道恢复核心最大生命 6%，同一窗口上限 12%**。Pro“任一个完成则恢复12%”可能被实现成12%或24%，此处消除歧义，且让击杀一个支援也有收益。核心已死不回血、满血不产生虚假有效治疗。
- 生命首次从大于50%跨到不高于50%，只触发一次 8 秒过载恢复窗，核心暂停普通攻击。此前已经死掉的一个支援位置在窗末换入新单位，最多补位一次。进入该阶段时无空位则本场不补位；不排队生成第三个支援。
- 补位拥有全新实例 ID，旧单位死亡记录不修改；新单位从下一次18秒窗口起可参加恢复，不继承死者尚未完成的通道。回血把核心抬过50%也不能重触发阶段。
- 时限不能靠无限回血延长；实际有效治疗、溢出量、通道完成/被中止及补位分别记录。

路线一：先清支援再打核心；路线二：清一个支援、利用空档压核心，并应对一次补位。先看技能组合和目标切换是否能形成取舍，再调攻击/HP；不靠必须喝三药倒推伤害。

## 实验设计与遥测

待执行计划：[72项 JSON](../../../../docs/development/world-campaign-prototype-20260927/pro-final-review/core-probe-plan.json)。两场 × 塔30/100 × clean/中位假设/高压假设 × 无物品/3药/3药加普通品 × 2 seed。普通品预先选定：A 盐封呼吸袋，B 回礼扣；这是战术假设，不能跑完后只保留获胜装备。不使用主动勋章，以免混入第四个变量。

每个 `operator + seed` 预生成按固定逻辑时间索引的错误序列，所有携药、配装对照共用；不得因为有没有药、血量或即将失败临时抽更多错误。延迟作用于可执行决策，关键窗口错过单列；同一次错误不重复计成延迟与另一次“人为错过”。候选中位延迟0.35–0.80秒、次优目标10%、关键窗迟到10%、技能顺序偏离8%；高压为0.60–1.20秒、20%/20%/15%。这些是模型标签，**不是测到的真人分布**。

72次先检查机制有没有触发、错误模型是否改变决策、物品是否提高生存余地。如某配置需要估计模型胜率，可再增加预先固定的 seed，但机器人仍不能替代真人。35%–55%无药、55%–75%有准备仅为设计愿景；不能用每格2次验收。

遥测分三层：

|记录|必要字段|
|---|---|
|attempt|schemaVersion、匿名测试玩家ID、attemptID、scenarioVersion、输入来源bot/human、encounterID、gearBand、合法loadout、首次/重复尝试、开始/结束、结果、结束原因、有效时长|
|combat events|逻辑序号/时间、targetSwitch、skillID、预警出现/完成、机制处理、真实受伤/护盾抵扣/治疗、药品使用前后库存、核心有效回血、支援补位、死亡来源|
|economy follow-up|实际药品来源与购价、普通品实际磨损、修理时间/铜、选择暂不修或更换、交易/维护回执ID|

不得把“每场自动修满”的测试成本记为真人维修行为；未消费库存不算药耗。不在战斗引擎按免费/月卡状态改难度。对真人数据按玩家聚类，区分首尝和学习后的复尝；先校准错误模型，再定正式难度。

## 需求价值：使用相同统计口径

单次尝试直接现金差可用 `Δ现金 = 成本0 − 成本1 + (p1−p0) × 成功铜奖`，其中成本已含真实药费、修理和本次其它费用；如果求“尚未定价的物品愿付上限”，先剔除该物品自身成本，否则重复扣价。失败后的下一场成本不再重复记到本次失败里。

重复到首次成功、每次独立、无截止且策略不变的简化模型为 `成本/成功 = E[每次成本]/p`，`时间/成功 = E[每次时长]/p`。这不是当前战役的事实：真实窗口、票据上限、学习和退出必须纳入截尾结果。应同时报告成功率、平均总尝试次数、含失败时间和现金成本，不能只筛胜者比较时长。

本地算例：45%胜率、4铜/90秒一尝试，对比65%、7铜/80秒；有准备每次成功预期**多花1.88铜但节省76.92秒**。这说明“更容易过”不等于“现金上赚钱”，节省时间与改变世界的价值由真实选择/成交验证，不乘 Q30 铜/分钟冒充市场价格。

维修材料替代旧铜修会减少旧铜销毁；即使材料市价10铜，销毁材料也不是销毁10铜。新高阶主动耗材应逐件定义次数、失败处理与替代路线，旧普通品继续按现有规则运行。

## 战役与新闻的最小工程增量

候选流程 `NEWS → PREP → OUTER → CORE → SETTLEMENT → REORGANIZATION`，经济周期与现实时间映射须配置，不能直接把“7周期”写成7现实天。

|阶段|入口/行为|完成/失败|
|---|---|---|
|NEWS|默认3周期，公开争端、两方目标与准备需求；先要求后第一章桥接完成|桥接剧情与新人物未核定时正式入口关闭|
|PREP|默认7周期；免费加入，投资转项目账后本事件绑定；中立工匠可卖给双方|候选每账号本金≤项目目标10%，分笔合并计；不卖票据或投钱换伤害|
|OUTER|默认3周期；现有普通单人遭遇＋工程物料；每账号本阶段最多3胜计全服进度|达到本方物料/贡献阈值才开放核心；未达标有公开失败分支|
|CORE|签发账号/阵营/遭遇版本/截止绑定的本次票据，运行新核心战|发票、截止、宽限分开；重复/迟到胜利只记合法个人记录|
|SETTLEMENT|等所有已签票的公开宽限结束再决定|A单胜/B单胜/双死无人独占/无突破；现金、工程物资、人物记录原子落账|
|REORGANIZATION|败方候选14周期重组，创建不同继任ID|保留死者永久回执，基础服务不断，下一轮不能复活同一人|

永久 `npcDeathReceipt` 的键必须包含稳定人物实体 ID，跨战役检查；不能仅用 `campaignID` 幂等宣称永久。权威回执要验证合法战斗输入或可信重演，不能信任客户端胜利布尔值。现有单宿主结构体也不等于网络事务。

工程物资先转项目库存，开路时真实扣减。票据数量与贡献资格独立配置，未定前不承诺正式全服胜率。若每位挑战者胜率50%，10个独立挑战者至少一人获胜概率已达99.90%；因此 Pro 的“单人55%–75%”和“全战役50%–70%”不能混用。全战役还需计参与人数、有限票据、相关错误和双方死亡，不能用一个单人概率当全服难度。

首版8个作者新闻 fact 类别：争端、目标、需求、准备摘要、外围开启、核心开放、人物结果、经营/继任结果。每条由已提交事实＋版本＋幂等键生成；准备摘要按里程碑合并，投资每一笔不推一条骚扰通知。原24篇剧本作为扩展，首版先完成8类触发和正文。

项目最低账：`cash / inventory / stake / operatingRight / committedCosts / reserve`。投资和退本金是转移；实际营业收入未接入时 `dividendSettlement=disabled`。未来分配候选为 `max(0, cash−reserve−已承诺成本)` 的50%，其余留项目；结算批次幂等、舍入余款留账。投资收益权转让、贷款和证券不纳入这版。

## 公共采购政策：保留研究，不自动铸币

Pro候选年度最多12,000铜、单品200件，按 `clamp(active14/1000, .25, 1)` 缩放。使用**滚动365经济周期**同时检查铜/数量额度，避免跨年连发双份；active14暂定义14周期平均日活并记录计算口径，不能用14日独立账号数替代。

必须已有真实公共需求、项目缺库存、市场有可售货、原财政不足；商品无用途或私人买家缺钱都不触发托市。`publicConsumptionCounter>0` 对新建项目会形成“先消费才能采购”的死锁：第一笔依据作者定义的、有期限和数量的公共消费任务核准；后续依据实际消费回执续批。执行采购后超过两次公开消费期限仍零消耗则冻结剩余额度，已买物资留库存，不凭空抹掉。购买与实际使用分开发回执。

Pro的sell-through≥70%暂停条件只作辅助诊断：市场销量恢复不等于医院已经有药，不应单独取消已承诺的公共救治合同。主要停止条件是公共需求已满、达到14周期合理储备、额度用完或消耗项目失效。缺货、玩家缺钱、商品无用分别处理，不用同一个采购按钮解决。

`MINT_PLAYER_REWARD` 与 `MINT_PUBLIC_PROCUREMENT` 单独报表；采购转账不重复记发行，物资消费不虚记铜销毁。未获规则定案前仅模型测试，不改既有 Q30 奖励。

## 实施与验收顺序

1. 新增两场隔离核心战及事件化预警接口；先验证减伤只算一次、Dot封顶/截止、恢复窗口、核心死即胜、支援补位一次和有效回血。旧遭遇回归结果应保持。
2. 执行预登记72次，保留每次配置、错误序列、动作和伤害轨迹。这里不设自动“调到目标胜率”的循环；发现全胜或全败照实记录并解释。
3. 隔离试玩入口接真实输入遥测；记录药品与封印物的容错、时间和重试价值，至少验证两条无稀有物品路线。真人测试数量按条件覆盖与区间收敛决定。
4. 补最小战役时间机、永久人物账、8类新闻与项目账户。试验覆盖冷服、70:30、双死、零突破、截止/宽限、重复提交和换届。
5. 用真实需求参数替换模型假设，再研究动态生产/成交、投资经营与高阶启动耗材；固定价格物量守恒不等于经济稳定。

本轮交付的是回复存档、144对数据复核、数学修正、72项待执行清单和此开发规格；**两场核心战、真人遥测接入与完整战役阶段机尚未交付**。
