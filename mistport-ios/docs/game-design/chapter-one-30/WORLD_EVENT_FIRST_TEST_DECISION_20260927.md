# 世界事件首测定案与验证边界

2026-09-27。用户要求继续验证、做小应用，并明确“不需要自己调参；做到接近完善，后期有方法补救”。因此本页把规则收敛为**首轮接入稿**，数值有版本、有观察指标、有修正办法；不是宣布整体共享经济已经稳定。

完整故事继续以[《谁让雾港重新亮灯》](WORLD_EVENT_LIGHTS_CASE_20260927.md)为准；本页更新首测参数和开机条件。新[推演室](../../../../tools/world-event-lab/README.md)默认显示结论，详细参数折叠。它是设计工具，不是新增攻防玩法，也不接正式存档。

## 1. 首轮不再反复讨论的结构

- 玩家先见城市危机和两种发展路线，选择投资、生产、公共行动或高难突破；不需要投资才能参加。
- 投资/正式战斗锁定当期利益阵营；中立卖货不自动站队。金钱不购买贡献倍率、核心资格或人物击杀。
- 工程钱物都必须落实；普通与困难行动各有实际作用。无人击杀核心时，合格公共领先者仍取得合同。
- 三节点之后才进入关键人物决战；四名不同账号的四次成功，不是重复杀同一NPC。同轮双方同时结算，永久死亡、继任和合同结果分别记账。
- 交易是已有铜转移；安装/服用/加工才产生实物消耗。NPC不是无限回购口，不因库存积压凭空发行货款。
- 经营只对已履约真实收入分配；赢了合同仍可能亏本金。故事后果与货币稳定分开验收。

## 2. 本轮首测参数

|项目|首测取值|使用边界|
|---|---|---|
|时间|准备7日、公共48小时、核心24小时、经营30日|按服务端时间，玩法试玩后可改下一版；不是未经定义的经济周期|
|公共贡献|普通1点、高难2点；每账号一次有效世界尝试|演练隔离；网络故障回执另行核验，不允许反复失败重抽|
|普通目标|准备合格的普通玩家以约85%成功为设计目标|这是目标与模拟输入，不是引擎已测85%；与旧65%假设分别对照|
|困难目标|比普通更依赖操作与配装，成功2点|研究中用45%与准备充分80%作敏感性，不把概率直接写进战斗结算|
|工程资格|本方12套组具验收＋至少4名成功账号|人少不能用多交钱代替账号；没有资格就不能取得合同|
|核心机会|领先6/落后4，同分5/5，受候选人数限制|账号一次；缺席处理后仍无人则空席占次；模型到场率60/85/100%|
|核心难度|节点与人物战分别测量|模型50%基准、准备少数派75%节点/70%人物战，均是假设|
|筹资|单项目最多1200铜，单账号最多120铜|无杠杆、无保本，不证明账号一定不同真人；正式服仍需身份及关联风控|
|组具报价|首测60铜/套，即单方最多720铜工程采购|取代旧40铜算例作为新首测候选；可按布12、绑带9、罐9铜各2件核算，非无限商店定价|
|生产收益检验|成本34铜、主动时间6分钟的假设下，26铜/套、4.33铜/分钟|成本须含材料机会成本；取得材料和制作的时间口径必须一致，不能把此算例当实际配方利润|
|经营|服务4铜/单，日上限50单，每营业日1套维护组具＋60铜外部燃料|客户必须实际付款并有原料；两种服务各自实际需求尚待内容接入|
|分配|已履约经营现金净额的50%|先保退款、已承诺采购及运营资金，不动剩余投资本金；不把建设损失藏掉|

为什么上调组具首测报价：旧40铜在成本34、6分钟假设下只有1铜/分钟，缺乏生产吸引力。60铜给出可测的起点，同时把采购预算牢牢限制在真实工程量内。它不保证买方愿意支付；真实成本或需求不支持时，改配方产出批量/用途/报价，不能无限系统接盘。

## 3. 新增开机检查：先有确认订单，再付调试费

旧方案获合同即支付120铜调试费，即使没人买服务也会损失。首测改为：

1. 先完成工程与世界结算，得到的是经营资格，不自动启动设施。
2. 检查未来最多7日**已付款、原料落实、资金已托管**的订单；意向、预估日活和访问量不能替代。
3. 按每日容量排程，计算这些已确认订单的经营净额；至少能覆盖120铜调试才启动。
4. 每批真实收入不足该批成本则不开机；前置资金不足也不开机，不自动贷款。
5. 30日合同不会因等待客户无限延长；未启动也按实际剩余钱物清算，不承诺本金全退。

推演中7日订单是显式假设；模型守恒已验证，但托管、排程、取消和履约接口尚未进入游戏。生产环境必须先保客户退款与已承诺支出，不能先分预售款再补成本。不可交付的订单原路退回托管款；故障责任由项目真实储备承担，没有储备不得追加不可撤销订单。

在60铜组具候选下：建设720，调试120；无客户则不付调试，退480，损失720。满负荷且有真实6000铜客户钱包时，30日1500单收入6000，维护1800、燃料1800，经营净额2400，最终投资净收益1560。此为有客户的上界情景，不是承诺130%月收益。每日35单即使通过开机检查，整个合同也可能亏损：检查只避免没有订单就继续投入，不保证回本。

## 4. 计算证据与可接受结论

见[复算报告](../../../../docs/development/world-event-lab-20260927/REPORT.md)与原始JSON。覆盖阵营比例50:50/70:30/90:10，20/100/400人、不同普通成功率、少数派准备、缺料和缺席；项目覆盖无客户、有限钱包、原料瓶颈与开机检查；货币比较180/365/730日及两种上线人群。

**可进入首测的结论：**公共成果决定合同能消除“没人击杀就什么都没改变”的结构问题；人数和组织有真实优势，少数派有准备翻盘路径；有限采购与逐笔项目账能明确表达盈亏，无需无限回购。

**不能据此接受的结论：**真人觉得好玩、药品已经刚需、配方利润已经合理、免费玩家已经负担得起、共享铜币已无通胀。独立胜率、客户数和成本没有来自玩家遥测，不能把模型输入当成验证结果。

## 5. 货币处理定案：先保留产品边界，不靠高额强制损耗填坑

基准下三种Q30规则都存在经常性净投放。旧“日活发行/7”仅适用于每日同一批领取者等特定行为；若每天独立上线，7日内领取账号更多。两种情形都应观察。

本轮接入以本地/隔离工艺、有限项目账、真实订单和事件体验为范围。**共享自由市场、银行放贷、无限重复现金与跨服余额导入不能借此直接开放。** 不修改正式Q30奖励，也不追扣旧铜或月卡已承诺权益。

下一阶段的共享服候选应使用“公开现金预算＋预先签发现金权益＋材料可重复”结构：预算来自已核对真销毁及明确有限的启动储备；预留已承诺基础/月卡权益后才能签新的重复现金票据。先显示奖励、保留预算再让玩家开战，不能打赢后因预算不足拒付。若基础承诺本身超过回收，直接标红并暂停开放更多经济入口；不能把NPC可再花费的销售款当销毁。此结构尚未实现或获得长期验证，只是明确下一步，不把14日一次当已足够。

## 6. 补救办法必须事前写进规则

|监测项|首测观察窗/触发候选|当期处理|下一版调整|
|---|---|---|---|
|钱物不守恒、同票据重复付款|任何一笔异常即触发|隔离异常结算与新采购，保留回执、玩家合法债权及存档|查重放/并发/账户归类，再恢复；不对全体玩家回滚扣钱|
|订单不足|不满足开机条件，或单批收入低于成本|不调试或暂停该批；按规则退款|调整实际服务用途与配方，不发虚构利润|
|工程货卖不掉|采购资金/数量耗尽立即停止新单|已承诺有预算订单照约处理；剩余货仍归卖家|按已验收消耗设下次批量，不无限回购|
|普通入口过难|至少100场合格真人尝试，成功率仍低于70%|不临时追缴药品；允许隔离演练|检查提示/操作，再改下一事件难度；不能仅按抽样噪声热改|
|同等条件长时间单边占优异常|分人数、装备、操作与准备分组记录至少3场事件|保留既发资格与票据；不暗补少数派伤害|查关联账号和名额算法，按新版本修正|
|无人或单方未合格|到公开截止仍不满足条件|按资格、公共成果或临时接管结算；退实际余额|调整招募/准备期与工程需求，不能凭空补成功者|
|经常性货币新增过大|滚动28日分账户/来源核账，至少两窗口观察|共享经济入口保持关闭，停止扩大未承诺发行试验|调整未来预算与非现金产出；不突然暴涨维修费或没收存量|

以上阈值是首测运维候选，非现成自动开关。每个事件创建时冻结 `rulesetVersion`、预算、期限、数量及退出规则；活动内不静默改合同。安全性漏洞可以暂停，但恢复/补偿必须有范围和回执。

## 7. 工程接入与下一次验收

**2026-09-28接入范围更新：**正式游戏尚未制作第二章仪式后的转运站入口。本轮先沿用Q16工坊门槛落地一条本地检修教学单，连接真实塔战、背包、铜币和持久化回执；不使用11套工程/其他账号贡献夹具，不记世界判胜。详见[接入记录](../../../../docs/development/local-workshop-integration-20260928/README.md)。本地单的18铜一次性启动预算须单独列入未来共享货币模型，不能冒称财政已闭合。

**隔离试玩进展：**新增[工坊闭环](../../../../docs/development/workshop-playtest-20260927/README.md)，在现有macOS演练工具中串起立场新闻、真实F1战斗、候选材料领取、皮革批次制作、有限交货、安装、公共行动与简化合同结果。最终试玩v0.3.3已构建签名。此前21项测试及288场对照为规则证据；本次经用户授权使用原生界面操作，另走通普通胜利、高难胜利、用药撤退，并修复操作问题。现在可开始一条本地工艺/有限项目/普通公共行动的接入开发，尚未完成实际存档、iPhone与完整战役验收。详细状态以该记录为准；第二章资格、其他账号成果和此前工程为显式夹具，不视为正式游戏、多人与完整剧情接入。

1. 先把8篇新闻、两派计划、工程需求和结果页串到现有内容入口；本轮小应用不替代这个步骤。
2. 接通一条真实工艺订单：合法塔材/配方/熟练度/角色等级→制作→有预算交货→安装→钱物回执。保留裁缝、皮革、金属、药剂的原有方向，不增加强制打工工资。
3. 迁入新公共贡献、分层核心、同轮死亡和合同结算。真实权威服必须验证身份、时间与战斗回执；本地概率模型不是防作弊实现。
4. 落地原料、客户、托管、履约与停工后再开经营分配，记录不同玩家实际需求。
5. 真人试测后更新概率/耗时/需求输入，重跑本工具；共享货币继续单独过验收。

当前完成：设计推演小应用、模拟、守恒与边界检查、首测稿及补救规格；9月28日增加第一条本地工坊的正式Swift接入，验证以接入记录为准。未完成：完整世界事件接入、Unity真机闭环、真人需求及高难体验验收、全服个人财富与物价模型、银行和共享经济上线。
