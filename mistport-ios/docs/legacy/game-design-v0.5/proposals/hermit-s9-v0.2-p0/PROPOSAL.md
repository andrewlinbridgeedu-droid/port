## 一、本轮修复结果，以及哪些结论仍然不能下

| 问题             | 本轮处理                               | 当前可声称的结果                                |
| -------------- | ---------------------------------- | --------------------------------------- |
| 被动取证缺少全局上限     | 增加每名玩家、每场战斗共享的滚动窗口门控，同时保留单敌间隔      | 三名误认敌人同刻攻击，基础取证从 **1、1、1** 改为 **1、1、0** |
| 调度要求四张卡        | 支持1—4张不同技能，以及中间留空的物理槽位             | 单卡、双卡、三卡、四卡和空槽调度测试通过                    |
| 十八天赋没有参与模拟     | 新增预算、加减点、前置、级联退点等状态参考模块；没有假装补齐战斗监听 | **天赋状态可测试，构筑强度仍未验证**                    |
| 固定0.2秒与Unity不同 | 明确降级为旧回归样例的合成时序；调度器允许注入不同技能时序      | 不能将这些时间直接写进客户端伤害结算                      |
| 假面重设计未同步教学     | 保留为独立实验规则，不作为已确认正式能力               | 耐久相关天赋、遗落物和教学仍待同一轮决策                    |
| 高价值错配有无效装备     | 历史案例保留，但显式标记失效物品；未实现且可能生效的遗落物直接报错  | 不能再静默模拟后拿结果证明稀有度平衡                      |

**实际执行的检查：**新增53项自动化测试通过，原有17项定向检查通过；另检查了46,656个单系配点向量、10,000个取证事件及3,000次加减点操作。它们都是Python参考模块测试，不是Unity客户端验收。[查看逐项测试记录](sandbox:/mnt/data/fogharbor_s9_v0_2/results/new_tests.txt)

六场旧基线及原有两种敏感性变化已经重跑，核心结果没有变化。这个结果说明：**旧样例没有覆盖三名误认敌人同刻取证的缺陷路径，并不说明缺陷无关紧要。**

### 取证上限还需要统一这一层口径

补丁限制的是：

> **误认敌人的原生攻击实际命中后，触发基础取证的次数。每个滚动1秒内，全局最多两次。**

不是按自然秒清零。例如0.99秒已成功两次，1.00秒不能因为跨过整数秒而再成功两次。

本次补丁明确采用以下规则：

| 情况             | 处理                       |
| -------------- | ------------------------ |
| 同一命中的动画、碰撞重复回调 | 使用同一个命中身份去重              |
| 第三个合格命中被全局上限拒绝 | 立即拒绝，不排队补发               |
| 台账已满，基础证据无法入账  | 不消耗成功取证额度，也不启动该敌人的成功取证间隔 |
| N、E、I直接给证据     | 不占“敌方行为取证”的额度            |
| R05等遗物给予额外份数   | 单独记录来源，不冒充额外一次基础取证       |

因此，带R05时，两次合法基础触发可能产生两份基础证据和两份遗物奖励。**“最多两次基础取证”不等于“所有来源合计最多两份证据”。** 这一点需要同步写进正文和日志，否则下一轮仍会出现“代码正确，但双方理解不同”的问题。

## 二、P0先做天赋树，不同时改战斗

建议把P0限定为一个可以独立验收的闭环：

**读取状态 → 编辑草稿 → 校验前置与预算 → 预览级联 → 应用存档 → 重新读取一致。**

### 2.1 预算与五级数据

| 项目    | P0明确规则                         |
| ----- | ------------------------------ |
| 节点    | 三系各6个，每节点整数0—5级                |
| 总预算   | 三系已投点数 ≤ 当前已获得点数 ≤ 30          |
| 已获得点数 | 来自任务／成长里程碑，不从旧存档“已投＋剩余”反推      |
| 剩余点数  | 始终由“已获得－已投入”计算，不单独维护另一份容易失步的余额 |
| 节点标识  | 使用稳定ID；显示名称、树上位置改变不应导致存档找不到节点  |
| 五级效果  | 同一份数据驱动当前效果、下一级效果和后续战斗参数       |
| 剧情条件  | 与点数前置分开；有点数不代表可以提前获得未解锁能力      |

例如角色当前只获得14点、投入11点，界面应该显示：

> **已用11／已得14，剩余3；本序列上限30。**

不能把“上限30”误显示成当前还有19点可用。

五级显示还要检查两个常见边界：**0级不错误读取最后一级效果，5级不尝试读取不存在的第六级。**

### 2.2 加点、减点都先改草稿

角色页保留“已提交状态”和“编辑草稿”两份数据。加点、减点、重置只修改草稿；点击应用后提交。战斗开始读取已提交快照，不读取尚未确认的草稿。

减点流程应当是：

**模拟减1点 → 重建全树可达状态 → 计算需要级联退还的等级 → 显示确认 → 一次性更新草稿。**

这里的“全树”不是只检查当前节点连线下方。

### 2.3 跨支路门槛：必须有这项测试

假设诡术为：

`T1—T6 = [5, 1, 4, 0, 5, 0]`

T5依赖T3，且T5以外正好投入10点，因此合法。

现在把 **T2从1减到0**：

* T3仍满足前置，可以保留4级。
* T5以外只剩9点，低于10点门槛。
* 虽然T2不是T5连线上的前置，**T5仍必须退回5点**。

确认框应该显示：

> T2退还1点；T5退还5点；合计退还6点。
> T3保留4级，其他系不变。

这一案例已经加入参考模块测试。另一个测试覆盖多层连锁失效，避免只退一次下游就停止校验。

**过期确认框也要拒绝。** 玩家打开退点预览后，又通过其他操作改变了草稿，旧预览不能直接覆盖新状态；需要重新计算。

## 三、存档迁移：先保住进度，再谈保留配点

真实旧存档字段尚未提供，所以本轮交付的是**迁移规则与规范化测试格式**，不是“现有存档已经迁移成功”。

建议采用以下处理：

| 旧数据情况             | 处理方式                      |
| ----------------- | ------------------------- |
| 已知版本、节点映射明确、等级合法  | 保留兼容配点                    |
| 不清楚旧布尔值代表什么       | 不猜“勾选＝1级”或“勾选＝5级”         |
| 节点被删除、结构不再可达、预算超额 | 提出本序列整页退点的明确确认，不擅自替玩家重新分配 |
| 旧存档显示异常多的已投／剩余点数  | 按可靠成长进度恢复预算，不把异常值兑换成更多点   |
| 读到比当前客户端更新的存档版本   | 禁止降级覆盖，不自动清空              |
| 迁移再次运行            | 不重复发点、不重复累计退款             |

生产流程应为：

**备份原始存档 → 识别版本与映射 → 校验成长预算 → 生成候选与报告 → 写临时文件 → 读回校验 → 原子替换。**

任何一步失败，保留原文件。即使需要重置，也只处理该序列天赋页，不能连技能、物品、剧情或其他序列一起清掉。

参考模块已测试兼容映射、非法配点处理、原数据不被修改及迁移幂等性。**真实磁盘中断、云存档冲突、回滚和旧客户端样本仍需单独验收。**

## 四、安全区布局：树滚动，主要操作不滚走

P0页面结构建议固定为：

| 区域      | 内容与行为               |
| ------- | ------------------- |
| 顶部固定区   | 序列切换、三系切换、已用／已得／剩余  |
| 中部独立滚动区 | 两列三层节点、前置连线、0/5—5/5 |
| 底部固定详情区 | 当前效果、下一级效果、具体缺少的条件  |
| 底部固定操作区 | 减点、加点、应用、重置         |
| 次级关联区   | 技能／遗落物关联，可折叠或独立打开   |

顶部和底部放在同一个安全区容器内，避免父容器已经扣了底部安全距离，子容器又重复扣一次。

小屏或大字号导致空间不足时，优先折叠关联内容，必要时把长说明放进独立详情层。**不能靠缩小主要按钮或让整页滚动，把“应用”藏到系统手势区域。**

节点状态也应细分：剧情未开放、结构条件不足、预算不足、可投入、已投入、满级。不要把前三种都画成一把锁，却不给原因。

还有一个开发期必须区分的状态：

> **“战斗效果未接入”不是“剧情未解锁”。**

未接入节点可以在开发预览中加减点测试，但不能在正式入口让玩家以为加点已经影响战斗。

## 五、Unity命中同步与假面变更，分别验收

### 5.1 不能把0.2秒换成另一个固定数就算修复

应该区分四类事件：

**施法被接受、发射／幻影形成、实际命中、动作结束。**

近战在命中标记确认时结算；弹道在抵达或碰撞确认时结算；幻影在形成事件后可承伤，在实际命中时扣次数。动作结束可以早于弹道命中，不能强行等同。

生命、护盾、假面次数、飘字和受击反馈应使用**同一份命中结算结果**，而不是各自启动延迟计时器。

去重要同时考虑两个尺度：

| 尺度             | 用途                          |
| -------------- | --------------------------- |
| 施法ID＋命中段数＋逻辑目标 | 防止同一命中的动画与碰撞回调重复扣血          |
| 施法ID           | 限制“每次施法最多一次”的天赋，避免双目标变成两次触发 |

没有命中绑定时，应报错并终止该次待结算事件，不能偷偷回退为“0.2秒后扣血”。

本轮补丁保留原合成时序，只用于确认调度修复没有改坏旧样例。**真正重跑构筑之前，必须接入实际时序配置或实际事件回放。**

### 5.2 假面仍然属于待确认的重设计

现有“两次承接”和实验“部分承伤＋耐久”应分开规则版本。本轮不将实验版默认写入教学、技能说明或现有存档。

采用实验版之前，需要同批完成：

**技能说明、次数与耐久显示、不同破碎原因、角色残余伤害、400火球教学、纸人与主动幻影的区别。**

P2、P6以及R02、R06、R14等依赖耐久的提案机制，也要跟随这项决策。**不能先接入这些效果，再假定玩家已经接受假面重设计。**

## 六、下一轮构筑对照：不再用缺配套技能替代竞争力验证

原错配战例可以保留为教学演示，但下一轮应分开两种实验。

### 第一层：控制变量，比较物品取舍

同属性、同30点天赋、同技能顺序、两个相同遗落物，只替换最后一件。

| 比较              | 双方必要配套    | 成对场景         | 要观察的差异        |
| --------------- | --------- | ------------ | ------------- |
| R02补缝针／R06无客面具  | 都装备M      | 快速三连击／慢速重击   | 刷新频率与耐久额度的取舍  |
| R05旧邮戳／R18禁售校样  | 都有稳定取证和封卷 | 短命换目标／长时间单目标 | 首份入账速度与后续复印价值 |
| R04缺角铠钉／R10单面镜片 | 都装备F、R    | 护甲覆盖／标记断档    | 延长破甲与无条件追击的取舍 |

**这些是下一轮测试设计，本轮尚未运行。** 当前子模型对尚未实现的活跃遗落物会直接报错，不能拿无效结果填表。

### 第二层：双方分别优化构筑

基础物品池与更广的高价值物品池分别寻找合理搭配。高价值组允许保留普通物品，不能强迫它穿满稀有度。

这里的公平目标不是“让高价值组也输”。当更广的候选池包含普通物品时，增加选择本身不应让最优结果变差。应当检查的是：

> **普通物品是否在特定问题上仍有明确用途，甚至被拥有更多选择的构筑主动保留。**

还要区分两种情况：纸人没有触发，可能只是本场不需要容错；没有装备M的R06，则是结构上根本不可能生效。两者不能都记作“无效槽位”。

属性优势压力测试应放在同属性对照之后，单独列报，不能代替它。
