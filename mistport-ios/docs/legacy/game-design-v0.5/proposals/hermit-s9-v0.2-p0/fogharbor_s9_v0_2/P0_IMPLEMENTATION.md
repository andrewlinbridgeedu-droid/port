# 隐者序列9：P0落地任务书与后续验收

## 0. 本轮范围

先完成五级天赋树、手机安全区、30点预算、草稿编辑、前置门槛、级联退点、存档迁移入口。
三系战斗资源、假面重设计、完整构筑优劣、首领和经济不是P0交付前提。
但未接入战斗的节点不能在正式版伪装成已经生效。本轮天赋界面可在开发预览入口验收；正式开放要受战斗覆盖状态约束。

本包仅提供规则参考模块及测试，未修改Unity工程。实际旧存档结构和动画时序未提供。

## 1. 点数及数据模型

天赋定义与玩家状态分开，节点用稳定ID，不用显示名、数组位置或UI层级路径当存档键。
推荐命名空间：hermit / sequence9 / T1，后续更名不改变ID。
节点定义包含：tree、位置、maxRank=5、每级效果数组、前置节点及等级、本系其他投入门槛、剧情条件、战斗接入状态。
同一份五级效果数据驱动“当前效果”“下一级效果”和之后的战斗运行参数，避免UI写26%、战斗仍使用22%。

玩家状态按序列存储nodes/rankMap、saveSchemaVersion、talentRulesVersion、saveRevision。
已得点数由已完成里程碑的权威进度决定。单机可使用经校验的任务进度，联网使用服务端进度。
不能通过旧存档的“已投＋剩余”自行制造已得点数；也不能因为上限30就给新玩家直接补到30。

三系总投入 ≤ 当前已得点数 ≤ 30；每节点整数0至5。本系30只是容量，不是额外预算。
例如玩家已得14点、已投11点，显示“已用11 / 已得14，上限30，剩余3”。

解锁关系保持原案：两个根无结构门槛；中层需对应根1级及本系其他可达投入5点；下层需对应中层1级及本系其他可达投入10点。
“其他投入”不含当前节点自己，也不含从零无法达到的下游点。剧情解锁和结构可达性分开校验。

## 2. 草稿、应用与加减点

角色页维护committed与draft两份状态。加点、减点和重置只改draft，应用后才提交。离开未应用页面提示应用／放弃／返回。
每次草稿变化增加draftRevision；每次持久化增加saveRevision。过期的退点确认框和过期存档写入应拒绝，不覆盖新状态。
战斗开始读取已提交快照；不把未应用草稿带入战斗，战斗内不允许重新配点改变本次快照。

加点事务：复制草稿 → 检查等级、预算、剧情与可达性 → 更新草稿 → 重绘；失败不扣点。
减点事务：先模拟指定节点减1，再从零重建最大可达保留集合；反复退还不可达等级，直到稳定。不是只删除连线上的子节点。

### 跨支路门槛案例

诡术原分配T=[5,1,4,0,5,0]，合计15。
T5依赖T3，当前T5以外有10点，合法。
把T2由1降0后，T5以外只剩9点；即使T2不在T5的前置连线上，T5仍须退回5点。
确认框显示：T2退1、T5退5，总退6；T3保留4。
若另一系仍投15，总投入从30降24，剩余6。不要显示退5，也不要连另一系一起重置。

另一递归案例：T=[5,0,5,0,5,0]。T1由5降4会令T3不可达，再令T5不可达；总退11。
确认展示具体受影响节点与数量；确认前不改变草稿。先应用后破坏前置再“偷偷修复”不可接受。

本系重置仅退该系，序列重置仅退该序列。退款是已得预算中可重新分配的点，不提高已得预算。

## 3. 存档迁移

参考模块的v1只是明确的整数等级测试格式，不是对真实旧存档的假设。
实际客户端需先识别旧版本及字段语义，提供旧ID到新ID映射，并用真实样本验收。
不能猜“true代表1级还是5级”，不能把旧百分比除以某个常数推导等级。

迁移流程：读取并备份原始字节 → 识别版本 → 从可靠任务进度取已得点数 → 映射兼容等级 → 校验全树 → 生成迁移报告和候选存档 → 写临时文件 → 读回校验 → 原子替换。
任何步骤失败保留原存档，不能留下半份新旧混合数据。这里的真实磁盘流程尚未在本包实现。

已知映射且合法：保留等级。
未知旧布局、已删除节点、非法等级、预算超额或不再可达：不猜分配顺序，提出“本序列整页退点”的明确确认，保留原始备份；其它序列、技能、物品和剧情不变。
未知更新版本：禁止降级覆盖，不自动重置。
已得预算不明：停止该页自动迁移，等待可靠进度适配，不能用上限30兜底发点。
迁移应可重复运行而不增点；不得把每次退还额累计到已得预算。

必须用真实样本测试：空存档、部分投入、满30、旧布尔节点、重命名节点、损坏文件、写入中断、云存档冲突、回滚、重复迁移。
本包只测试规范化数据映射及幂等性，未测试上述真实存储和云端行为。

## 4. 手机UI与安全区

信息结构：安全区容器内分为顶部固定区、树独立滚动区、底部固定详情区、底部固定操作区。
顶部：序列切换、三系切换、已用／已得／剩余。
中部：两列三层六个节点，显示0/5至5/5；只有该区域随树内容滚动。
底部详情：当前等级效果、下一级效果、前置不足的具体值。节点满级时显示“已满级”，不错误访问第六级数组。
底部操作：减点、加点、应用、重置；撤销草稿可收在次级菜单，但主要加减点不可被关联弹层遮挡。

状态要区分：剧情未开放、结构条件不足、满足条件但预算不足、可投入、已投入、满级。不要全都用一把锁。
节点的“战斗效果未接入”是开发状态，不是剧情锁。开发入口可预览；正式入口不能谎称效果有效。
配色采用旧铜与暗色星盘，但颜色之外使用锁、加号、等级文字等冗余提示。

建议设计触控框48×48逻辑单位以上；实际单位转换由客户端缩放方案处理。
布局读取当前安全区矩形，顶部和底部锚在同一个安全区容器，避免同时在父子容器重复加下边距。
小屏、横屏、大字号导致高度不足时，关联内容先折叠或改为独立抽屉，关键当前／下级摘要和操作保留。不能缩小按钮到不可点，也不能让整页滚动把应用按钮藏到系统手势区。
关联面板有独立关闭入口，不拦截底部加减点区域。

验收覆盖：窄屏、长屏、顶部缺口、底部手势区、横竖切换、屏幕缩放、大字号、多行前置说明。检查按钮hitbox而不只是截图位置。
本包没有实际UI画面或真机测试，以上是实施规格。

## 5. 战斗接入前的事件契约

把“起手后固定0.2秒伤害”从正式实现需求中删除。现有0.2秒数据只留作旧回归fixture。
需要从实际攻击内容区分：施法被接受、发射或幻影形成、每次命中、动作结束；冷却从现有成功起手规则开始。
近战在权威命中标记结算；弹道在实际抵达或碰撞确认结算，不在发射时扣血；幻影在形成事件可用，在命中事件才扣承接次数。
动作结束可以早于弹道命中，不能把两者强行等同。

统一HitConfirmed身份至少包含battleId、castId、hitIndex、logicalTargetId。动画与碰撞都回调时，必须指向同一次逻辑命中去重。
双目标各有目标身份，但“每施法一次”的天赋另用castId去重；多段各有hitIndex，不能全部折成一次也不能一个碰撞体算一段。
生命、护盾、假面次数、飘字和受击反馈订阅同一结算结果；不要分别用各自延迟计时器。
缺少命中绑定时记录错误并终止该次待命中事件，不偷偷回退到0.2秒扣血。
动画取消、对象池复用、目标死亡、暂停恢复必须使旧castId失效或按既定飞行规则完成，不能把迟到回调应用到新一轮施法。

真实时序验收后，导出同一配置给离线模型，或用实际事件轨迹做回放比对。每个结果携带timingProfileId、combatRulesVersion、talentRulesVersion、遗落物规则版本，版本不同不能混报为同一结论。
30/60/120帧下检查不提前结算、重复回调不双扣、行动顺序一致；显示帧与逻辑时刻的允许误差另行记录。

## 6. 假面变更隔离

现有规则与实验规则分开版本：current_full_two_hit与experimental_partial_endurance。
本轮不把实验版默认写入现有教学prefab、技能说明或旧存档。不引入两个不同的正式假面并让教学不告诉玩家发生了变化。
采用实验版之前，需同时验收：技能说明、耐久和次数双显示、重施刷新、不同破碎原因、角色剩余伤害、400火球教学、纸人差异、战后记录。
P2/P6和R02/R06/R14等依赖耐久的提案机制，在该决策未通过前标为待定接入，不能说已在现有假面下成立。
本包仍保留实验假面仅为复现旧数值；这不构成设计获准。

## 7. 后续分批接入及准入条件

P1：先统一真实命中与去重，再分别接入戏势/接缝、余响/针脚、误认/证据/封卷。
每种资源先测试获得、消费、到期、刷新、容量、同刻事件及不能由派生事件递归触发。
每个节点五级都有正向、负向及边界测试；五级效果是一组绝对配置，不把前四级效果再累计一遍。
没有实现的活跃技能或遗落物要直接拒绝测试，不允许静默失效后得出强弱结论。

P2：十八节点和相应遗落物均接入后，运行九套30点配点与基础／进阶装备，包含教学1/2卡回归、20/60/180秒轨迹、不同敌方起手相位及参数扰动。
记录伤害、生命、资源过期/溢出、真正确认的幻影承接、隔离阻止量、封卷/转移/死亡失效。展示第20秒以后仍在发生的资源循环，不只截开场。
以每套有优势问题、可以最小调整处理劣势为目标，不预设九套输出相等或必须各赢某场。
未达到机制覆盖标准的对照标INVALID，不进入平衡汇总。

P3：上述通过后扩展首领阶段与掉落经济。避免边做核心结算边用首领免疫或数值补丁掩盖错误。

## 8. 双方合理的基础／高价值对照

原来的错配战例只作为“空配套槽位和错误准备有代价”的演示，不再用于证明普通物品长期竞争力。

第一层为单物品替换：同角色属性、同30点天赋、同技能与顺序、两个相同遗落物，只替换最后一件。适用于查清物品效应。
第二层为各自优化：基础可获得物品池与更广物品池分别寻找合理搭配；高价值池允许保留普通物品，不强迫穿满稀有度。
第三层才加入+5%/+10%/+25%属性压力测试，独立列报，不代替同属性比较。

建议成对场景（尚未运行）：

| 单槽比较 | 必须同时有的配套 | 场景对 | 检查的取舍 |
| --- | --- | --- | --- |
| R02补缝针 vs R06无客面具 | 双方都有M | 快速三连击 / 慢速重击 | 3秒刷新频率 vs 5秒CD更高耐久 |
| R05旧邮戳 vs R18禁售校样 | 双方都有稳定取证与封卷 | 短命换目标 / 同一目标长战 | 首份快速入账 vs 第二次合格封卷副本 |
| R04缺角铠钉 vs R10单面镜片 | 双方都有F、R | 护甲覆盖 / 标记断档 | 延长破甲但失去副伤 vs 无条件较弱幻刃 |

第一层不声称两边已经全局最优，第二层必须实际优化并记录搜索范围。
R18在短战没有兑现可以是其真实代价，但不能因此把它硬塞进高价值优化组来证明基础更强。
保命纸人没有触发不自动等于配置无效；必须区分“条件具备但这场没用上”与“缺对应技能永远不可能触发”。
认可的竞争力包括：普通物品在特定机制有更快通关/更少残伤/更低波动，或被高价值优化组主动保留。不要求普通物品全局胜过扩大后的候选池。

## 9. P0完成定义

18节点五级显示一致；0至30已得预算正确；不能第六级、不能超投；前置与故事条件清晰；加减点不吞点；跨支路级联准确；应用/取消/重置正确；过期确认不覆盖新草稿；旧存档有映射报告、备份和回滚；安全区内主要按钮可点。
天赋战斗效力、真实动画同步、假面重设计和稀有度平衡均有独立状态，不用“P0通过”代替它们。
