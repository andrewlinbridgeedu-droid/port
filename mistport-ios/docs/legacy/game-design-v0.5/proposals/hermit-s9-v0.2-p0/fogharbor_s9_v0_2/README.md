# 《秘仪：雾港升序》v0.2 定向修复与P0参考包

## 状态与边界

本包没有修改Unity工程，没有实现手机界面，也没有接入十八天赋的战斗效果。
它包含修补后的Python有限验证器、天赋状态参考模块、测试、原始对照快照和实施说明。
**0.2秒仍只用于保留旧样例的合成时序夹具，不是客户端规则。部分承伤＋耐久假面仍是未确认实验方案。**
真实Unity攻击事件、动画资源、旧存档字段未提供，因此没有宣称完成真实命中同步或生产存档迁移。

## 一键复现

仅用Python标准库。在本目录执行：

```sh
python run_all.py --outdir ./results
```

分别运行新增测试或状态性质检查：

```sh
python -m unittest -v test_regression
python verify_properties.py --outdir ./results
```

## 取证口径

限制的是“误认敌人的原生攻击真实命中后，产生基础证据”的触发家族。
每名玩家、每场战斗只有一个共享门控器；各敌人不能各自获得一份全局额度。
滚动窗口是(t-1秒,t]，不是自然秒；每敌人成功触发间隔至少1秒，全局最多两次。
命中事件按稳定事件顺序处理；被拒绝的第三次不会排队补发。
同一命中的碰撞与动画回调使用同一个命中身份去重。
台账满、派生反照、不满足误认、攻击者已死、记录者已死等拒绝不占成功预算。
成功入账的基础+1与预算消费须同一个结算事务完成。
N/E/I直接给证据不占这个预算；R05的额外份数另记来源，不冒充额外一次基础触发。
因此带R05时，两次合法基础触发可能总计得到四份，这是两个基础触发＋两个遗物奖励，不是全来源每秒最多两份。
这一区别需要保持在文案、日志和后续机制实现中一致。

## 调度口径

允许1至4张不同卡，允许物理槽位中间为None；空槽不占首次轮播动作，不创建CD。
0张卡明确拒绝开始，不崩溃也不进入无限循环。
首次只依装备的有效卡顺序各施放一次；之后按就绪时间、原物理槽位排序。
普攻补空档；已经开始的动作不被新就绪技能抢占。
`schedule`可注入每卡命中延迟和动作占用，用来验证调度逻辑；这种注入能力不代表已经导入Unity真实动画。

## 文件

- `evidence_gate.py`：共享滚动窗口、单敌间隔、重复回调及拒绝原因。
- `validate_s9.py`：修补后的1至4卡调度、原配点检查和实验假面探针。
- `combat_subset.py`：接入全局门控；未实现的活跃遗落物直接报错。历史错配组的R06/R15必须显式允许失效，并写入结果。
- `talent_core.py`：预算、可达性、草稿、级联退点、冲突检测、参考存档迁移提案。**没有实际旧存档解析器。**
- `test_regression.py`、`verify_properties.py`：定向及性质测试。
- `P0_IMPLEMENTATION.md`：客户端分批实施、UI安全区、存档迁移、命中同步、假面决策和合理搭配对照验收。
- `PATCH_FROM_V01.diff`：三份旧脚本的差异；新模块不在此差异内，以本包完整文件为准。
- `COVERAGE_MANIFEST.json`：明确列出未接入能力，防止把子模型当全量战斗。
- `baseline_v01/`：历史只读快照，不能当作新验证结果。

总运行器不再把“基础方必胜”硬编码为新对照的合格条件；保留有明确名称的历史快照回归测试。将来规则变更改变历史胜负，应先审阅差异，再更新快照，而不是调参强行恢复预设赢家。
