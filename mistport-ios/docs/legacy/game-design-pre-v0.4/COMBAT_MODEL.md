# 副本战斗与人物建模

## 首发方向

首版采用固定视角 2.5D，而不是可旋转镜头的完整 3D MMO。它能保留场景氛围、人物移动、技能特效和多人协作，同时把角色与地图制作成本控制在小团队可承受范围。

建议的副本内容比例：70% 战斗、20% 移动与环境机制、10% 极短过场。线索通过怪物行为、场景变化和战利品表现，不用大段文字选择。

一个 6–10 分钟副本由三段组成：清理小怪、处理战场机制、击败精英或 Boss。剧情只在开场、转阶段和结算各出现一句。

## 四层模型

1. **关卡层**：背景、可行走多边形、障碍、出生点、怪物波次、出口。
2. **导航层**：当前使用 A* 网格；以后可由 LDtk/Tiled JSON 生成，画面替换不影响碰撞。
3. **角色层**：位置、朝向、速度、生命、技能冷却、异常状态和当前目标。
4. **表现层**：人物帧动画、怪物帧动画、粒子、伤害数字、音效和镜头震动。

不要把数值或碰撞写进图片。人物换皮、怪物变体、技能平衡都应通过数据完成。

## 人物美术规格

六条路径共用同一套人物骨架尺寸和碰撞盒，只替换服装、武器、颜色与技能特效。每名角色首发只制作四方向：

- 待机：每方向 4–6 帧
- 行走：每方向 8 帧
- 普攻：每方向 6–8 帧
- 路径技能：每方向 8–12 帧
- 受击：每方向 3–4 帧
- 倒地：每方向 6–8 帧

统一导出透明 PNG 图集，单帧建议 256×256，锚点放在双脚中点。SpriteKit 只更换纹理序列；移动、寻路、血量和联机数据不依赖具体角色图片。

### 更符合游戏的 2.5D 建模标准

现有首关角色属于美术验证版，后续不再使用“正面立绘缩小”的做法。正式单位统一采用以下标准：

- 正交相机向下俯视 40°，角色默认朝右上；所有角色与怪物共享同一相机和地平面。
- 先制作低至中面数 3D 基础模型、骨骼与动作，再从四个方向预渲染为 2D 精灵；这样换装、动作和体型比逐帧生成更稳定。
- 单帧 256×256，主体高度占画布 72–78%，脚底锚点固定为 `(0.5, 0.12)`，禁止每个动作重新缩放。
- 角色头身约 1:6.5，武器和外套轮廓适度夸张；减少脸部和皮革微纹理，优先保证 100 像素高度下的职业辨识。
- 主光固定为左上冷月光，技能颜色作为独立附加层；人物图片不烘焙地面阴影、红圈、粒子和文字。
- 四方向先满足首发成本；若后续需要更细腻转向，直接由同一 3D 模型补渲染八方向，不重画全部动作。

角色交付包应包含模型源文件、骨骼、贴图、动作工程文件、透明 PNG 图集和锚点清单。仅有一张 AI 立绘不能视为完成建模。

如果要达到可自由旋转镜头、真实遮挡和 3D 换装，应尽早迁移到 Unity 或 Godot，并制作模型、骨骼、蒙皮、动画状态机、碰撞体和 NavMesh。那会把美术与工程量提高数倍，不适合作为第一版验证。

## 怪物量产

不要为九联邦的每座城市制作全新怪物。首发先做 6 套基础骨架，每套通过材质、部件和精英词缀生成变体：

- 发条兽：冲撞、扑咬
- 盐雾灵：远程弹幕、减速
- 镜潮影：瞬移、分身
- 誓约傀儡：护盾、反击
- 星蚀虫群：包围、持续伤害
- 深潮巨像：重击、地面范围技

每个联邦增加 1 个独立 Boss 和 2 个区域词缀，比堆积大量一次性怪物更经济，也更容易形成辨识度。

## 六路径战斗职责

| 路径 | 主动作 | 组队价值 |
|---|---|---|
| 愚者·假面 | 分身诱敌、错位伤害 | 控场与仇恨转移 |
| 女祭司·潮听 | 灵视标记、治疗波 | 弱点揭示与恢复 |
| 战车·远征 | 冲锋、格挡反击 | 前排与保护 |
| 魔术师·炼成 | 炼成炮台、范围爆破 | 持续输出与机关破解 |
| 正义·誓衡 | 护盾、净化、伤害分摊 | 防护与异常处理 |
| 星星·星渡 | 闪现、穿透射击 | 位移与远程输出 |

序列提升不需要不断增加按钮。每个阶段优先提供一个技能变体、一个被动和一个组队联动，保持手机操作区清晰。

## 多人同步边界

单机原型直接以本机 60 FPS 更新。联机版本由服务器权威计算生命、伤害、掉落和 Boss 阶段；客户端只发送移动方向、目标与技能指令，并对移动做预测。不要逐帧同步人物动画，动画由本地根据角色状态播放。
