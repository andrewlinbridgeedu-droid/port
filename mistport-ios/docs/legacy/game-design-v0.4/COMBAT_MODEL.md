# 固定技能回合制战斗与人物表现模型

版本：0.4  
状态：iOS MVP 实施基线

## 一、首发方向

首版采用固定视角的 2D／预渲染 2.5D 回合制战斗场景。玩家不在战场上自由移动，不需要导航、碰撞、寻路或多人同步。

典型战斗画面：

- 玩家角色位于画面左侧；
- 1–3 名敌人位于右侧；
- 上方显示行动时间轴与敌方意图；
- 下方显示 4 个普通技能、1 个核心技能与状态详情；
- 点击技能后先显示预计结果，再确认结算；
- 单场普通战斗 3–6 分钟，首领战 8–12 分钟。

战斗的主要观赏性来自角色动作、状态变化、结果被延迟或改写的视觉反馈，而不是角色在地图中跑动。

## 二、五层技术模型

1. **战斗模拟层**：回合、行动顺序、生命、意志、资源、冷却和胜负；
2. **事件管线层**：行动宣布、目标选择、效果确定、等待结算、结果施加、后续触发、回合结束；
3. **数据层**：技能、敌人、状态、遗器和首领规则全部数据驱动；
4. **表现层**：角色动画、特效、音效、镜头反馈和战斗日志；
5. **界面层**：技能栏、意图、时间轴、状态详情、预计结果与确认操作。

模拟层不能依赖动画完成。动画中断、跳过或低帧率不能改变战斗结果。

## 三、战斗状态与事件管线

### 标准行动流程

1. 回合开始并刷新持续状态；
2. 敌方公布或更新意图；
3. 玩家选择技能与目标；
4. 系统展示预计伤害、状态和时间轴变化；
5. 玩家确认；
6. 技能进入事件管线；
7. 依优先级结算反应、替代、转移和伤害；
8. 播放动画与日志；
9. 进入下一行动。

### 规则标签

技能和首领效果必须支持以下限制标签：

- 不可复制；
- 不可再次延迟；
- 不可转移；
- 每回合仅触发一次；
- 不能触发自身；
- Boss 核心规则；
- 可部分修改；
- 完全不可修改。

系统禁止无限递归。任一效果链达到安全上限时停止后续触发，并在测试日志中报错。

## 四、输入与可读性

### 玩家输入

- 单击技能：查看说明与预计结果；
- 单击目标：选择或切换目标；
- 再次确认：执行技能；
- 长按状态：查看来源、剩余回合和可修改标签；
- 单击时间轴事件：查看该事件为何在该位置；
- 允许在确认前取消选择，不允许在结算后撤销。

### 必须显示的信息

- 敌方下一行动与目标；
- 行动时间轴；
- 技能冷却和资源消耗；
- 状态剩余回合；
- 意志或稳定值；
- 技能执行后的预计结果；
- 条件规则是否即将触发；
- 某效果为什么不能被延迟、复制或转移。

普通难度不隐藏致命技能的核心图标。困难难度可以加入有限伪装，但必须存在可识破线索。

## 五、角色表现规格

首发不需要四方向行走动画。每个单位只使用固定三分之四侧面战斗朝向。

### 玩家角色基础动画

- 待机：6–10 帧或骨骼循环；
- 普通施法／攻击：8–12 帧；
- 4 类技能动作模板：每类 10–16 帧；
- 受击：4–6 帧；
- 防御／闪避：6–10 帧；
- 状态异常：使用独立覆盖层；
- 倒地或退场：8–12 帧；
- 晋升演出：单独制作，不计入常规战斗动画。

### 敌人基础动画

- 待机；
- 普通攻击；
- 强攻或蓄力；
- 受击；
- 意志击破；
- 倒地；
- 首领阶段转换。

### 资产方案

可采用以下任一方案：

1. 2D 骨骼动画；
2. 低至中面数 3D 模型预渲染成透明序列帧；
3. 少量关键角色使用手绘逐帧，普通敌人使用骨骼或预渲染。

若采用预渲染 2.5D：

- 相机、主光和角色朝向全项目固定；
- 单帧建议 384×384 或 512×512，再按设备缩放；
- 脚底锚点统一；
- 人物图不烘焙地面阴影、状态圈、粒子和文字；
- 同一基础模型可通过服装、部件和材质生成变体。

仅有一张 AI 立绘不能视为可用战斗资产。

## 六、场景与镜头

每个战斗场景由以下元素组成：

- 一张高质量背景；
- 玩家与敌人站位槽；
- 前景遮罩或少量环境动画；
- 独立地面阴影；
- 技能特效层；
- 状态与目标指示层；
- UI 层。

镜头只使用少量可控表现：

- 技能时轻微推近；
- 首领阶段转换时短暂拉远；
- 关键结果被取消或改写时冻结 0.2–0.4 秒；
- 不频繁震屏，不让特效遮挡意图和状态。

## 七、怪物量产

MVP 先制作 6 套战斗原型，而不是六套移动骨架：

1. **发条兽**：蓄力扑击，测试闪避；
2. **空壳钟匠**：普通攻击与防御切换；
3. **记忆蛭**：寄生并转移负面状态；
4. **镜面替身**：显示相似外观但不同意图；
5. **校准傀儡**：护甲与意志双层防线；
6. **吞灯兽幼体**：短暂隐藏非关键信息。

每个原型通过材质、部件、数值和一项精英词缀产生变体。首领必须拥有独立轮廓和阶段动画。

## 八、六条路径的表现边界

六条路径不是队伍职业，不设计坦克、治疗或仇恨职责。每条路径必须能够单独完成主线。

| 路径 | 核心表现 | 战斗辨识 |
|---|---|---|
| 帷幕之径 | 预兆线、假目标、事件被划去或替换 | 改变意图与结算 |
| 潮忆之径 | 记忆残响、梦境波纹、精神修复 | 读取与重写记忆状态 |
| 远征之径 | 蓄势轨迹、格挡冲击、反击窗口 | 承压后爆发 |
| 炼成之径 | 材料符号、元素转换、构装投影 | 组合与转化 |
| 誓衡之径 | 契约线、代价刻度、规则封印 | 条件与公平交换 |
| 星渡之径 | 距离线、路线投影、可能性分支 | 调整目标关系与顺序 |

首发只实现帷幕之径的完整表现。

## 九、联网边界

战斗不需要实时联网同步。

- 战斗模拟在本地运行；
- 关键战斗使用服务器下发的版本号、敌人数据和随机种子；
- 战斗结束后上传摘要，用于奖励验证和异常检测；
- 玩家库存、可交易物品、金币、市场订单和订阅状态由服务器权威保存；
- 断网时可以进行不产生可交易高价值奖励的训练或已下载剧情战；
- 不开发移动预测、重连战斗、队友接管或多人 Boss 同步。

## 十、性能与验收

- 战斗逻辑与动画帧率解耦；
- 中低端目标设备保持稳定 30 FPS，高端设备可选 60 FPS；
- 同屏最多 1 名玩家角色、3 名普通敌人或 1 名首领加 2 个附属单位；
- 关键技能结果在确认前可预览；
- 战斗日志可完整还原每次状态变化；
- 自动测试覆盖事件优先级、延迟、替代、转移和死亡结算；
- MVP 不因美术缺失而阻塞规则测试，可先使用统一占位动画。
